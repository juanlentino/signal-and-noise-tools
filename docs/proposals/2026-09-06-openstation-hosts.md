# The two hosts: S&N Dashboard and S&N Analytics on the App Framework

**Date:** 2026-09-06 · **Owner decision (2026-09-05):** "adapt SN Dashboard and S&N Analytics to the App Framework — PORT = FAITHFUL. ALWAYS. Host first (framework tabs + server views calling the existing leaf renderers; no iframe), rebuild the daily surfaces second." · **Issues:** #1074 (Dashboard), #1075 (Analytics) · **Cuts:** two MINORs, one per host.

## What a host is

A native OpenStation window (`App::define()`, server views) that paints the SAME HTML the classic admin page paints, produced by the SAME render callables, for every leaf, with every form saving through the SAME handler table and every notice saying the same thing. Nothing is redesigned, dropped or "simplified"; the window is the admin page wearing the shell's chrome. The daily-surface rebuilds (client views in the Explorer idiom) come after, and only for surfaces the owner names.

## Measured facts the design rests on (2026-09-06)

1. **The desktop document IS wp-admin.** `/openstation/` resolves to `wp-admin/admin.php?page=openstation`; `body.wp-admin.wp-core-ui`; core's `common`, `forms`, `dashboard`, `list-tables`, `buttons`, `edit`, `media` stylesheets are loaded (measured: a probe `.form-table th` computes 257px/10px/left, `.postbox` has its 1px border, `.button-primary` its background and 2px radius, `.notice` its 4px left border). The leaves' admin HTML styles natively inside a window. **No iframe is needed and none is used.**
2. **The Dashboard's IA is data.** `sn_admin_top_tabs()` (inc/admin-tabs-data.php): 8 top tabs, 34 static leaves plus up to 2 spliced (Machine Readers, Search Console), each leaf `{ label, render: callable, wide | wide_card, sub_sections? }`. The dispatcher `sn_admin_render_active_tab( $tab, $sub )` (inc/admin-render-sections.php) prints the sub-tab strip, the wrapper (capped `.sn-fieldset` card / bare `.sn-section` for `wide` / `.sn-fieldset--wide` for `wide_card`) and the leaf. `sn_admin_canonical_destination()` and `sn_admin_post_redirect_target()` are pure.
3. **Every write is one pipeline.** A leaf's `<form method="post">` carries `sn_action` + `_wpnonce` (`sn_theme_options_nonce`); `sn_handle_admin_post()` (admin_init) checks `manage_options`, the page slug, the nonce, looks the action up in `sn_admin_post_handlers()`, calls `handler( $_POST )`, gets a FLASH CODE back, and redirects to the tab/sub (+ `#sn-sec-*` anchor) with `?sn_flash=`; the page maps the code through `sn_admin_flash_to_notice()` into `<div class="notice notice-{severity}">`. **57 forms across 35 leaves, none uploads a file** (the map: `files=false` everywhere). One form (`audit_prune_now`) is handled inline inside its render function from `$_POST`. One GET door (`admin-post.php?action=sn_force_update_check`) redirects to `update-core.php`. Analytics has a POST CSV/JSON export form that streams a file.
4. **The framework's contract** (desktop-mode 1.1.6, `includes/framework`): `->view( callable( State, Os ) )` captures echoed HTML (`View::capture`: `ob_start`, echo + return); `->action( name, handler( State, Os, $args ) )`; markup dispatches with `os-action="<name>"` and carries args as `os-arg-<key>` attributes; a `<form os-action="x">` submit ships every field as `$args['values']` (FormData; multi-values as arrays; the runtime `preventDefault`s submit); a click on an element with `os-action` is NOT `preventDefault`ed, so a rewritten link must lose its `href`; painted HTML lands by `innerHTML`, so inline `<script>` blocks do not execute; effects: `toast`, `open_url( url, title, icon )` (an admin-URL window), `open( id )`, `badge`, `menu`, `refresh_menu`, `announce`, `title`, `close`; `$os->param()` reads open-time params and the `reopen` lifecycle retargets a live window. `->tab()` bakes framework-level views at definition time and cannot be switched by a server action.
5. **Assets are gated on the classic hook suffixes** (`sn_admin_page_hooks()` in inc/admin-menu.php): `sn-admin` (admin.css + admin.js: sub_sections tabs, dirty-tracking), `snt-analytics-tokens`, `sn-analytics-admin`, `snt-confirm`, `sn-analytics-brush`, `sn-resume-admin`, `sn-freshness-dot`, `snt-health-suggest-actions` (three leaves), uptime-status (webhooks); the analytics page's own chart/brush scripts. All self-gate on DOM markers. They never load on the desktop page unless the host appends them. The S&N app already appends handles through `openstation_app_window_args` (inc/openstation-app.php) when the framework cannot map a symlinked path.
6. **The dock today:** inc/desktop-mode-dock.php registers `sn-dashboard` as a URL dock item (the classic page in the shell's admin window) with an 8-tab submenu and a deploy badge, and `snt_desktop_admin_url()` builds admin URLs that the S&N app's doors and the Attention rows open through `open_url`.

## Decisions

| Question | Decision | Why |
| --- | --- | --- |
| One window or two? | Two apps: `sn-dashboard` (id = today's dock id) and `sn-analytics`. | They are two surfaces today with two menus, two capabilities' worth of intent and two vocabularies of state; one window would invent a merge. |
| Framework `->tab()` or state? | ONE `->view()` per app; `tab` and `sub` (Dashboard) / the URL params (Analytics) live in STATE; the host paints its own tab strip and sub-tab strip, derived from the registry on every paint. | A leaf link (the Dashboard's Health card → monitoring/health) must switch the tab from a server action, which framework tabs cannot do; and the registry is resolved at render time (trap 1 of the port memory). |
| How is a leaf painted? | `ob_start(); sn_admin_render_active_tab( $tab, $sub ); ob_get_clean()` (Dashboard) and `snt_analytics_render_dashboard()` with `$_GET` set from state for the duration of the capture, then restored (Analytics). Byte-for-byte the classic body, wrapper and sub-tab strip included. | Zero leaf rewrites; every future leaf lands in the window for free. |
| What is rewritten? | One pass over the captured HTML with `WP_HTML_Tag_Processor`: (a) `<form method="post">` → `os-action="post"`, `action` dropped, `method` kept; (b) `<form method="get">` (Analytics' custom dates) → `os-action="go"`; (c) `<a href>` into OUR pages (`page=sn-theme-options`, `page=sn-analytics`) → `os-action="go"` with `os-arg-*` from the query (`tab`, `sub`, `anchor` from the fragment; every `sn_*` param), `href` REMOVED; (d) `<a href>` to any other admin URL (`update-core.php`, `admin-post.php?action=…`, `post.php`, …) → `os-action="door"` + `os-arg-url`, `href` removed (opens as a shell admin window through `open_url`); (e) external `http(s)` links keep their href and GAIN `target="_blank" rel="noopener noreferrer"` when they lack a target; (f) `<script>` blocks gain `data-snt-exec`. Nothing else is touched. | Only the seams that would navigate the top document or never run are changed; everything a reader sees is the same. (e) is the one recorded deviation: today a targetless external link replaces the admin tab; in a window it would replace the whole desktop. |
| How does a form save? | Action `post` with `$args['values']`: require `manage_options`; require `wp_verify_nonce( values['_wpnonce'], 'sn_theme_options_nonce' )`; set `$_POST = wp_slash( values )` and `$_REQUEST['page']` = the tab's slug (handlers `wp_unslash()` and some read `$_REQUEST`); look `values['sn_action']` up in `sn_admin_post_handlers()` — unknown → nothing runs, one toast "Nothing was saved."; call the handler; take the flash code; apply `sn_admin_post_redirect_target()` to state (tab, sub, anchor); map the code through `sn_admin_flash_to_notice()` into state `notice` = `[ severity, html ]`, painted in the window as the same `<div class="notice notice-{severity} is-dismissible">` above the tab strip, and ALSO `$os->toast( wp_strip_all_tags( html ) )`; restore `$_POST`/`$_REQUEST`. The inline-handled form (`audit_prune_now`) works because the leaf re-renders with `$_POST` populated. | The classic pipeline minus the two things a window cannot do (`header()` + `exit`), reproduced exactly: capability, nonce, page, handler table, flash table, redirect target, anchor. |
| Things a window cannot replay | The `sn_force_update_check` door → `open_url` to its own URL (the destination `update-core.php` opens as an admin window — the same screen the classic link lands on). Analytics' export form → stays a real `<form method="post" target="_blank">` to the classic page URL (a download must be a navigation; a new tab is the least a window can do). Both recorded as deviations; both pinned. | Faithful means the destination still happens, not that the mechanism is identical. |
| Scripts | The window-args seam appends, for `sn-dashboard`: `sn-admin`, `snt-analytics-tokens`, `sn-analytics-admin`, `snt-confirm`, `sn-analytics-brush`, `sn-resume-admin`, `sn-freshness-dot`, `snt-health-suggest-actions`, the uptime-status handles — registered (with their localized data, taken from the same functions inc/admin-menu.php uses) when absent; plus ONE host script `assets/os-host.js` that, on every paint of the window root (MutationObserver, debounced to the paint), (1) re-creates `script[data-snt-exec]` nodes once each so inline scripts run, (2) calls `window.snAdmin.init( root )` — an idempotent seam added to assets/admin.js (its sub_sections tabs and dirty-tracking currently bind on DOMContentLoaded, which fires once). For `sn-analytics`: the analytics page's own handles the same way. | Every leaf behaviour is a script that self-gates on a DOM marker; the host's job is only to make sure each script is present and re-armed after a paint. |
| Dock | The manual `sn-dashboard` dock item in inc/desktop-mode-dock.php is REMOVED (the app registers its own dock entry under the same id, same icon, same title); its 8-tab submenu becomes the window's `menu` (`$os->menu()` at mount and `refresh_menu`), each entry a `go`; its badge (`snt_desktop_dock_badge()`) becomes `$os->badge()` at mount and after every action, from the SAME function. `snt_desktop_admin_url()` is unchanged: the classic page stays reachable, and every door that exists today still opens what it opened. Deep links into the host: `params { tab, sub }` on open and on `reopen`. | One surface per id; the doors keep their contract; the classic page is not removed (a removal is not a port). |
| Sub-sections and anchors | `#sn-sec-*` anchors stay real anchors: the composite Identity & SEO leaf's in-page tabs are admin.js's, re-armed by the host script. A post-save anchor from `sn_admin_post_redirect_target()` becomes state `anchor`, painted as `data-snt-anchor` on the root; the host script scrolls to it once after the paint. | The classic page scrolls by fragment; a window scrolls by script. Same landing. |
| Capability | `->capabilities( 'manage_options' )` on both apps AND the `post`/`go`/`door` handlers re-check `current_user_can( 'manage_options' )`. | The classic pipeline re-checks on every POST; the window does too. |
| Analytics state | State = the page's whitelisted params exactly: `view` (default overview), `range`, `from`, `to`, `class`, `compare`, `drill`, `event_prop`, `lg_range`; `go` applies args through the page's OWN resolvers (`snt_analytics_resolve_view/window/class/compare`) and, on a view switch, resets exactly `snt_analytics_view_reset_params()` (never `compare`). | The URL was the state; the window keeps the same state with the same validators, so a bookmarkable classic URL and a window state are the same fact. |
| What is NOT ported | Nothing is removed from the classic pages; nothing is added to the windows beyond the chrome they must have. The daily-surface client rebuilds are a later, named program. The `signal-noise` app (Notes, Pages, …) is untouched. | Port = faithful. |

## Out of scope

Redesign of any leaf; client-view rebuilds; merging the two windows or the S&N app; retiring the classic admin pages; the S&N app's doors switching from admin URLs to window params (a follow-up once both hosts exist); the Station Home widgets.

## Verification (both hosts)

- Suites: registry parity (the host's tabs and sub-tabs are `sn_admin_top_tabs()` — derived, and a mutation that hardcodes one goes red); the rewrite pass over a fixture holding every case (post form, get form, our-page link with tab/sub/fragment, other-admin link, external link with and without target, inline script, a link that must NOT change); the `post` replay (capability, nonce, unknown action, slashing, handler called, flash → notice + toast, redirect target and anchor applied, `$_POST` restored); `go` validation against the registry and the canonical-destination map; the window-args filter appending every handle once; `$_GET` set-and-restored around the analytics capture; the analytics `go` resolvers and reset list (source-parity with `snt_analytics_view_reset_params()`); the dock item gone and the badge from the same function.
- Sandbox: open the window; visit every tab and every sub-tab (35) and every analytics view (13) — each paints without a PHP notice and with the classic wrapper classes present; save the Now page and read the notice; Full Reset's `data-snt-confirm` still confirms; a Dashboard card link switches the tab; the Links tab's external links open a new tab; the `sn_force_update_check` door opens an admin window; the Identity & SEO section tabs switch; a `#sn-sec-*` landing after a save scrolls; the dock shows one S&N Dashboard with the badge and the 8-entry menu; the phone band paints (stacked chrome is the shell's).
