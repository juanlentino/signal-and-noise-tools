# v4.0.2 Design — Inline-`<img>` alt Suggest + Copy

**Status:** Approved 2026-05-25 (brainstorm session, continuing from v4.0.x roadmap)
**Target ship:** plugin v4.0.2 (patch 2/7 in v4.0.x)
**Estimated:** ~150 LOC + 6 file edits, 1-2 hours of execution time
**Predecessor decisions:** Option B (sibling ability) confirmed; context extraction = Suggest-time, ~500 chars stripped (per brainstorm).

---

## 1. Why this ships

v4.0.0 scoped out inline-`<img>` missing-alt Suggest because the existing `snt_ai_alt_suggest_impl()` rejects non-attachment input. The CHANGELOG entry explicitly deferred this to v4.0.x. v4.0.2 discharges that scope debt with a sibling ability that handles inline-img findings via a separate, narrowly-scoped impl.

Apply itself remains deferred — editing `post_content` to mutate inline `<img alt="…">` is a block-serialization-roundtrip problem (WORDPRESS-REFERENCE.md gotcha #4). v4.0.2 ships **Suggest + Copy only**. User copies the AI suggestion to clipboard, opens the editor, pastes manually into the alt field.

This is an explicit application of the canonical pattern captured in `feedback_health_suggest_apply_pattern.md` memory.

- **Before/After modal UI** — that's v4.0.3.

- The drift detection's `phrase`/`position`/`context_snippet` extension from v4.0.0 Task 5 stays intact. No changes to drift code.

## 3. Architecture

### Surface convention

Mirrors `inc/ai-alt-text-suggest.php` (v4.0.0) byte-for-byte where applicable:
- Pure `snt_ai_alt_inline_suggest_impl()` impl function is single source of truth
- REST endpoint wraps the impl for non-JS callers
- Ability `signal-noise/ai-alt-inline-suggest` wraps the impl for the canonical AI-discoverable surface
- JS calls the Abilities REST surface via `wp.apiFetch`

The only structural difference from the attachment-alt impl: **no `snt_ai_alt_inline_apply_impl()` companion**. Apply is deferred indefinitely; the impl-pair convention from the v4.0.0 pattern is bent (suggest exists without paired apply). The pattern memory should be updated to acknowledge this is allowed for Suggest-only check variants.

## 4. Backend contract

### `snt_ai_alt_inline_suggest_impl( $post_id, $image_src )`

```php
/**
 * Pure impl: generate alt text suggestion for an inline <img> found in a post body.
 *
 * Unlike snt_ai_alt_suggest_impl() which keys off an attachment_id, this impl
 * keys off (post_id, image_src) because inline-img findings have no attachment
 * — they're <img src="..."> tags in post_content where the src may or may not
 * point at an attachment in the media library.
 *
 * Context gathering: ~500 chars centered on the image src position in
 * post_content, with HTML and shortcodes stripped. Plus post title + filename
 * from the URL.
 *
 * @param int    $post_id   The post containing the inline img.
 * @param string $image_src The img src URL (as it appears in post_content).
 * @return array{ok:true,suggestion:string,post_id:int,image_src:string}|WP_Error
 *
 * WP_Error codes:
 *   snt_ai_unavailable          (503) — AI client / provider not configured
 *   snt_ai_post_not_found       (404) — post_id doesn't resolve
 *   snt_ai_img_not_found        (422) — image_src doesn't appear in post_content
 *                                       (post may have been edited since scan)
 *   snt_ai_empty_post           (422) — context after strip is empty (very short post)
 *   snt_ai_insufficient_context (422) — AI returned ALT_INSUFFICIENT_CONTEXT marker
 *   snt_ai_runtime_error        (500)
 *   snt_ai_empty_response       (502)
 *
 * @since 4.0.2
 */
```

### Context extraction (the new mechanism)

```php
function snt_ai_extract_inline_img_context( $post_content, $image_src, $window = 500 ) {
    // Find first occurrence of the img src in post_content (we don't need
    // a specific occurrence since alt text is per-image-src not per-position).
    $haystack = (string) $post_content;
    $needle   = (string) $image_src;
    if ( '' === $needle ) { return ''; }

    $pos = strpos( $haystack, $needle );
    if ( false === $pos ) { return ''; }  // src not in post — caller returns snt_ai_img_not_found

    // Strip HTML/shortcodes from a wider window first, then trim to ~$window chars.
    // We strip a wider region because HTML strip can compress significantly.
    $wide_start = max( 0, $pos - ( $window * 2 ) );
    $wide_end   = min( strlen( $haystack ), $pos + $window * 2 );
    $wide       = substr( $haystack, $wide_start, $wide_end - $wide_start );

    $stripped = function_exists( 'strip_shortcodes' )
        ? strip_shortcodes( $wide )
        : $wide;
    $stripped = wp_strip_all_tags( $stripped );
    $stripped = trim( preg_replace( '/\s+/', ' ', $stripped ) );

    // Truncate to ~$window chars; prefer cutting at word boundaries.
    if ( strlen( $stripped ) > $window ) {
        $stripped = substr( $stripped, 0, $window );
        $last_space = strrpos( $stripped, ' ' );
        if ( false !== $last_space && $last_space > $window - 50 ) {
            $stripped = substr( $stripped, 0, $last_space );
        }
    }

    return $stripped;
}
```

## 6. Cost model

- **Per Suggest click**: ~$0.001 (Sonnet 4.6 pricing). Filename + post title + 500-char context = ~200 input tokens; output ≤ 80 tokens.
- **Suggest all on a mixed section** (attachment + inline-img findings): each finding generates one Suggest call at the 500ms throttle. Cost scales linearly with finding count.
- **No background generation.** No cron-triggered AI calls. Bounded by user clicks.

Production impact estimate: most sites have far fewer inline-img findings than attachment findings (because attachments without alt are common from quick uploads, while inline-img usage is less common in modern Gutenberg posts). Expected: +$0.10-0.50/month at most for typical use.
