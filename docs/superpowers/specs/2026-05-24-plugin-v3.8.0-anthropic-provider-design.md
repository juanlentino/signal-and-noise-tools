## §0 — TL;DR

Register Anthropic (Claude Sonnet 4.6) as a desktop-mode AI provider via [`desktop_mode_register_ai_provider()`](https://github.com/WordPress/desktop-mode/blob/trunk/includes/ai-copilot/providers-registry.php) (since desktop-mode 0.18.0), and register **26 of our 29 ability surfaces** as desktop-mode AI tools via [`desktop_mode_register_ai_tool()`](https://github.com/WordPress/desktop-mode/blob/trunk/includes/ai-copilot/tools-registry.php) (since desktop-mode 0.17.0). The user selects Anthropic in desktop-mode's OS Settings; `wp.desktop.ai.ask()` then routes through our Anthropic-backed agentic loop with structured tool-calling into theme and plugin abilities.

**The 3 destructive abilities omitted** (per safety defense-in-depth): `purge-all-caches`, `clear-template-overrides`, `full-reset`. These remain accessible via `wp ability run`, the SN admin tabs, and manual ⌘K commands — just not via natural-language Copilot invocation.

## §1 — Goals & non-goals

### Goals

1. **Anthropic-first Copilot.** A SN user typing into the desktop-mode AI overlay reaches Claude Sonnet 4.6, not OpenAI. Same model the plugin already pins for `snt_ai_generate_with_constraints` (v3.7.2 pin).
2. **Structured tool invocation.** Replace the v3.7.4 plan's clunky `window.prompt()` UX with JSON-Schema-typed tool calls. The model fills in `{content, content_type}` from natural language; our handler dispatches; the model formats the response.
3. **Single credential.** User enters the Anthropic API key once (in wp-ai-client's Connectors UI). Our provider reads from there at runtime.
4. **Full coverage.** 12 theme abilities + 17 plugin abilities → 26 AI tools (3 destructive omitted).
5. **Capability-gated.** Read tools require `read`, generative require `edit_posts`, operations require `manage_options`. No user gets tools they can't already invoke through other means.
6. **No regressions.** All 9 existing test suites continue to pass (550 assertions). `snt_ai_generate_with_constraints` continues to work for the 5 theme + 3 plugin AI features that already depend on it.

### Non-goals

1. **Not replacing OpenAI for users who prefer it.** The OpenAI provider remains the desktop-mode default; our Anthropic provider is additive. Users select via OS Settings.
2. **Not refactoring `snt_ai_generate_with_constraints`.** It stays wp-ai-client-backed; the new desktop-mode provider talks Anthropic Messages API directly. Duplication accepted (the agentic loop is a different primitive than single-shot prompting).
3. **Not building a custom UI.** desktop-mode's existing AI Copilot overlay is the user surface. We contribute provider + tools, not chrome.
4. **Not exposing destructive ops to natural language.** `purge-all-caches`, `clear-template-overrides`, `full-reset` stay manual-only. v3.9.0 may add a `confirm: true` field at the tool level if upstream desktop-mode adds one.
5. **Not backporting to desktop-mode < 0.18.0.** The plugin gracefully skips provider/tool registration when the APIs aren't present.

## §2 — Architecture

### High-level data flow

```
User: "rewrite this content in our brand voice"
  │
  ▼
desktop-mode AI Copilot overlay (JS)
  │  POST /wp-json/desktop-mode/v1/ai/search { query, ... }
  ▼
desktop-mode search.php (PHP)
  │  desktop_mode_ai_get_active_provider($user) → loads our 'anthropic' provider
  │  desktop_mode_get_registered_ai_tools_for_user($user) → 26 tools (filtered by cap)
  ▼
Agentic loop (max 10 iterations):
  ├── make_turn_input('user_message', $query) → Anthropic messages format
  ├── agentic_call($key, $turn_input, $tools, $text_format, $instructions, $state)
  │     POST api.anthropic.com/v1/messages
  │     → returns { text?, function_calls[], next_state, raw }
  │
  ├── If stop_reason='tool_use':
  │     For each function_call:
  │       → desktop_mode_ai_invoke_registered_tool($tool, $args, $user_id)
  │       → handler closure → snt_dispatch_ability_as_tool($ability_slug, $args, $user_id)
  │       → wp_call_ability($ability_slug, $args) [WP 7.0 Abilities API]
  │       → returns array result
  │     make_turn_input('tool_results', $outputs) → Anthropic tool_result blocks
  │     loop back to agentic_call with updated $state
  │
  └── If stop_reason='end_turn': final text → JSON answer → returned to user
```

### Why not single-file?

CLAUDE.md mandates ~150 lines per file. The provider alone is ~200 lines (necessary — Anthropic's wire format complexity); tool tables are ~150 lines each. Splitting along concern boundaries keeps each file focused and within the rule.

### Cross-package surface

**Unchanged.** The 3 existing cross-package filters (`sn_purge_all_caches_result`, `sn_clear_template_overrides_result`, `sn_og_font_paths`) remain the only cross-package contract. v3.8.0 adds no new theme↔plugin coupling — theme abilities are invoked via `wp_call_ability()` which is a WordPress core primitive, not a SN-specific bridge.

## §3 — Anthropic provider implementation

### §3.1 — API key resolution

```php
function snt_anthropic_resolve_api_key(): string|WP_Error {
    // wp-ai-client stores provider keys via its own options mechanism.
    // Read directly from the option (verified shape from wp-ai-client v0.x source).
    if ( ! function_exists( 'wp_ai_client_get_provider_settings' ) ) {
        return new WP_Error( 'wp_ai_client_missing', __( 'WP AI Client plugin is required for Anthropic API key sourcing.', 'signal-noise-tools' ) );
    }
    $settings = wp_ai_client_get_provider_settings( 'anthropic' );
    if ( empty( $settings['api_key'] ) ) {
        return new WP_Error( 'anthropic_no_key', __( 'No Anthropic API key configured. Set one in Settings → AI Connectors.', 'signal-noise-tools' ) );
    }
    return (string) $settings['api_key'];
}
```

**Read-on-call**, not at registration. Means registration never fails on missing credentials (graceful degradation); errors surface at first invocation with a clear remediation message.

If `wp_ai_client_get_provider_settings()` isn't available (different wp-ai-client version), fall back to reading the raw option name directly. Verify the option name via:

```bash
grep -rn "update_option.*anthropic\|get_option.*ai_client" $(wp plugin path wp-ai-client)
```

at implementation time. Document the verified option name in the implementation file.

### §3.2 — `make_turn_input($kind, $payload)`

Two cases, both pure-data transforms (no HTTP, no state):

**`user_message`** (payload = string):
```php
return array(
    array( 'role' => 'user', 'content' => $payload ),
);
```

**`tool_results`** (payload = `array<int, array{call_id: string, output: string}>`):

Anthropic packages tool results as a single user message with multiple `tool_result` content blocks:
```php
$blocks = array();
foreach ( $payload as $tr ) {
    $decoded = json_decode( $tr['output'], true );
    $blocks[] = array(
        'type'        => 'tool_result',
        'tool_use_id' => $tr['call_id'],
        'content'     => is_array( $decoded ) ? wp_json_encode( $decoded ) : (string) $tr['output'],
    );
}
return array(
    array( 'role' => 'user', 'content' => $blocks ),
);
```

Note: Anthropic's `tool_result.content` can be string OR an array of content blocks. We use string (the JSON-encoded result) — simpler, and search.php already gave us JSON-encoded output.

### §3.3 — `agentic_call($key, $turn_input, $tools, $text_format, $instructions, $state)`

The multi-turn core. State carries the full message history (no `previous_response_id` equivalent in Anthropic).

```php
function snt_anthropic_agentic_call(
    string $api_key,
    array $turn_input,
    array $tools,
    ?array $text_format,
    string $instructions,
    mixed $state
): array|WP_Error {
    // 1. Build messages: previous history + this turn's new input
    $messages = is_array( $state['messages'] ?? null ) ? $state['messages'] : array();
    $messages = array_merge( $messages, $turn_input );

    // 2. Translate tools (OpenAI shape → Anthropic shape)
    $anthropic_tools = snt_anthropic_translate_tools( $tools );

    // 3. If text_format is set (final-turn structured output requested):
    //    Add a synthetic tool that has the schema as input_schema
    //    Force tool_choice on it
    $tool_choice = null;
    if ( is_array( $text_format ) && ! empty( $text_format['format']['schema'] ) ) {
        $schema_name = $text_format['format']['name'] ?? 'final_answer';
        $anthropic_tools[] = snt_anthropic_synthetic_structured_tool(
            $schema_name,
            $text_format['format']['schema']
        );
        // Don't force the schema tool yet — let the model use real tools first
        // tool_choice defaults to 'auto'
    }

    // 4. POST to Anthropic
    $body = array(
        'model'      => apply_filters( 'snt_anthropic_provider_model', 'claude-sonnet-4-6' ),
        'max_tokens' => 4096,
        'system'     => $instructions ?: 'You are a helpful assistant in a WordPress admin Copilot.',
        'messages'   => $messages,
        'tools'      => $anthropic_tools,
    );
    if ( $tool_choice ) {
        $body['tool_choice'] = $tool_choice;
    }
    $response = snt_anthropic_messages_call( $api_key, $body );
    if ( is_wp_error( $response ) ) return $response;

    // 5. Parse response by stop_reason
    $stop_reason = $response['stop_reason'] ?? 'unknown';
    $content     = $response['content'] ?? array();

    if ( 'end_turn' === $stop_reason ) {
        // Plain text answer (or model used the synthetic schema tool)
        $text       = snt_anthropic_extract_text_blocks( $content );
        $schema_use = snt_anthropic_extract_schema_tool_use( $content, $schema_name ?? null );
        if ( $schema_use ) {
            // Structured answer via synthetic tool — encode tool input as the text
            $text = wp_json_encode( $schema_use );
        }
        $assistant_msg = array(
            'role'    => 'assistant',
            'content' => $content,
        );
        return array(
            'text'           => $text,
            'function_calls' => array(),
            'next_state'     => array( 'messages' => array_merge( $messages, array( $assistant_msg ) ) ),
            'raw'            => $response,
        );
    }

    if ( 'tool_use' === $stop_reason ) {
        $function_calls = snt_anthropic_extract_tool_uses( $content );
        // Filter out the synthetic schema tool from function_calls — we don't
        // want desktop-mode to try to dispatch it as a regular tool
        if ( ! empty( $schema_name ) ) {
            $function_calls = array_values( array_filter( $function_calls, fn( $fc ) => $fc['name'] !== $schema_name ) );
        }
        $assistant_msg = array(
            'role'    => 'assistant',
            'content' => $content,
        );
        return array(
            'text'           => null,
            'function_calls' => $function_calls,
            'next_state'     => array( 'messages' => array_merge( $messages, array( $assistant_msg ) ) ),
            'raw'            => $response,
        );
    }

    if ( 'max_tokens' === $stop_reason ) {
        return new WP_Error(
            'anthropic_max_tokens',
            __( 'Anthropic response truncated by max_tokens. Increase max_tokens or simplify the query.', 'signal-noise-tools' )
        );
    }

    return new WP_Error(
        'anthropic_unknown_stop_reason',
        sprintf( __( 'Anthropic returned unknown stop_reason: %s', 'signal-noise-tools' ), $stop_reason )
    );
}
```

### §3.4 — `structured_request($key, $messages, $schema, $schema_name, $model)`

Single-shot structured output via forced `tool_choice`:

```php
function snt_anthropic_structured_request(
    string $api_key,
    array $messages,
    array $schema,
    string $schema_name,
    string $model
): array|WP_Error {
    // Split system messages out
    $system = '';
    $msgs   = array();
    foreach ( $messages as $m ) {
        if ( 'system' === ( $m['role'] ?? '' ) ) {
            $system .= ( $system ? "\n\n" : '' ) . (string) $m['content'];
        } else {
            $msgs[] = $m;
        }
    }

    $tool = snt_anthropic_synthetic_structured_tool( $schema_name, $schema );
    $body = array(
        'model'       => $model ?: apply_filters( 'snt_anthropic_provider_model', 'claude-sonnet-4-6' ),
        'max_tokens'  => 4096,
        'system'      => $system ?: 'Return only the requested structured data.',
        'messages'    => $msgs,
        'tools'       => array( $tool ),
        'tool_choice' => array( 'type' => 'tool', 'name' => $schema_name ),
    );

    $response = snt_anthropic_messages_call( $api_key, $body );
    if ( is_wp_error( $response ) ) return $response;

    $tool_uses = snt_anthropic_extract_tool_uses( $response['content'] ?? array() );
    if ( empty( $tool_uses ) ) {
        return new WP_Error(
            'anthropic_no_structured_output',
            __( 'Anthropic did not return a tool_use block for the requested structured output.', 'signal-noise-tools' )
        );
    }
    // Anthropic gives us the args as a DECODED OBJECT, not a string — return as array
    $args = $tool_uses[0]['arguments'] ?? '{}';
    return json_decode( $args, true ) ?? array();
}
```

### §3.5 — Tool format translation

```php
function snt_anthropic_translate_tools( array $openai_tools ): array {
    // OpenAI Responses API tool: {type:'function', name, description, parameters, strict?}
    // Anthropic tool:             {name, description, input_schema}
    return array_map( function( $t ) {
        if ( ( $t['type'] ?? '' ) !== 'function' ) {
            // Not a function tool — pass through (shouldn't happen in practice)
            return $t;
        }
        return array(
            'name'         => (string) ( $t['name'] ?? '' ),
            'description'  => (string) ( $t['description'] ?? '' ),
            'input_schema' => $t['parameters'] ?? array( 'type' => 'object', 'properties' => (object) array() ),
        );
    }, $openai_tools );
}
```

### §3.6 — Tool-use extraction

```php
function snt_anthropic_extract_tool_uses( array $content_blocks ): array {
    $out = array();
    foreach ( $content_blocks as $block ) {
        if ( ( $block['type'] ?? '' ) !== 'tool_use' ) continue;
        $out[] = array(
            // desktop-mode's registry contract: arguments is a JSON-encoded STRING
            // Anthropic gives us a decoded object — encode it back to comply
            'name'      => (string) ( $block['name'] ?? '' ),
            'call_id'   => (string) ( $block['id'] ?? '' ),
            'arguments' => wp_json_encode( $block['input'] ?? (object) array() ),
        );
    }
    return $out;
}
```

### §3.7 — Provider registration

```php
add_action( 'desktop_mode_ai_register_providers', 'snt_anthropic_register_provider' );

function snt_anthropic_register_provider(): void {
    $result = desktop_mode_register_ai_provider( 'anthropic', array(
        'label'              => __( 'Anthropic (Claude)', 'signal-noise-tools' ),
        'description'        => __( 'Anthropic Messages API. Defaults to Sonnet 4.6.', 'signal-noise-tools' ),
        'api_key_label'      => __( 'Anthropic API key', 'signal-noise-tools' ),
        'api_key_link'       => 'https://console.anthropic.com/account/keys',
        'default_model'      => 'claude-sonnet-4-6',
        'capabilities'       => array( 'tools', 'structured_output' ),
        'make_turn_input'    => 'snt_anthropic_make_turn_input',
        'agentic_call'       => 'snt_anthropic_agentic_call',
        'structured_request' => 'snt_anthropic_structured_request',
    ) );
    if ( is_wp_error( $result ) ) {
        // v3.7.1 lesson: every error path is logged
        error_log( '[SN] Anthropic provider registration failed: ' . $result->get_error_message() );
    }
}
```

The provider's 3 callbacks each call `snt_anthropic_resolve_api_key()` internally — desktop-mode's registry doesn't pass the key from settings to the callback; the provider must source it itself. (See providers-registry.php contract: `agentic_call($api_key, ...)` — the `$api_key` is from desktop-mode's per-provider OS Settings, NOT from us. We ignore that and source from wp-ai-client instead, OR fall back to using the desktop-mode-stored key if wp-ai-client is unavailable.)

**Decision: the provider uses whichever key is available**, preferring wp-ai-client first (per user choice). If wp-ai-client is uninstalled, desktop-mode's per-provider key works. This keeps both surfaces functional.

## §4 — AI tool wrappers (26 tools)

### §4.1 — Shared dispatch helper

```php
function snt_dispatch_ability_as_tool( string $ability_slug, array $args, int $user_id ): array|WP_Error {
    if ( ! function_exists( 'wp_call_ability' ) ) {
        return new WP_Error(
            'abilities_api_unavailable',
            __( 'WordPress 7.0 Abilities API not available. SN AI tools require WP 7.0+.', 'signal-noise-tools' )
        );
    }
    // wp_call_ability handles the registered ability's input_schema validation,
    // capability checks at the ability layer (separate from the tool's own cap),
    // and execute_callback dispatch. Returns array, string, or WP_Error.
    $result = wp_call_ability( $ability_slug, $args, $user_id );
    if ( is_wp_error( $result ) ) {
        // Surface as structured tool error — don't crash the agentic loop
        return $result;
    }
    return is_array( $result ) ? $result : array( 'result' => $result );
}
```

|---|---|

### §4.5 — Registration pattern

Each tool registers via a uniform closure (one closure per tool, not one shared closure — keeps the `$ability` lexically bound):

```php
function snt_register_theme_ai_tools(): void {
    $tools = snt_ai_tool_definitions_theme();  // array from §4.2
    foreach ( $tools as $name => $def ) {
        $ability_slug = $def['ability'];
        $result = desktop_mode_register_ai_tool( array(
            'name'             => $name,
            'description'      => $def['description'],
            'parameters'       => $def['parameters'],
            'capability'       => $def['capability'],
            'progress_message' => $def['progress_message'] ?? '',
            'handler'          => function( array $args, int $user_id ) use ( $ability_slug ): array|WP_Error {
                return snt_dispatch_ability_as_tool( $ability_slug, $args, $user_id );
            },
        ) );
        if ( is_wp_error( $result ) ) {
            error_log( '[SN] AI tool registration failed for ' . $name . ': ' . $result->get_error_message() );
        }
    }
}
add_action( 'desktop_mode_ai_register_providers', 'snt_register_theme_ai_tools' );
```

Same pattern for `ai-tools-plugin.php`.

## §7 — Risks & open questions

### §7.1 — Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Anthropic Messages API changes wire format | Provider stops working | Pin `anthropic-version: 2023-06-01` header; integration test against real API in a manual smoke step (NOT automated CI, to avoid API spend) |
| wp-ai-client option name changes | API key resolution fails | Read source at impl time; document; add fallback to desktop-mode's own apiKeys storage |
| Desktop-mode 0.18.0 not installed | Provider/tools never register | `function_exists` guard skips all registration cleanly; no fatals |
| Hallucinated tool name | Model invokes nonexistent tool | desktop-mode search.php:1177-1182 handles this — returns "Unknown tool" error to the model |
| Capability race: user demoted mid-request | Demoted user gets tool result anyway | Pre-existing desktop-mode behavior; out of v3.8.0 scope. Note in CHANGELOG. |
| Token cost from full-history replay | High cost per multi-turn query | Cap at 10 iterations (desktop-mode's existing limit). Document expected cost: ~$0.01-0.10 per tool-using query depending on conversation depth |
| Model picks wrong tool | User confusion | Tool descriptions must be specific. "Use for X scenario, NOT for Y" pattern. Iterate descriptions in v3.8.1+ based on production observations |

### §7.2 — Open questions for plan-phase

None at design-time. The destructive-ops question was the last one; resolved as "omit 3" per the table in §4.4.

### §7.3 — Deferred to v3.9.0+

1. **Confirm-required tools.** If desktop-mode adds a `confirm: true` field at the tool level, we can expose the 3 destructive ops with explicit user confirmation gating.
2. **Per-feature model override.** Currently the `snt_anthropic_provider_model` filter affects ALL Copilot calls. A per-tool override could route long-context queries to Opus 4.7 and quick lookups to Haiku 4.5.
3. **Token cost telemetry.** Hook `desktop_mode_ai_search_completed` and record per-query token spend. Surface in the Insights tab.
4. **Extended thinking.** Anthropic supports `thinking: { type: 'enabled', budget_tokens: N }` since 4.5. If desktop-mode's `capabilities` field gets a `'extended_thinking'` value, we expose it.
5. **Streaming responses.** Desktop-mode's loop is non-streaming today. If they add streaming, we'd need to mirror.
