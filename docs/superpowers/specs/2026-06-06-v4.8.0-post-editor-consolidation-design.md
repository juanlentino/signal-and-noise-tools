# v4.8.0 — Post-editor sidebar cleanup + AI prepopulation (DESIGN)

**Status:** APPROVED 2026-06-06. Promotes the [2026-05-27 stub](2026-05-27-v4.8.0-post-editor-consolidation-stub.md) to a full design after the grounding audit of the upstream `ai/ai` plugin + SN's own AI surfaces. Supersedes the stub's mechanism assumptions where they conflict (noted inline).

**One-line:** In one minor, (A) disable `ai/ai`'s two **duplicate** editor features (meta-description + excerpt-generation) so SN owns those surfaces alone, and (B) auto-prepopulate `_sn_meta_description` + `post_excerpt` + `_sn_og_card_title` at the draft→publish/scheduled transition — **deferred, empty-field-only, per-field-tuned concise output** — with a single consolidated "auto-generated" notice in the SN meta box.

---

## §0. Audit corrections that shaped this design (READ FIRST)

The 2026-05-27 stub was written before the source audit. The audit (3 agents, 2026-06-06) overturned several of its assumptions. Build to **this** section, not the stub:

| Stub assumed | Reality (audit-verified) | Consequence |
|---|---|---|
| Hide `ai/ai` meta-desc panel via `remove_meta_box` | It's a **JS editor plugin** (`registerPlugin('ai-meta-description')`), no PHP meta box exists — `remove_meta_box` is a no-op | Use the PHP feature filter instead (§A) |
| Only meta-description is duplicated | `ai/ai` **also** ships Excerpt Generation (`registerPlugin('excerpt-generation')`) — a second real duplicate | Hide **both** features (§A) |
| Ability `execute()` returns `array['text']` | Returns **feature-specific keys**: meta-desc → `['ok','description','length']`; excerpt → `['ok','excerpt','length','words']`; og-title → `['ok','title','length','card_regenerated','card_url']` | Prepop reads `description`/`excerpt`/`title`, never `text` (§B) |
| Excerpt is a post-meta key | Excerpt is the **core `post_excerpt` field** (the SN excerpt ability only *returns* text; the editor JS writes it via `editPost`) | Prepop writes excerpt with `wp_update_post`, not `update_post_meta` (§B) |
| OG-title prepop must persist the result | The OG-title **ability already** `update_post_meta(_sn_og_card_title)` **and rebuilds the PNG** + returns `card_url` | Prepop just calls it; persistence is a side effect (§B) |
| `update_post_meta` runs the field's sanitizer | A raw `update_post_meta()` in PHP does **not** invoke `register_post_meta`'s `sanitize_callback` | Prepop must call `sanitize_textarea_field()` itself (§B) |

**Latent bug this design fixes:** with no third-party SEO plugin active (SN replaced TSF), `ai/ai`'s meta-description feature falls back to its own key `wpai_meta_description` **and emits its own `<meta name="description">` on `wp_head` priority 1** — competing with SN's SEO module. If both fields ever carry content, the page renders **two** meta-description tags. Disabling the `ai/ai` feature (§A) stops that emit at the source.

**Coupling note:** `ai/ai` is an explicitly *experimental* plugin (readme: "functionality may change"). The feature-id slugs we filter on (`meta-description`, `excerpt-generation`) and their filter names (`wpai_feature_{id}_enabled`, stable since `ai/ai` 0.7.0) are version surface. The dedupe module documents this and the build verifies the slugs against the installed `ai/ai` version.

## §A. Workstream A — Sidebar cleanup (dedupe `ai/ai`)

**New file:** `inc/ai-ai-dedupe.php` (~25 LOC incl. docblock).

Two unconditional filters that disable `ai/ai`'s two duplicate features. Disabling a feature stops `Loader::register()` for it, so its asset enqueues never run, its JS bundle never loads, its `registerPlugin` never fires, **and** its WordPress Ability never registers (no orphaned generator):

```php
add_filter( 'wpai_feature_meta-description_enabled', '__return_false' );
add_filter( 'wpai_feature_excerpt-generation_enabled', '__return_false' );
```

**Design choices:**
- **Unconditional, no setting/toggle** (YAGNI). If `ai/ai` is absent the filters never fire — harmless. The decision (SN owns meta-desc + excerpt) is fixed, not user-configurable.
- **Kept untouched:** `ai/ai`'s 4 non-duplicated features — Editorial Notes, Summary, Suggest Categories/Tags, Title Generation — and SN's own generators (`assets/ai-meta-description.js`, `assets/ai-excerpt.js`) which prepop also builds on.
- **Bootstrap:** `require` from the main plugin loader alongside the other `inc/` modules.
- **Docblock** states the experimental-coupling caveat: the filter ids are **verified against `ai/ai` 1.0.x** (audit HEAD `c71c9c9`, 2026-06-05). If a future `ai/ai` renames a feature id the filter silently no-ops and the duplicate re-surfaces — an **accepted, documented fragility** (no runtime guard; re-verify on `ai/ai` updates, and the §E.6 test asserts our filters are wired). The slug confirmation is a plan-time source check (§H.2), not a CI artifact.

## §B. Workstream B — AI prepopulation at publish (deferred)

**New file:** `inc/ai-prepopulate.php` (~130 LOC) — trigger + scheduling + engine + sentinels + dismiss REST route. Notice **render** lives in `inc/post-settings.php` (it owns the SN meta box markup); sentinel **clear-on-save** also lives there (it owns `save_post`).

### B.1 Trigger — `transition_post_status`, priority 10

Mirrors the canonical guard already used by `sn_webhook_on_transition()` (`inc/webhooks.php:340`):

```php
add_action( 'transition_post_status', 'snt_prepop_on_transition', 10, 3 );

function snt_prepop_on_transition( $new_status, $old_status, $post ) {
    $public_now    = in_array( $new_status, array( 'publish', 'future' ), true );
    $public_before = in_array( $old_status, array( 'publish', 'future' ), true );
    if ( ! $public_now || $public_before ) {
        return; // fire only on FIRST entry into published/scheduled, never on re-saves
    }
    if ( ! in_array( $post->post_type, array( 'post', 'page' ), true ) ) {
        return;
    }
    wp_schedule_single_event( time(), 'snt_prepop_event', array( (int) $post->ID ) );
    // Optional nudge if loopback cron feels slow on this site:
    // if ( function_exists( 'spawn_cron' ) ) { spawn_cron(); }
}
```

- Fires on `draft/pending/auto-draft/new → publish` **and** `→ future` (scheduled posts get fields at schedule-time).
- Skips `publish→publish` re-saves and `future→publish` auto-publish (already handled at schedule-time; the empty-only guard is the safety net regardless).
- Post types: `post` + `page` (matches `SN_POST_SETTINGS_POST_TYPES` / `sn_webhook_post_types`).

### B.2 Deferred mechanism — `wp_schedule_single_event`

Chosen over `fastcgi_finish_request` because it fully decouples from the publish request (holds no FPM worker), works identically from the editor / scheduled-publish cron / WP-CLI, and the user won't see results until they reopen the post (the notice's job). The few-seconds delay is acceptable.

```php
add_action( 'snt_prepop_event', 'snt_run_prepop', 10, 1 );
```

### B.3 Engine — `snt_run_prepop( int $post_id )`

Re-checks everything (the user may have edited between publish and cron firing):

1. Bail silently if `! snt_ai_is_available()` (deterministic, no API call — `inc/ai-bootstrap.php:111`), post missing, or no longer public.
2. Bail if `str_word_count( wp_strip_all_tags( $post->post_content ) ) < SNT_PREPOP_MIN_WORDS`.
   **`SNT_PREPOP_MIN_WORDS` default `50`, filterable** via `snt_prepop_min_words` — don't burn AI calls on stubs; 50 is low enough to cover short notes.
3. Per field, **empty-only**, using real ability contracts:

| Field | Empty check | Ability (slug) | Returns | Persist |
|---|---|---|---|---|
| Meta description | `'' === get_post_meta($id,'_sn_meta_description',true)` | `signal-noise/ai-generate-meta-description` | `['description']` | `update_post_meta($id,'_sn_meta_description', sanitize_textarea_field($desc))` |
| Excerpt | `'' === $post->post_excerpt` | `signal-noise/ai-generate-excerpt` | `['excerpt']` | `wp_update_post(['ID'=>$id,'post_excerpt'=>sanitize_textarea_field($exc)])` |
| OG card title | `'' === get_post_meta($id,'_sn_og_card_title',true)` | `signal-noise/ai-generate-og-card-title` | `['title']` (+ self-persists meta + rebuilds PNG) | none (side effect of `execute()`) |

   - All three calls pass `array( 'post_id' => $id, 'concise' => true )`.
   - Each call wrapped in an `is_array($res) && empty($res['error'])` / `! is_wp_error($res)` guard; a failed field is simply skipped (no sentinel).
   - Each **successfully filled** field sets a sentinel `update_post_meta($id, '_sn_autogen_<field>', '1')` where `<field>` ∈ `meta_description` / `excerpt` / `og_card_title`.

### B.4 Re-entrancy + data-loss hazards (VERIFY AT PLAN TIME)

- **Excerpt write re-fires `save_post` + `transition_post_status`.** The trigger guard (§B.1) skips `publish→publish`, so **no loop**. **But** `sn_post_settings_save` (`inc/post-settings.php:256`, on `save_post`) **deletes** SN meta when its fields are absent from `$_POST` (empty canonically = no row). In a cron context `$_POST` is empty.
  - **REQUIRED plan-time verification:** read `sn_post_settings_save` and confirm it early-returns when its nonce/`DOING_AUTOSAVE`/capability guard is unmet (the standard WP pattern). If it does (expected), the cron `wp_update_post` is harmless. **If it does not, the design must add a guard flag** (e.g., a static re-entrancy bool set around the `wp_update_post` call) so the save handler does not wipe `_sn_meta_description`/`_sn_og_card_title` we just wrote. Do **not** assume — this is the verify-the-real-contract rule (memory `feedback_verify_impl_contracts_behavioral_tests`).
- **Manual sanitization:** `update_post_meta()` in PHP does not invoke `register_post_meta`'s `sanitize_callback`; prepop calls `sanitize_textarea_field()` itself to match the `_sn_meta_description` / `_sn_og_card_title` contract (`inc/post-settings.php:49-74`). (The AI text is additionally trimmed + quote-stripped inside each impl.)
- **Order of writes:** do the two `update_post_meta` fields (meta-desc, og-title — which the og ability handles) and the OG ability call first; do the `wp_update_post` excerpt write last, so the single re-entrancy point happens after the other fields are settled.

## §C. The `concise` parameter (edits to 3 ability files + their schemas)

**Files:** `inc/abilities-ai-post-editor.php` (schemas), `inc/ai-meta-description.php`, `inc/ai-excerpt.php`, `inc/ai-og-card-title.php` (impls).

- Add `concise` to the `input_schema.properties` of **all three** abilities:
  ```php
  'concise' => array(
      'type'        => 'boolean',
      'default'     => false,
      'description' => 'Tighten output to the shortest on-brand form for auto-prepopulation.',
  ),
  ```
  Kept **out of `required`**; existing `additionalProperties => false` already permits an optional-with-default prop. Added to all three so prepop's uniform call doesn't get rejected by OG-title's strict schema (precedent: boolean params `sn_only`, `force` in `inc/abilities-cron.php` / `inc/abilities-insights.php`).
- **Backward compatible:** manual editor JS (`ai-meta-description.js` etc.) never sends `concise` → default `false` → **current manual behavior unchanged**.
- Thread `concise` into each `*_impl( int $post_id, bool $concise = false )`; when true, swap to a tighter system instruction + lower `max_tokens`:

| Field | `concise=true` |
|---|---|
| **Meta description** | System instruction: "Output a single meta description of **at most 155 characters** (hard limit — count carefully). One or two short, declarative sentences." **+ PHP-side truncation guard** (§C.1). |
| **Excerpt** | Tightened from "2–3 sentences, 50–75 words" to "**Up to 3 short sentences, 40–60 words. Punchy, not comprehensive.**" `max_tokens` ~120. |
| **OG card title** | **No behavioral change** (already 60–90 chars / `max_tokens` 60); accepts the flag as a no-op. |

### C.1 Char-truncation guard (meta-description, concise only)

Models are unreliable at counting characters. After generation, if the concise meta description exceeds 160 chars, trim to the last whole word ≤155 (no mid-word cut, no trailing punctuation orphan). Belt-and-suspenders so the SERP never truncates mid-sentence. Implemented in `snt_ai_meta_desc_impl` after the existing trim/quote-strip, gated on `$concise`.

## §D. The notice (consolidated, informational)

- **Sentinels:** per-field `_sn_autogen_meta_description` / `_sn_autogen_excerpt` / `_sn_autogen_og_card_title` = `'1'`, set by the engine (§B.3). Net-new per-post pattern (no existing per-field notice precedent; structural model = the per-post pattern-adoption dismiss array, `inc/pattern-adoption-*`).
- **Render** (in `sn_post_settings_render`, `inc/post-settings.php`): read the sentinels; if any set, render one line at the top of the SN meta box:
  > *Auto-generated when you published: meta description, excerpt. **[Dismiss]***
  (lists only the fields whose sentinel is set; human-readable labels). No Edit/Regenerate — the fields + their existing "Generate with AI" buttons are inches away. Uses the project's inline-notice styling (native WP, no brutalist treatment per memory `feedback_no_brutalist_in_admin_ui`).
- **Dismiss:** `assets/prepop-notice.js` (~40 LOC, enqueued on `post.php`/`post-new.php`, gated on `snt_ai_is_available()` + `current_user_can('edit_posts')`, dep `wp-api-fetch`) → `POST signal-noise/v1/prepop/dismiss { post_id }` (permission `edit_post`) deletes the three `_sn_autogen_*` keys, then hides the DOM node.
- **Auto-clear on edit:** `sn_post_settings_save` deletes all three `_sn_autogen_*` sentinels on any editor save (nonce present). The notice therefore shows **exactly once** — the first editor open after publish — then clears on the next manual save or explicit dismiss. **No race:** the cron sets the sentinels *after* the publish-time save.

Per memory `feedback_verify_impl_contracts_behavioral_tests`. Pure-PHP CLI harness (no WP load), modelled on existing suites. New/extended:

1. **`concise` changes generation** (extend `tests/ai-bootstrap.php` or new `tests/ai-concise-param.php`): with `concise=true` vs `false`, assert the system instruction string + `max_tokens` passed into `snt_ai_generate_with_constraints()` differ (stub the generator, capture args). 3. **Trigger guard** (same file): fires `wp_schedule_single_event` on `draft→publish` and `draft→future`; does **not** on `publish→publish`, non-`post`/`page` types.
4. **Notice lifecycle** (same file): sentinel set on generate; render lists exactly the set fields; cleared on save; cleared on dismiss REST.
5. **Char-truncation guard:** a 200-char model output is capped to ≤160 at a word boundary; a 120-char output passes through untouched.
6. **Dedupe presence** (new `tests/ai-ai-dedupe.php`): the two `wpai_feature_*_enabled` filters are registered and return false (effect: `apply_filters('wpai_feature_meta-description_enabled', true)` === false).

Run via the standard `php tests/*.php` sweep (excluding the WP-only `contracts-smoke.php`). Target: all current 34 suites + new suites green, 0 failures. phpcs clean (`composer run lint`), falsification-confirmed.

## §G. Anti-scope (from stub §5, reaffirmed)

- Only **filters into** `ai/ai` — never edits its internals; no coupling to its Ability IDs.
- Prepop fires **only** on the publish/scheduled transition — never on every save/draft.
- **Empty-field-only is absolute** — never overwrites manual content.
- Never generates **post titles** (user-authored) — only the supplementary metadata.
- No new top-level admin notice/dashboard widget; the prepop notice is an inline editor surface tied to a generated field (memory `feedback_no_dashboard_widgets`).
- Cleanup 3.2 (redirect) and 3.3 (consolidate-all) are **rejected** (audit §0): redirect keeps clutter + needs extra emit-suppression; consolidate-all hard-couples to `ai/ai`'s experimental abilities.
