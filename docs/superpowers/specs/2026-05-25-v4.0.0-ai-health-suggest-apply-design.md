# v4.0.0 Design — AI-assisted content-health fix proposals (alt text + drift phrases)

**Status:** Approved 2026-05-25 (brainstorm session, Path A locked from [`signal-and-noise/docs/superpowers/handoffs/2026-05-25-v3.8.6-shipped-v4.0.0-sequencing-pending.md`](../../../../signal-and-noise/docs/superpowers/handoffs/2026-05-25-v3.8.6-shipped-v4.0.0-sequencing-pending.md))
**Target ship:** plugin v4.0.0 (auto-rolled from would-be v3.9.0 per the 5-minors-per-major cap; v3.x had 8 minors)
**Estimated:** ~330 LOC + 4 file edits, 2–3 hours of execution time after the plan is written

---

## 1. Why this ships

`inc/health-checks.php` (v3.5.0+) ships 5 detection-only checks that flag content-health issues but stop at the editor link. The module docblock (line 13) explicitly states: *"AI-assisted fix proposals are a future extension."*

v4.0.0 closes that gap for the 2 highest-leverage checks — **missing alt text** and **drift time-phrases** — by adding a Suggest+Apply UX layer that turns each finding into a one-click fix. The remaining 2 checks (stale posts, orphaned media) are scoped to v4.1.0 once the suggest+apply patterns are battle-tested.

This is the headline v4.0.0 feature. The major version bump is forced by the cap (next minor would be v3.9.0 but v3.x is already 8 minors deep), so the ship is also the natural cap-rollover documentation point.

## 2. Scope

### In v4.0.0

| Check | Suggest semantics | Apply semantics | Concurrency risk |
|---|---|---|---|
| `missing_alt` (attachment case) | AI generates alt text from filename + post context (if attachment is featured-image or referenced inline anywhere) | Write `_wp_attachment_image_alt` for the attachment via `update_post_meta()` | Low — attachment alt is a single meta row; capability is `edit_post` on attachment ID |
| `missing_alt` (inline-img case) | AI generates alt text from filename + nearest paragraph context | **No Apply button rendered** — replaced by helper text "Open the editor to apply" + a Copy button that writes the suggestion to clipboard | N/A (no write path) |
| `drift_time_phrases` | AI generates a replacement phrase given the original phrase + last_modified + now date | String-swap at known byte offset in `post_content`, gated on a fingerprint match | Medium — `post_content` may have been edited since the scan |

### Deferred to v4.1.0

- **Stale posts (>12mo)** — AI-suggested freshness updates as a list (specific outdated statements + suggested rewrites). Apply is read-only / copy-to-editor because whole-post rewrites are too risky for one-click apply.
- **Orphaned media** — AI keep/delete recommendation per attachment based on context analysis + one-click apply (delete or mark-kept).

### Out of scope entirely (not v4.x)

- Broken-links: AI cannot reliably pick the right replacement URL; fix is fundamentally human-judgement.
- Background / cron-driven AI generation: all generation is user-click-initiated. Cost stays bounded to deliberate user actions.
- Bulk apply ("apply all without review"): the closest v4.0.0 gets is "Suggest all" which generates proposals in batch but Apply remains per-row.

### Inline-img write path — why deferred

Editing `post_content` to modify an inline `<img alt="…">` is a `parse → modify → serialize` problem. WordPress block markup is famously fragile under serialization roundtrips — see gotcha #4 in [`signal-and-noise/docs/WORDPRESS-REFERENCE.md`](../../../../signal-and-noise/docs/WORDPRESS-REFERENCE.md) which is exactly why `wp:html` is discouraged. Identifying the right `<img>` tag in a post that may have been edited since the scan compounds the risk. v4.0.0 keeps the suggest layer for inline imgs (users can copy the proposal into the editor) but does not own the write path. v4.x may revisit if a clean primitive emerges.

## 3. Architecture

### Surface convention

Both new features follow the established `snt_*_impl()` pattern from `inc/ai-meta-description.php`:

1. **Pure impl function** is the single source of truth (callable from REST handler, Abilities API, and any future surface).
2. **REST endpoint** (back-compat for JS clients) wraps the impl.
3. **Abilities API registration** (canonical surface as of v2.5.0+) wraps the impl with capability + JSON Schema validation.
4. **JS module** calls the endpoints via `wp.apiFetch` against the Abilities API path: `/wp-abilities/v1/signal-noise/<ability-slug>/run`.

This mirrors `snt_ai_meta_desc_impl()` and its REST + ability surfaces.

## 4. Backend contracts

### `snt_ai_alt_suggest_impl( $attachment_id )`

```php
/**
 * @param int $attachment_id  Attachment post ID (must be image MIME type).
 * @return array{ok:true, suggestion:string, attachment_id:int}|WP_Error
 *
 * WP_Error codes:
 *   snt_ai_unavailable          (503) — AI client / provider not configured
 *   snt_ai_not_attachment       (422) — post is not an image attachment
 *   snt_ai_empty_post           (422) — no context (no title, no caption, no referencing posts)
 *   snt_ai_insufficient_context (422) — model returned ALT_INSUFFICIENT_CONTEXT marker
 *                                       (would have produced low-quality alt; surfaces as a friendly
 *                                       "not enough context for a good suggestion" message in JS)
 *   snt_ai_runtime_error        (500) — generation failed mid-flight
 *   snt_ai_empty_response       (502) — model returned empty string
 */
```

**Prompt construction:**

- Gather: attachment title, filename, caption, parent post title (if any), first post that references the attachment's basename in `post_content`
- System instruction: "Generate descriptive alt text. 80-125 chars. Describe the image factually, not the page it appears on. No 'image of' / 'picture of' preamble. No alt='' (empty) suggestions — if no useful description possible, return ALT_INSUFFICIENT_CONTEXT. Output only the alt text or the marker."
- `max_tokens = 80`

**Output handling:** strip surrounding quotes; check for ALT_INSUFFICIENT_CONTEXT marker → return as WP_Error `snt_ai_insufficient_context` so JS shows a friendly message instead of writing a junk alt.

### `snt_ai_alt_apply_impl( $attachment_id, $alt_text )`

```php
/**
 * @param int    $attachment_id
 * @param string $alt_text       Validated; max 250 chars; must be non-empty.
 * @return array{ok:true, attachment_id:int, written_alt:string}|WP_Error
 *
 * WP_Error codes:
 *   snt_ai_not_attachment      (422)
 *   snt_ai_alt_too_long        (422) — > 250 chars (defensive; model output is capped, but user may edit)
 *   snt_ai_alt_empty           (422) — empty string after trim
 *   snt_ai_capability          (403) — current_user_can('edit_post', $attachment_id) === false
 *   snt_ai_write_failed        (500) — update_post_meta returned false AND $wpdb->last_error not empty
 */
```

**Implementation:**
- Validate inputs (trim, length, capability).
- `update_post_meta( $attachment_id, '_wp_attachment_image_alt', $alt_text )` — note this returns `false` for both "no change" and "real error" (see gotcha #10 in WORDPRESS-REFERENCE.md); check `$wpdb->last_error` to disambiguate.
- Return success payload.

### `snt_ai_drift_suggest_impl( $post_id, $phrase, $position, $context_snippet )`

```php
/**
 * @param int    $post_id          Post that owns the phrase.
 * @param string $phrase           Original phrase (e.g., "recently").
 * @param int    $position         Byte offset in post_content (from scan).
 * @param string $context_snippet  ~200 chars around phrase (from scan).
 * @return array{ok:true, suggestion:string, fingerprint:string, post_id:int, position:int}|WP_Error
 *
 * WP_Error codes:
 *   snt_ai_unavailable
 *   snt_ai_post_not_found  (404)
 *   snt_ai_phrase_drifted  (409) — phrase no longer at position (post changed since scan); JS asks user to re-run scan
 *   snt_ai_runtime_error
 *   snt_ai_empty_response
 */
```

**Prompt construction:**
- System instruction: "Replace a time-relative phrase with a temporally-explicit equivalent. Given: the original phrase, surrounding context, post last_modified date, current date. Output ONLY the replacement phrase (no preamble, no quotes, no markdown). Keep grammatical form. Prefer absolute references (years, dates) over time-relative ones. If no good replacement exists, return PHRASE_NO_REPLACEMENT."
- User content: JSON `{phrase, context, last_modified, now}`
- `max_tokens = 60`

**Pre-flight check:** before calling AI, verify the phrase still exists at `$position` in current `post_content`. If not, short-circuit with `snt_ai_phrase_drifted` (cheaper than calling AI then discovering it).

**Fingerprint generation** (returned to JS so apply call can include it):

```php
function snt_ai_drift_fingerprint( $post_content, $phrase, $position ) {
    $start = max( 0, $position - 40 );
    $window = substr( $post_content, $start, 80 );
    return md5( $phrase . '|' . $window );
}
```

### `snt_ai_drift_apply_impl( $post_id, $phrase, $position, $replacement, $fingerprint )`

```php
/**
 * @param int    $post_id
 * @param string $phrase        Original phrase (must still match at $position).
 * @param int    $position      Byte offset.
 * @param string $replacement   AI suggestion (possibly user-edited; max 200 chars).
 * @param string $fingerprint   md5 from Suggest response.
 * @return array{ok:true, post_id:int, replaced:string, with:string}|WP_Error
 *
 * WP_Error codes:
 *   snt_ai_post_not_found       (404)
 *   snt_ai_apply_conflict       (409) — fingerprint mismatch (post changed); JS prompts "re-run scan"
 *   snt_ai_replacement_invalid  (422) — empty / too-long / contains HTML
 *   snt_ai_capability           (403) — current_user_can('edit_post', $post_id) === false
 *   snt_ai_write_failed         (500)
 */
```

**Implementation:**
1. Load current `post_content` for `$post_id`.
2. Compute current fingerprint at `$position` for `$phrase`.
3. Compare to passed `$fingerprint`. Mismatch → `snt_ai_apply_conflict`.
4. Verify `substr( $post_content, $position, strlen($phrase) ) === $phrase`. If not → `snt_ai_apply_conflict` (defense-in-depth).
5. Splice: `substr_replace( $post_content, $replacement, $position, strlen($phrase) )`.
6. `wp_update_post( ['ID' => $post_id, 'post_content' => $new_content], true )`.
7. Return success payload.

### REST endpoints (back-compat with the established pattern)

```
POST /wp-json/signal-noise/v1/ai/alt-suggest          { attachment_id }
POST /wp-json/signal-noise/v1/ai/alt-apply            { attachment_id, alt_text }
POST /wp-json/signal-noise/v1/ai/drift-suggest        { post_id, phrase, position, context_snippet }
POST /wp-json/signal-noise/v1/ai/drift-apply          { post_id, phrase, position, replacement, fingerprint }
```

Permission callback for each: `current_user_can('edit_post', <the relevant post ID>)`.

### Ability registrations (canonical surface)

In `inc/abilities-registration.php`, add 4 abilities under the existing `signal-noise/` category:

```php
wp_register_ability( 'signal-noise/ai-alt-suggest', array(
    'label'               => 'Suggest alt text for an attachment',
    'description'         => 'Generate descriptive alt text for an image attachment using post + filename context.',
    'category'            => 'ai-generation',
    'permission_callback' => function( $input ) {
        $attachment_id = isset( $input['attachment_id'] ) ? (int) $input['attachment_id'] : 0;
        return current_user_can( 'edit_post', $attachment_id );
    },
    'execute_callback'    => 'snt_ability_ai_alt_suggest',
    'input_schema'        => array(
        'type'                 => 'object',
        'required'             => array( 'attachment_id' ),
        'properties'           => array(
            'attachment_id' => array(
                'type'        => 'integer',
                'description' => 'Image-attachment post ID to generate alt text for.',
                'minimum'     => 1,
                'examples'    => array( 1234 ),
            ),
        ),
        'additionalProperties' => false,
    ),
    'output_schema'       => array(
        'type'       => 'object',
        'properties' => array(
            'ok'            => array( 'type' => 'boolean' ),
            'suggestion'    => array( 'type' => 'string' ),
            'attachment_id' => array( 'type' => 'integer' ),
        ),
    ),
    'meta'                => array(
        'show_in_rest' => true,
        'annotations'  => array(
            'idempotent' => true,
        ),
    ),
) );
```

Pattern repeats for the other 3 abilities. The 2 suggest abilities use `annotations: { idempotent: true }`. The 2 apply abilities use `annotations: { destructive: true, idempotent: true }` (they write to the DB; running twice yields the same final state because the fingerprint check no-ops the second call). Execute callbacks are top-level named functions (`snt_ability_ai_alt_suggest`, etc.) following the v3.7.5 audit pattern, each delegating to its `snt_*_impl()` function via a `function_exists()` guard.

Note: this codebase uses `meta.show_in_rest + meta.annotations.{destructive,idempotent,readonly,open_world_hint}` for ability metadata. There is no `ai_callable` flag — every registered ability is AI-callable by virtue of being registered (gated by `permission_callback`). Verified against all 21 existing ability registrations in `inc/abilities-registration.php` (2026-05-25).

## 5. UX flow

### Findings table — initial state (Health admin tab)

When AI is available + finding belongs to `missing_alt` or `drift_time_phrases`:

```
| Subject                  | Note                            | Action  | AI fix       |
|--------------------------|---------------------------------|---------|--------------|
| logo-final-v2.png        | Image attachment has no alt...  | [Edit]  | [Suggest]    |
| ...                                                                              |
```

Per-check fieldset header gets a `[Suggest all 12]` button next to the count pill (visible only when AI is available + check has suggest+apply support).

### Suggest click — row transforms

```
| logo-final-v2.png  | Image attachment has no alt...  | [Edit]  |  ⟳ generating...  |
```

On success (~2–5 seconds):

```
| logo-final-v2.png  | Image attachment has no alt...  | [Edit]  | [Suggested alt text in editable textarea]    |
                                                                  | [Apply]  [Discard]                           |
```

The textarea is editable — user can refine the AI suggestion before applying.

On AI error: red border + error message inline in the AI-fix cell; row otherwise unchanged.

### Apply click — confirm + write

JS shows a `window.confirm()` dialog: `"Write this alt text to the attachment? This cannot be undone via this UI."` On OK → POST to apply endpoint → on success, replace row's AI-fix cell with `✓ Applied` + grey out the row. On conflict (drift only), red error: `"Post changed since scan. Re-run scan to refresh."`

### "Suggest all N" flow

- JS finds all rows in the section with un-suggested findings.
- For each, calls Suggest endpoint sequentially with a 500ms throttle (avoids hammering the AI provider rate limit).
- Each row transforms to its suggested state independently as responses land.
- Visible progress: button label updates to `Suggesting (3/12)…` then `Suggested all` on completion.
- No bulk-apply — user reviews + applies per row.

### Inline-img alt case (Apply disabled)

```
| inline img in "About" | Inline <img> has no alt...  | [Edit]  | [Suggest]    |
```

After Suggest:

```
| inline img in "About" | Inline <img> has no alt...  | [Edit]  | [Suggested alt text — read-only]              |
                                                                | Open the editor to apply.                     |
                                                                | [Copy suggestion]                             |
```

There is no Apply button for inline-img findings — only the read-only suggestion textarea + helper text + Copy button. `[Copy suggestion]` writes to clipboard via `navigator.clipboard.writeText()`.

## 6. Concurrency safety — fingerprint pattern

The drift-phrase apply is the riskiest write path because `post_content` is mutable and the scan-to-fix gap can be hours or days. The fingerprint pattern is the defense.

### Fingerprint algorithm

```php
function snt_ai_drift_fingerprint( $post_content, $phrase, $position ) {
    $start = max( 0, $position - 40 );
    $window = substr( $post_content, $start, 80 );
    return md5( $phrase . '|' . $window );
}
```

- 40 chars on each side of the phrase position = 80-char context window
- Phrase is hashed alongside the window so a phrase change inside the window invalidates the fingerprint even if surrounding chars are unchanged
- md5 is fast and 32 chars over the wire — cryptographic strength is unnecessary; collision space for an 80-char content window is ample

### How it gates apply

1. Suggest endpoint returns `{suggestion, fingerprint}`.
2. JS holds the fingerprint with the row state.
3. Apply request includes `fingerprint`.
4. Backend recomputes fingerprint from current `post_content` at `$position`.
5. Mismatch → `snt_ai_apply_conflict` (409). No write happens.

### Failure modes covered

- Post edited in another tab while AI is generating → mismatch.
- Two users hit Suggest on the same drift finding, one Applies first → second user's fingerprint mismatches (phrase has been replaced) → conflict surfaces cleanly.
- Post's other text edited but phrase + 80-char window unchanged → fingerprint still matches → apply succeeds (correctly — the edit didn't affect what we're writing).

### Failure modes NOT covered (acceptable)

- Phrase appears at multiple positions in `post_content` and a different occurrence was edited → fingerprint still matches the target position → apply writes correctly. We're targeting a specific byte position, not a phrase pattern.
- Post deleted between Suggest and Apply → `snt_ai_post_not_found` (404).

## 7. Cost model

| Action | AI calls | Tokens (avg in+out) | Cost at Sonnet 4.6 pricing | Wall time |
|---|---|---|---|---|
| Single alt Suggest | 1 | ~300 in + ~50 out | ~$0.0011 | ~2s |
| Single drift Suggest | 1 | ~250 in + ~40 out | ~$0.0009 | ~2s |
| Single Apply (alt or drift) | 0 | — | $0 | <1s |
| "Suggest all" on 50 alt findings | 50 | — | ~$0.055 | ~25s (500ms throttle) |
| "Suggest all" on 20 drift findings | 20 | — | ~$0.018 | ~10s |

Caps:
- No background generation: all calls are user-initiated.
- The 500ms throttle on "Suggest all" prevents rate-limit hits on Anthropic's tier and gives the user visible progress feedback.
- Apply is free (no AI call).
