# v4.4.0 — Cross-package contracts E2E + v5.0.0 readiness pass (A+D bundle)

**Status:** SPEC LOCKED via brainstorm 2026-05-26. Both workstreams (A: cross-package E2E tests; D: v5.0.0 readiness pass) bundled into a single minor. Next: `superpowers:writing-plans` to expand into a TDD-paced implementation plan.

**Repo:** `signal-and-noise-tools` plugin (theme untouched, except as a runtime dependency for smoke tests).

**Cap math:** plugin currently at v4.3.1 (patch 1/7). This minor rolls to v4.4.0. Plugin minor cap usage: 4/5 → **5/5 (FULL)**. **v4.4.0 is the LAST plugin minor before forced v5.0.0.** Plugin patch cap resets to 0/7 for v4.4.x (**7 patches available** before forced v5.0.0).

**Strategic context:** v5.0.0 will involve breaking changes (removed/renamed APIs, settings-schema migrations, or behavioral shifts requiring user action). The prerequisite work for v5.0.0 to ship cleanly cannot itself go in v5.0.0 — that release needs to focus on the breaking changes themselves, informed by D's inventory. v4.4.0 exists to do that prerequisite work.

---

## 1. Headline

**Two coordinated workstreams in one minor, no shared code surface.**

- **A** — Lock the 4 cross-package filter contracts ([WORDPRESS-REFERENCE §10.0](https://github.com/juanlentino/signal-and-noise/blob/main/docs/WORDPRESS-REFERENCE.md#10-the-theme--companion-plugin-split-v820--v840-complete-ongoing-contract-surface)) with hybrid tests. v5.0.0 can then refactor internal plumbing without breaking the theme half.
- **D** — Audit all public plugin APIs, identify v5.0.0 dispositions (KEEP / RENAME / REMOVE / SCHEMA-CHANGE), write a canonical v5.0.0 scope doc, and add `_deprecated_function()` runtime warnings on slated APIs. v5.0.0 starts from explicit scope, not guesswork.

**Together:** v4.4.0 buys v5.0.0 the canvas to break things safely and the contracts to refactor confidently.

---

## 2. Why this minor exists

The plugin has 4 minors deep (`v4.0.0`–`v4.3.x`) and hits the per-major minor cap at `v4.4.0`. The next bump is forced to be a major version. Two failure modes for v5.0.0 if v4.4.0 doesn't prep:

1. **Contract drift undetected.** v5.0.0 refactors a plugin internal that happens to feed `sn_og_font_paths`, but `font_paths` payload shape changes silently. Theme's OG card renderer breaks the next time anyone shares a /notes post on social. Nobody notices until someone reports a broken link preview.
2. **Deprecation scope ambiguity.** v5.0.0 reaches the cut-line with 30 candidate "things to rename" and no record of which were intentional public surface vs. which were always internal. Decisions get made by whoever's hands are on the keyboard at the moment, not by deliberate design.

Both are avoidable with v4.4.0's modest investment (~500 LOC test + docs + warning calls).

**Why bundle A and D in one minor:** they're complementary, not overlapping. A locks the *external* surface (theme↔plugin filter contracts) so v5.0.0 can refactor *internals*. D inventories the *internal* surface that v5.0.0 is going to break. Both serve the same goal — controlled v5.0.0 — from different angles.

## 4. Architecture

### 4.1 A — Stub-based contract tests

**File:** `tests/contracts-stub.php` (NEW).

**Pattern:** mirrors existing plugin tests — pure PHP, stub WP functions, assertion harness using the project's `pa_eq` / `pa_true` style.

**Per-contract test shape (×4):**

```php
// Contract: sn_purge_all_caches_result
echo "\nContract 1: sn_purge_all_caches_result\n";
$GLOBALS['__test_filters'] = array();
$GLOBALS['__test_callbacks'] = array();

// Stub add_filter to record registration.
// (Existing tests already use this stub pattern.)

// 1. Load plugin module that dispatches.
require_once __DIR__ . '/../inc/template-maintenance.php';
// 2. Load fake theme handler (or simulate via $GLOBALS).
$GLOBALS['__test_callbacks']['sn_purge_all_caches_result'] = function( $count ) { return 42; };

// 3. Stub apply_filters to invoke registered callback.
$result = apply_filters( 'sn_purge_all_caches_result', 0, array() );

// 4. Assert.
cs_eq( 42, $result, '1.1: theme listener invoked, returned count' );
cs_true( is_int( $result ), '1.2: return type is int' );
```

**Stub scaffolding:** this is a new test shape for the project — existing plugin tests don't stub `apply_filters`/`add_filter` because they exercise impl logic, not WP hook plumbing. The contract tests need a working filter simulator:

```php
$GLOBALS['__test_filters'] = array();

if ( ! function_exists( 'add_filter' ) ) {
    function add_filter( $hook, $callback, $priority = 10, $accepted_args = 1 ) {
        $GLOBALS['__test_filters'][ $hook ][] = $callback;
        return true;
    }
}
if ( ! function_exists( 'apply_filters' ) ) {
    function apply_filters( $hook, $value, ...$args ) {
        foreach ( $GLOBALS['__test_filters'][ $hook ] ?? array() as $cb ) {
            $value = call_user_func_array( $cb, array_merge( array( $value ), $args ) );
        }
        return $value;
    }
}
```

Plan phase can decide whether to inline this scaffolding in `tests/contracts-stub.php` or extract to a shared `tests/_filter-simulator.php` helper if other future tests need it.

**Total:** ~24 assertions across 4 contracts (~6 per contract).

### 4.2 A — WP-loaded smoke tests

**File:** `tests/contracts-smoke.php` (NEW).

**Invocation:** `wp eval-file tests/contracts-smoke.php` (manual, pre-tag). Optionally callable as `php tests/contracts-smoke.php` if it boots WP via `require_once ABSPATH . '/wp-load.php';` with `ABSPATH` set.

**Pattern:** assumes a real WP environment with theme + plugin installed. Directly invokes each filter and asserts the return.

```php
<?php
// tests/contracts-smoke.php — invoked via `wp eval-file` against a dev SN install.

if ( ! defined( 'ABSPATH' ) ) {
    // Allow direct PHP invocation by booting WP from the script.
    $wp_load = dirname( __DIR__, 4 ) . '/wp-load.php';
    if ( file_exists( $wp_load ) ) { require_once $wp_load; }
    else { die( "ABSPATH not set and wp-load.php not findable. Run via `wp eval-file`.\n" ); }
}

echo "Cross-package contract smoke tests — plugin v4.4.0\n";

// Contract 1: sn_purge_all_caches_result
$count = apply_filters( 'sn_purge_all_caches_result', 0, array() );
assert( is_int( $count ), 'sn_purge_all_caches_result must return int' );
echo "PASS: sn_purge_all_caches_result returns int ($count)\n";

// Contract 2: sn_clear_template_overrides_result
$count = apply_filters( 'sn_clear_template_overrides_result', 0 );
assert( is_int( $count ), 'sn_clear_template_overrides_result must return int' );
echo "PASS: sn_clear_template_overrides_result returns int ($count)\n";

// Contract 3: sn_og_font_paths
$paths = apply_filters( 'sn_og_font_paths', array() );
assert( is_array( $paths ), 'sn_og_font_paths must return array' );
assert( isset( $paths['bebas'] ), 'sn_og_font_paths must include bebas key' );
assert( isset( $paths['dmmono'] ), 'sn_og_font_paths must include dmmono key' );
assert( file_exists( $paths['bebas'] ), 'bebas TTF must exist at returned path' );
assert( file_exists( $paths['dmmono'] ), 'dmmono TTF must exist at returned path' );
echo "PASS: sn_og_font_paths returns valid font paths\n";

// Contract 4: sn_gh_latest_theme_tag_result
$tag = apply_filters( 'sn_gh_latest_theme_tag_result', null );
assert( is_null( $tag ) || is_string( $tag ), 'sn_gh_latest_theme_tag_result must return string|null' );
echo "PASS: sn_gh_latest_theme_tag_result returns string|null (" . var_export( $tag, true ) . ")\n";

echo "\nAll 4 contract smoke tests passed.\n";
```

**Total:** ~12 assertions, manual run only.

### 4.4 D — `_deprecated_function()` annotations

For every function in the inventory marked RENAME or REMOVE, add at the top of the function body:

```php
function sn_legacy_thing( $arg ) {
    _deprecated_function( __FUNCTION__, '4.4.0', 'sn_replacement_thing' );
    // ... existing body unchanged ...
}
```

`_deprecated_function()` is a WP core function that surfaces a warning in `debug.log` when `WP_DEBUG` is enabled. Doesn't break anything in production (WP_DEBUG off → silent). For replacements that don't exist, omit the third arg or pass `null`.

**Variants for non-functions:**
- Deprecated REST routes: handle in route registration (e.g., `_deprecated_function( 'REST route ' . $route, ... )` or a custom helper).
- Deprecated option keys: harder to flag automatically; document in the scope doc only.
- Deprecated hooks: WP has `apply_filters_deprecated()` / `do_action_deprecated()` if needed.

## 5. Testing strategy

### 5.1 New test surfaces
- **24 stub-based contract assertions** in `tests/contracts-stub.php` — runs in existing PHP harness, included in the standard 20-suite sweep.
- **12 WP-loaded smoke assertions** in `tests/contracts-smoke.php` — manual run via `wp eval-file` against a dev SN install before tagging v4.4.0 (and any v4.4.x patch).

### 5.2 Regression check
All existing 868 plugin test assertions must remain green.

**Deprecation-function stub requirement:** any test file that exercises a function which now contains a `_deprecated_function()` call will fatal-error unless `_deprecated_function()` is defined. The project's test fixtures stub WP functions per-file (`if ( ! function_exists( 'X' ) ) { function X() {} }` pattern). D's plan-phase work must:

1. Add `_deprecated_function()` as a no-op stub to every test file that includes a source module containing the call (`function _deprecated_function( $function, $version, $replacement = null ) {}`).
2. OR add the stub to a shared bootstrap file if/when test infra is refactored.

**Signal value:** if an existing test breaks because it exercises a deprecated API, that's *useful information* — the API isn't actually orphaned and should be reconsidered for KEEP rather than REMOVE in the v5.0.0 disposition.

### 5.3 No new test infrastructure
Both new files use the existing test idiom. No PHPUnit, no `wp-tests-lib`, no MySQL fixture. The smoke runner uses `wp eval-file` which is part of WP-CLI (no install needed beyond what every dev environment has).

## 6. Release process

Standard project workflow per [CLAUDE.md](../../CLAUDE.md):

1. Implement A (both test files), then D (audit → scope doc → annotations → CHANGELOG entry).
2. All test suites green (`for f in tests/*.php; do php $f; done` → 0 failed across all 20+ suites; +24 from new stub tests; +0 from smoke tests since they're manual).
3. Manually run `wp eval-file tests/contracts-smoke.php` on a dev SN install. All 4 contract assertions pass.
4. Bump `Version: 4.3.1` → `Version: 4.4.0` in `signal-and-noise-tools.php` docblock. `SNT_VERSION` constant auto-updates per the docblock-derived pattern.
5. CHANGELOG entry at top of `CHANGELOG.md` with the "Deprecated" subsection from §4.5.
6. Commit `v4.4.0: cross-package contracts E2E + v5.0.0 readiness pass`.
7. Annotated tag `v4.4.0` per project format.
8. Push origin HEAD:main + tag.
9. Update WORDPRESS-REFERENCE §10.0 if the 4 cross-package contracts table needs revision (likely no — A doesn't change the contracts themselves).
