# v4.8.0 — Post-editor sidebar consolidation + AI prepopulation (SPEC STUB)

**Status:** STUB captured 2026-05-27. Forward-looking idea — needs full BC + plan when v4.6.x + v4.7.0 (if it ships) gate stable.

**Why this is a stub, not a full spec:** user surfaced via screenshot review of the post editor sidebar 2026-05-27. Two related observations:
1. Several AI-generation surfaces are duplicated between the `ai/ai` plugin and Signal & Noise plugin (most notably meta description).
2. The OG card title, meta description, and excerpt could be **prepopulated** at save time so fields aren't empty when a post publishes.

The concrete decisions (which duplications to hide, which writes to coordinate, exact length constraints on AI output) are sketched here; finalize at v4.8.0 BC.

Two parallel workstreams in one minor:

**A. Sidebar cleanup** — eliminate the user-facing duplications between `ai/ai` plugin's AI-generation surfaces and Signal & Noise plugin's surfaces. Reduce 8 scattered AI-generation buttons to a coherent layout.

**B. AI prepopulation** — auto-generate OG card title + meta description + excerpt at the `draft → publish/scheduled` transition, ONLY when the field is empty. Surface a tiny inline notice so the user knows.

## §2. Existing surface — duplications observed (2026-05-27 screenshots)

### Real duplication

**Meta description** appears in TWO places:
- Top-level `Meta Description` section with `Generate Meta Description` button — contributed by `ai/ai` plugin.
- Inside `Signal & Noise` section, a `Meta description` FIELD with `Generate with AI` button — writes to `sn_meta_description` post meta, used by SN's SEO output (`<meta name="description">`, OG description, JSON-LD).

The fields likely target different post-meta keys. AI plugin's button probably doesn't reach SN's SEO module. **Both UI clutter AND possibly orphaned data**, pending source audit of `ai/ai` at BC time.

### Soft duplication (scattered, not strictly redundant)

| Button | Owner | Section |

## §3. Cleanup directions

Three approaches; pick at BC. Each is independently shippable.

**3.1 Remove duplicate AI-plugin panels (smallest, lowest risk)**

The top-level `Meta Description` panel from `ai/ai` is redundant with SN's own meta description field. Hide it via `remove_meta_box` or filter on `ai/ai`'s panel registration. Requires identifying the panel's slug in `ai/ai` source.

Estimated: ~30 LOC.

**3.2 Coordinate writes (medium)**

When `ai/ai`'s `Generate Meta Description` button runs, redirect its write to SN's `sn_meta_description` post meta key. Read `ai/ai`'s source to find the right filter; if no filter exists, fall back to 3.1.

Estimated: ~50 LOC + ~30 LOC for source audit time.

**3.3 Consolidate AI generation into one SN panel (biggest, highest ambition)**

Hide all scattered `ai/ai` AI-generation buttons. Surface every AI helper in a single `Signal & Noise → AI helpers` subsection with consistent layout (label + brief description + button + status indicator after click).

Risk: aggressive removal of `ai/ai` UI may break other things (the AI plugin may rely on its own surfaces for status feedback). Test thoroughly.

Estimated: ~200 LOC.

**Recommended starting point:** 3.1 only. If that lands cleanly + the duplication confusion resolves, ship and stop. 3.2 and 3.3 are deferrable.

## §4. AI prepopulation pattern

**Trigger:** `transition_post_status` action firing when post status changes from `draft` to `publish` or `future`.

**Generation rule** (the same rule applies to all 3 fields — OG card title, meta description, excerpt):

```php
function snt_prepopulate_field( $post_id, $field_meta_key, $ability_slug, $min_words = 200 ) {
    // 1. Skip if field is already populated — never overwrite manual edits.
    $existing = get_post_meta( $post_id, $field_meta_key, true );
    if ( ! empty( $existing ) ) {
        return;
    }

    // 2. Skip if content too short — not enough to generate from.
    $word_count = str_word_count( wp_strip_all_tags( get_post( $post_id )->post_content ) );
    if ( $word_count < $min_words ) {
        return;
    }

    // 3. Skip if AI is unavailable.
    if ( ! function_exists( 'snt_ai_is_available' ) || ! snt_ai_is_available() ) {
        return;
    }

    // 4. Generate via existing ability.
    $ability = wp_get_ability( $ability_slug );
    if ( ! $ability ) {
        return;
    }
    $result = $ability->execute( array( 'post_id' => $post_id, 'concise' => true ) );
    if ( ! is_array( $result ) || empty( $result['text'] ) ) {
        return;
    }

    // 5. Write + record sentinel for admin notice.
    update_post_meta( $post_id, $field_meta_key, sanitize_text_field( $result['text'] ) );
    update_post_meta( $post_id, $field_meta_key . '_was_auto_generated', '1' );
}
```

**Length constraint on generated text** (per user 2026-05-27): **"a few short sentences, maybe up to 3."** The AI ability prompts must include this constraint explicitly:

| Field | Length budget (prompt instruction) |
|---|---|
| OG card title | 60–90 chars — single line, no period. (Already enforced.) |
| Meta description | **1–3 short sentences, ≤ 160 characters.** Tighter than the current ability's default. |
| Excerpt | **Up to 3 short sentences, ~40–60 words.** Tighter than the current 50–75-word target — explicitly says "short sentences." |

**Why the tighter excerpt budget:** the user observed that generated text trends long. "Up to 3 sentences" is the explicit ceiling. The existing 50–75-word target produced 5+ sentences in practice (per the AI's natural verbosity). Prepopulated content should default to PUNCHY, not COMPREHENSIVE.

**Implementation:** add a `concise` boolean parameter to the relevant abilities (`signal-noise/ai-generate-meta-description`, `signal-noise/ai-generate-excerpt`). When `true`, the prompt instructs "Respond in 1–3 short sentences. No more." When `false` (default for manual generation), keep current behavior.

**Admin notice on next edit:** after auto-generation lands, the next time the user opens the post editor, show a dismissible inline notice next to the field: "*This was auto-generated when you published. [Edit] [Regenerate]*". Notice clears when user edits OR dismisses.

## §5. Anti-scope

- NOT v4.6.0 work — pure prep, no UX additions.
- NOT v4.6.x patches — bugfix only.
- NOT v4.7.0 work — that's the admin-bar expansion stub. Different surface. Could potentially BUNDLE into one minor if scope allows, but cleaner as separate cycles.
- NOT v5.0.0 — pure removals.
- NOT a refactor of `ai/ai` plugin internals — only hide / redirect / consolidate from OUR side via filters.
- NOT auto-generation on every save — ONLY on `draft → publish/scheduled` transition. Drafts stay un-generated to avoid burning AI calls + accidentally locking in placeholder content.
- NOT auto-generation that overwrites existing manual content. Empty-field-only rule is absolute.
- NOT generation of post titles — those are user-authored. Only the SUPPLEMENTARY metadata (OG card title, meta desc, excerpt) gets auto-fill.
