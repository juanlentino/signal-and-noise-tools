# v5.0.0 scope — public API audit (compiled v4.4.0)

**Compiled:** 2026-05-26 during v4.4.0 D workstream.

**Method:** grep-based audit of `signal-and-noise-tools` source for `sn_*` function declarations, `register_rest_route` calls, `apply_filters` / `do_action` dispatches with `sn_` or `signal-noise/` prefix, and `update_option` writes (resolved via the `SN_*_OPT` constants since all option keys flow through constants rather than literal strings). Each finding categorized as KEEP / RENAME / REMOVE / SCHEMA-CHANGE.

**Audit philosophy:** v5.0.0 is a *controlled* deletion exercise, not a sweeping rewrite. Default disposition is **KEEP**. RENAME/REMOVE require a specific reason backed by docblock or callers analysis. The four cross-package contracts already locked by v4.4.0 Tasks 1–3 (`sn_purge_all_caches_result`, `sn_clear_template_overrides_result`, `sn_og_font_paths`, `sn_gh_latest_theme_tag_result`) are KEEP-by-mandate.

## 6. Out of scope for v5.0.0

Items considered during this audit and explicitly deferred to v5.1.x or later:

- **REST route consolidation: deprecate the 4 `@deprecated since 2.5.0` legacy routes** (`/ai/generate-meta-description`, `/ai/generate-excerpt`, `/ai/generate-og-card-title`, `/cmd/<action>`). Removing these requires first migrating the corresponding JS clients in `assets/` to ability-only paths (no back-compat fallback), AND coordinating with the external WordPress/desktop-mode plugin for the `/cmd/<action>` route. Both prerequisites are outside v5.0.0 scope. Revisit when `assets/ai-*.js` files are next refactored.

- **Internal function namespacing.** Functions like `sn_pl_*` (Plausible widget internals) or `sn_admin_render_*` (admin template helpers) are file-internal but use the same flat namespace as public functions. A future refactor could bundle them into classes or rename them with an internal prefix (`sn_internal_*`). Out of scope — purely cosmetic, no behavioral or contract impact.

- **`sn_admin_pages()` legacy table removal.** Already `@deprecated 4.2.0` but still drives the legacy-URL redirect map. Removing it would break bookmarks pointing to pre-v3.8.0 admin tab URLs. Revisit in v6.x once enough time has elapsed that legacy bookmarks have decayed.

- **Theme-side cross-repo audit.** This document covers plugin surface only. The theme (`signal-and-noise`) has its own public-API surface (functions defined in `inc/template-maintenance.php`, `inc/wp-update-integration.php`, etc.) that may warrant a parallel scope document during theme's own v10.0.0 prep. Out of scope here.

- **Action hooks renaming for namespace consistency.** Hooks under the `sn_admin_*_tab` pattern (9 entries) are admin-internal extension points. Renaming them to `sn/admin/<slug>/tab_render` (slash-namespace) would improve discoverability but force a 9-file refactor with no functional benefit. Defer.

No SCHEMA-CHANGE dispositions were identified. The one REMOVE entry (`sn_login_rewrites_flushed` option) requires no shim — it's a one-line `delete_option()` call in v5.0.0's upgrade path, and the option is already dead (no code reads or writes it since v4.2.1).

**v5.0.0 upgrade-path code snippet** (for reference when v5.0.0 is implemented):

```php
// inc/migrations.php or activation hook
if ( get_option( 'sn_settings_migrated_v1' ) && ! get_option( 'sn_v500_cleanup_done' ) ) {
    delete_option( 'sn_login_rewrites_flushed' );  // orphaned since v4.2.1
    update_option( 'sn_v500_cleanup_done', '1', true );
}
```

This is documentation-only at v4.4.0 — the actual code lands in v5.0.0.
