# v4.1.0 Design — AI Suggest+Apply for orphaned-media

**Status:** Approved 2026-05-25 (brainstorm session)
**Target ship:** plugin v4.1.0 (first minor in v4.x; 0/5 in minor cap, 0/7 in patch cap)
**Estimated:** ~270 LOC of production code across 1 new file + 4 edits (~400 LOC including tests + changelog). 5-6 implementation tasks.
**Predecessor decisions:**
- v4.0.0 — established Suggest+Apply 3-surface convention (impl / REST / Ability)
- v4.0.1 — established `(subject_id, modified, prompt_version_md5)` transient cache for AI verdicts
- v4.0.2 — established `apply: null` sentinel for read-only-Suggest variants
- v4.0.3 — established `openApplyModal()` Before/After preview pattern

---

## 1. Why this ships

v4.0.x shipped Suggest+Apply for two of the five Health check types (`missing_alt` for attachment + inline-`<img>`, `drift_time_phrases`). The original v4.0.0 brainstorm explicitly deferred two checks: `stale_posts` and `orphaned_media`.

**The original v4.1.0 brainstorm started with both** (Theme A — "Complete the Suggest+Apply suite"). Mid-design, a new constraint surfaced: **juanlentino.com's posts are evergreen by design**. The stale-posts AI Suggest feature is mismatched to this site — it would fire ~50 AI calls per scan to generate suggestions the user would dismiss every time. The `drift_time_phrases` check already handles the actual decay vector in evergreen content (time-relative phrases like "as of 2024", "recently"). Stale-posts is therefore **dropped** from v4.1.0 and removed from the v4.x roadmap.

**Orphan-media remains valuable regardless of evergreen-status.** Orphaned attachments accumulate from drafts, screenshots, image iterations, and aborted media-library uploads. The existing v3.5.0 detection (not-featured-image AND basename-not-in-any-post-content AND older-than-7-days) is already in place; v4.1.0 adds the AI verdict layer that turns "here are 50 maybe-orphans" into "here are 8 deletes / 35 keeps / 7 needs-review."

## 2. Scope

### In v4.1.0

- **New file** `inc/ai-orphan-suggest.php` — both `snt_ai_orphan_suggest_impl()` and `snt_ai_orphan_apply_impl()` plus their REST routes (mirrors `inc/ai-alt-text-suggest.php` layout).
- **2 new Abilities registered** in `inc/abilities-registration.php`: `signal-noise/ai-orphan-suggest` and `signal-noise/ai-orphan-apply`.
- **Verdict-shaped response from Suggest**: `{ verdict: "delete"|"keep"|"unsure", reason: string, attachment_id, thumbnail_url, filename }`. First feature in the suite to return a verdict instead of a `suggestion` string.
- **New JS render branch** in `assets/health-suggest-actions.js` keyed on `res.verdict` (existing branches stay untouched). 3-state UI: red Delete button for "delete", "✓ Likely keep" for "keep", "? Manual review" + Edit link for "unsure".
- **Delete confirmation modal** reuses `openApplyModal()` from v4.0.3 with a new `buildOrphanDeleteModalContent()` sibling builder. Shows thumbnail + filename + reason (Before pane) + warning text (After pane).
- **Verdict cache** under `sn_orphan_verdict_<attachment_id>` transient, 30-day TTL, keyed on `(post_modified_gmt, md5(SYSTEM_PROMPT))`. Same shape as v4.0.1 drift cache.
- **Apply** calls `wp_delete_attachment($id, true)` (force=true — bypasses trash). Cache entry explicitly cleared on successful delete.
- **Admin UI** adds `'orphaned_media'` to `$suggest_supported_checks` (`inc/health-checks-admin.php` L28) and adds a render branch in `sn_health_render_suggest_cell()` that emits `data-check="orphaned_media"` + `data-attachment-id`.

### Out of scope (deliberate non-goals)

- **stale-posts AI Suggest** — dropped permanently per evergreen-mismatch (Section 1)
- **Bulk delete** ("Delete all delete-verdict rows in one click") — too dangerous as first ship; user confirms each individually
- **Force re-evaluate button** — if AI says "keep" but user disagrees, workaround is Discard → wait for cache decay (30d) or delete via Media Library. Revisit if friction surfaces in production
- **Restore from trash** — `wp_delete_attachment($id, true)` is force-delete by design; matches user intent of "this is junk, remove it"
- **Provider-aware cache key** — switching AI providers mid-cache will serve consistent verdicts until 30d expiry. Acceptable; add `provider_slug` to cache key only if real complaints surface
- **Per-feature audit log entries** — existing audit-log surfaces admin actions broadly; no orphan-specific log emission
- **Detection-layer changes** — `sn_health_check_orphaned_media()` SQL detection unchanged from v3.5.0; v4.1.0 is AI-layer-only
- **CSS file for the modal** — inline styles via JS, matches v4.0.3 convention
- **JS unit tests** — matches existing alt/drift posture; gate-walk covers verdict-render logic

## 3. Architecture

```
orphaned_media check (existing SQL detection, unchanged)        v4.1.0 AI Suggest+Apply layer
────────────────────────────────────────────────                ──────────────────────────────────
sn_health_check_orphaned_media()              ─→                snt_ai_orphan_suggest_impl($att_id)
  └─ returns N flagged attachments                                 ├─ cache lookup: sn_orphan_verdict_<id>
     (not featured + basename not in post_content                  ├─ AI call (if miss): returns {verdict, reason}
      + older than 7 days)                                         └─ cache write (30d TTL)

                                                                snt_ai_orphan_apply_impl($att_id)
                                                                   ├─ capability check: delete_post
                                                                   ├─ wp_delete_attachment($id, force=true)
                                                                   └─ delete_transient(sn_orphan_verdict_<id>)
```

Shared infrastructure (no changes): `snt_ai_generate_with_constraints()`, `openApplyModal()` + close/focus-trap handlers, `ABILITY_BY_CHECK` dispatch map (+1 row), 3-surface convention (impl / REST / Abilities API).

## 5. Data flow

### Suggest path (per row, called by Suggest button or Suggest-all)

```
User clicks [Suggest] in orphan-media row
   │
   ▼
JS: onSuggestClick(event)
   │   reads data-check="orphaned_media", data-attachment-id=N
   │   input = { attachment_id: N }
   ▼
JS: callAbility('ai-orphan-suggest', input)
   │   POST /wp-abilities/v1/abilities/signal-noise/ai-orphan-suggest/run
   │   body: { input: { attachment_id: N } }
   ▼
PHP: ability callback → snt_ai_orphan_suggest_impl(N)
   │
   ├─ Gate: snt_ai_can_text_generate()           → snt_ai_unavailable (503) if no
   ├─ Gate: get_post(N) is attachment + image/*  → snt_ai_not_attachment (422) if no
   │
   ├─ Cache lookup: get_transient("sn_orphan_verdict_$N")
   │   if hit AND cached.modified === post_modified_gmt
   │       AND cached.prompt_version === md5(SYSTEM_PROMPT)
   │     → return cached.payload  (skip AI call)
   │
   ├─ Build prompt context:
   │     - filename, title, caption, post_date
   │     - parent post title (if attached)
   │     - basename, MIME type, dimensions
   │
   ├─ snt_ai_generate_with_constraints($prompt, SYSTEM, max_tokens=120)
   │   AI returns JSON: { "verdict": "delete"|"keep"|"unsure", "reason": "..." }
   │
   ├─ Parse + validate verdict (3 allowed values; anything else → "unsure" fallback)
   │
   ├─ set_transient("sn_orphan_verdict_$N", { modified, prompt_version, payload }, 30*DAY)
   │
   └─ return { ok, verdict, reason, attachment_id, thumbnail_url, filename }
                                       ▲
                                       │ JSON over REST
                                       ▼
JS: renderSuggestion(cell, res, applyAbility, input, checkType)
   │
   ├─ if (res.verdict)                  // NEW v4.1.0 branch
   │     switch (res.verdict)
   │       'delete' → cell shows reason + [Delete] button (red) + [Discard]
   │       'keep'   → cell shows "✓ Likely keep" + reason + [Discard] (no Apply)
   │       'unsure' → cell shows "? Manual review" + reason + Edit link
   │
   └─ else (existing path for alt/drift)
         standard textarea + Apply/Discard
```

### Apply path (only for verdict === 'delete' rows)

```
User clicks [Delete] in cell
   │
   ▼
JS: onApplyClick(...) calls openApplyModal({
        title: "Permanently delete this attachment?",
        beforeNode: buildOrphanDeleteModalContent() → thumbnail + filename + reason
        afterNode:  warning text ("This deletes the file and DB record. No undo.")
        originatingButton: deleteBtn,
        onApply: doDelete,
        onCancel: noop,
   })
   │
   ▼
User clicks modal's [Apply] button
  (button text stays "Apply" — the destructive intent is carried by the modal TITLE
   "Permanently delete this attachment?" + the After-pane warning text.
   Rationale: changing the shared openApplyModal() signature to add an applyLabel
   opt would risk regressing the v4.0.3-shipped alt + drift Apply paths.)
   │
   ▼
JS: callAbility('ai-orphan-apply', { attachment_id: N })
   ▼
PHP: snt_ai_orphan_apply_impl(N)
   │
   ├─ Gate: current_user_can('delete_post', N)   → snt_ai_capability (403)
   ├─ Gate: get_post(N) is attachment             → snt_ai_not_attachment (422)
   │
   ├─ wp_delete_attachment(N, true)
   │   if false/null → snt_ai_delete_failed (500)
   │
   ├─ delete_transient("sn_orphan_verdict_$N")    // cache stale after deletion
   │
   └─ return { ok: true, attachment_id: N, deleted: true }
                                       ▲
                                       ▼
JS: renderApplied(cell) → "✓ Deleted"; row.style.opacity = 0.5
```

### Boundary contracts

| Boundary | Input shape | Output shape |
|---|---|---|
| JS → suggest REST | `{ input: { attachment_id: int } }` | `{ ok, verdict, reason, attachment_id, thumbnail_url, filename }` or `WP_Error` |
| JS → apply REST | `{ input: { attachment_id: int } }` | `{ ok, attachment_id, deleted: true }` or `WP_Error` |
| AI prompt → AI response | text prompt | strict JSON: `{ "verdict": one-of-3, "reason": str }` |
| Cache slot | `sn_orphan_verdict_<N>` (30d TTL) | `{ modified: gmt, prompt_version: md5, payload: {...} }` |

**Security invariant:** the apply REST does NOT take a verdict parameter. The server re-validates capability + attachment existence from scratch. A crafted apply request with `verdict="delete"` for an arbitrary attachment still has to pass `current_user_can('delete_post')` + `get_post()` checks. Verdict is JS-side display logic only; the destructive action is independently authorized.

## 6. AI prompt + verdict contract

```php
const SNT_AI_ORPHAN_SUGGEST_SYSTEM = "You are evaluating whether a WordPress media attachment is safe to delete.\n\n" .
    "Context provided: filename, title, caption, MIME type, upload date, parent post title (if any).\n\n" .
    "The attachment has already been confirmed via SQL to be:\n" .
    "- NOT used as any post's featured image\n" .
    "- NOT referenced (by basename) in any published post body\n" .
    "- Older than 7 days\n\n" .
    "Your job: weigh whether the attachment is genuinely orphaned (safe to delete) or might still be in use somewhere the SQL didn't catch (widgets, customizer settings, theme.json refs, template parts).\n\n" .
    "Return ONLY a JSON object on a single line: {\"verdict\": \"delete\"|\"keep\"|\"unsure\", \"reason\": \"<one short sentence>\"}\n\n" .
    "Rules:\n" .
    "- \"delete\": filename + metadata suggest a one-off upload that was never integrated (e.g., screenshot-2024-03.png with no caption, no parent post)\n" .
    "- \"keep\": filename or metadata suggest a meaningful asset that may be referenced outside post_content (logo-final.svg, hero-banner.jpg, site-logo-*)\n" .
    "- \"unsure\": insufficient signal to recommend either way\n" .
    "- Be conservative: if in doubt, return \"unsure\" not \"delete\"\n" .
    "- Output JSON only. No markdown, no preamble, no trailing text.";

const SNT_AI_ORPHAN_SUGGEST_MAX_TOKENS = 120;
```

**Parse rules:**
- Strip optional markdown fences before `json_decode()` (same pattern as v4.0.1 drift)
- If `json_decode()` fails OR `verdict` isn't one of `delete`/`keep`/`unsure` → fallback to `verdict = "unsure"`, `reason = "AI response could not be parsed; review manually"`. Do NOT error out — preserve the finding with a useful state.

## 7. Error handling + edge cases

### `snt_ai_orphan_suggest_impl()` WP_Error codes

| Code | HTTP | Trigger | Message |
|---|---|---|---|
| `snt_ai_unavailable` | 503 | `snt_ai_can_text_generate()` returns false | "AI text generation is not available. Upgrade to WordPress 7.0+ and configure a provider in Settings > Connectors." |
| `snt_ai_not_attachment` | 422 | `get_post($id)` null OR not attachment OR mime not `image/*` | "Not an image attachment." |
| `snt_ai_runtime_error` | 500 | AI client returns WP_Error | Bubbles underlying error |
| `snt_ai_empty_response` | 502 | AI returns empty string | "AI returned empty response." |

(Note: invalid-verdict does NOT raise an error — it falls back to `verdict=unsure` per Section 6.)

### `snt_ai_orphan_apply_impl()` WP_Error codes

| Code | HTTP | Trigger | Message |
|---|---|---|---|
| `snt_ai_capability` | 403 | `!current_user_can('delete_post', $id)` | "You cannot delete this attachment." |
| `snt_ai_not_attachment` | 422 | `get_post($id)` null OR not attachment | "Attachment not found or already deleted." |
| `snt_ai_delete_failed` | 500 | `wp_delete_attachment($id, true)` returns false/null | "Delete failed. Check file permissions on uploads/." |

### Edge cases

| ID | Case | Handling |
|---|---|---|
| E1 | Attachment deleted between Suggest and Apply (TOCTOU) | `snt_ai_orphan_apply_impl()` re-checks `get_post($id)`. Returns `snt_ai_not_attachment (422)`. Cell shows "✗ Already deleted." Graceful. |
| E2 | AI returns malformed JSON | Falls back to `verdict=unsure`, preserves the finding. Does NOT error out. Does NOT cache the fallback (only successful parses cache). |
| E3 | Attachment used in widget/customizer/theme.json (SQL detection blind spot) | AI can't see those either. Modal warning + opacity:0.5 row act as final signal. User picks Discard if they know better. 30d cache TTL means false-positives don't keep re-asking. |
| E4 | User has dozens of orphans; "Suggest all" floods provider | Existing `onSuggestAllClick()` does sequential 500ms-throttled iteration. Cap of 50 visible rows means worst case is ~50 calls per scan iteration → ~30 seconds wall-clock, ~$0.025 in tokens. |
| E5 | AI verdict is `keep`, user disagrees | Discard button resets cell. To force re-eval: wait 30d (cache decay) OR delete manually via Media Library OR run `wp transient delete sn_orphan_verdict_<id>` via wp-cli. Acceptable v4.1.0 behavior. |
| E6 | `wp_delete_attachment()` fails because file is gone but DB row exists | The function still deletes DB row + meta when file is missing — returns success. True failures only happen on DB error → `snt_ai_delete_failed (500)`. |
| E7 | `wp_delete_attachment()` partial-success (DB row gone, files orphaned on disk) | Acceptable. User intent was "remove this attachment from WP." Disk cleanup is a separate operational concern. |
| E8 | Cache key collision after attachment_id reuse | `cached.modified === post_modified_gmt` invariant catches reuse. Safe. |

**Errors are NOT cached.** Only successful parses (including `unsure`-fallbacks) cache. Provider hiccups never poison the cache.

## 8. Cost model + cache invariants

### Per-scan cost — worst case (50 orphans, cold cache)

| Phase | Calls | Per-call cost | Total |
|---|---|---|---|
| Suggest (cold cache, all 50) | 50 sequential @ 500ms throttle | ~150 in + ~30 out tokens | ~9,000 tokens |
| Suggest (warm cache, all 50 unchanged) | 0 AI calls | — | $0.00 |
| Apply (user deletes 30 of the 50) | 0 AI calls | — | $0.00 |

**Token math (Anthropic Sonnet, current SN default):** ~150 in + ~30 out per call × 50 = ~9,000 tokens. At Sonnet pricing (~$3/M in, ~$15/M out): **~$0.025 per full cold scan**.

**Wall-clock:** 50 × ~600ms (call+throttle) = ~30s for full "Suggest all" pass.

### Cache slot

**Key:** `sn_orphan_verdict_<attachment_id>`
**TTL:** `30 * DAY_IN_SECONDS`

**Payload:**
```php
array(
    'modified'       => $attachment->post_modified_gmt,
    'prompt_version' => md5( SNT_AI_ORPHAN_SUGGEST_SYSTEM ),
    'payload'        => array(
        'ok'            => true,
        'verdict'       => 'delete'|'keep'|'unsure',
        'reason'        => '...',
        'attachment_id' => N,
        'thumbnail_url' => '...',
        'filename'      => '...',
    ),
)
```

**Hit requires:** `cached.modified === current post_modified_gmt` AND `cached.prompt_version === md5(current SYSTEM)`. Either drifts → cache miss → fresh AI call.

### Invalidation paths

| Trigger | Effect |
|---|---|
| Attachment edited (title/caption/alt) → `post_modified_gmt` bumps | Auto-invalidates (modified mismatch) |
| System prompt tuned in v4.1.x patch | Auto-invalidates all entries (md5 mismatch) |
| Attachment deleted via Apply | `delete_transient()` explicit cleanup (E1 belt+suspenders) |
| Attachment deleted manually (Media Library) | Stale cache survives 30d; harmless (next Suggest 422s on `get_post()`) |
| User forces re-eval | No UI; manual `wp transient delete sn_orphan_verdict_*` via wp-cli |
| TTL expires (30d) | Natural decay |

### Pathological cases handled

| ID | Case | Outcome |
|---|---|---|
| P1 | 500+ orphans (detection cap edge) | Detection caps at LIMIT 500. Visible-rows cap at 50. Suggest-all runs against ≤50. Cost bounded. |
| P2 | Tight-loop Health scans (cron-style) | No AI calls unless user clicks Suggest. Detection is unchanged. No regression. |
| P3 | Provider down for hours | All Suggest clicks return 500. Inline error displays. No cache poisoning (errors not cached). User retries. |
| P4 | Provider switch mid-cache (Anthropic → Gemini) | Serves Anthropic verdicts until 30d expiry. Acceptable. Provider-aware cache key deferred per YAGNI. |
