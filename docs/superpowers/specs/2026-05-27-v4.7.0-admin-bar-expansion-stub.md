## §2. Existing surface (reference)

Current dropdown structure in `inc/admin-bar.php`:

```
S&N ▾
├── ↻ Purge All Caches        (sn_quick_purge_caches)
├── ⌫ Clear DB Overrides      (sn_quick_clear_overrides)
├── ☁ Purge Cloudflare         (sn_quick_cf_purge — guard: sn_cf_is_configured)
└── ⚙ Open Dashboard           (link only — no action)
```

**Architecture pattern:**
- Single source of truth: `sn_admin_bar_items()` returns array of `{ action, label, guard? }`
- Per-action AJAX handlers registered on `wp_ajax_<action>`
- Per-action nonces, `manage_options` capability check at multiple layers
- Toast notifications via inline JS (XSS-safe `textContent` manipulation)
- Unicode glyphs in labels (no Dashicons dependency — avoids lazy-load layout shift)

**Adding a new item is mechanical:**
1. Add entry to `sn_admin_bar_items()` array (id, action, label, optional guard).
2. Register the `wp_ajax_<action>` handler in the `init` action's `$handlers` array.
3. Write the handler function (check nonce + cap, dispatch the work, send JSON response).

## §4. Decisions deferred to BC

1. **Final label wording + glyphs.** Each candidate has a draft above but may shift after design review (e.g., should "Regen OG Card" say "Regenerate OG image" instead? More verbose but unambiguous).
2. **Guard logic for "Regen OG Card."** Contextual to post edit pages — exact `$screen` checks need verification at BC.
3. **Toast message wording.** Each action produces a toast — copy needs draft + review.
4. **Sub-menu ordering.** Currently the items appear in array-declaration order. Should the new items go above or below the existing destructive items?
5. **Should we add visual separators?** WP admin bar supports a `wp-admin-bar-add-new` style separator pattern; might help group "destructive" actions vs "diagnostic" actions vs "context" actions.

## §6. Anti-scope

- NOT v4.6.0 work — v4.6.0 ships abilities + prep only. Bundling admin-bar items into v4.6.0 expands the prep minor (~540 → ~700 LOC) and mixes additive plumbing with user-visible UX. Cleaner to keep v4.6.0 thin.
- NOT a v5.0.0 work — v5.0.0 is pure removals. Admin-bar additions would muddy the breaking-change narrative.
- NOT a v4.6.x patch — those are bugfix only per spec §4.
- NOT a v4.7.0+ catchall — if v4.7.0 also picks up other emergent work (e.g., mimestream release notes infrastructure), that's a separate workstream within the same minor; the admin-bar expansion stands on its own.
