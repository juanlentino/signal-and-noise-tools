# Design — v3.8.1 sub-tabs + sidebar fix + cache fix

**Date:** 2026-05-25
**Status:** APPROVED (3 sections, user-confirmed via brainstorming)
**Ships as:** plugin **v3.8.1** + theme **v9.1.5** (two separate atomic ships)
**Scope:** Refinement of v3.8.0 IA reorg based on real-world usage feedback. Three issues addressed; no new functional capability.
**Brainstorm session:** 2026-05-25 (immediately post-v3.8.0 ship, in response to user-observed issues)

---

## TL;DR

v3.8.0 shipped the 6-tab IA reorg with internal-TOC pattern for sub-sections. Real-world use surfaced three issues:

1. **WP submenu duplicates in-page tabs in desktop-mode.** The 12 legacy WP submenu entries (kept for "preserve deep-link shortcuts") render as a horizontal top nav in desktop-mode plugin, visually duplicating the 6-tab in-page nav.
2. **Long scrolling per tab.** Internal-TOC pattern forces each multi-section tab onto one long page. User explicitly asked for sub-tabs (click-to-swap) instead of scroll-to-anchor.
3. **Plugin version cache stale.** SSH deploys don't invalidate WP's `get_plugin_data()` cache; dashboard widget reports stale version.

**Resolution:**
- **Sub-tabs (click-to-swap, URL-driven)** replace internal-TOC scrolling on multi-section top tabs. EXCEPT Identity's 4 form-coupled sections, which preserve internal TOC inside an "Identity & SEO" sub-tab (preserves the single-save UX). Ships as plugin v3.8.1.
- **WP submenu reduces to 6 entries** (matching new top tabs). Eliminates desktop-mode duplication. Legacy URLs still 301-redirect via extended redirect map. Ships in same plugin v3.8.1.
- **Plugin cache invalidation** added to theme's purge filter chain. Ships as theme v9.1.5 (2 LOC fix).

Two atomic ships: theme v9.1.5 FIRST (so plugin v3.8.1's verification can validate the cache fix), then plugin v3.8.1.

## Problem statement

### Issue 1: WP submenu duplication in desktop-mode

**Symptom:** screenshot shows two visually-similar nav rows above the SN admin content:
- Top row: "Dashboard | Identity | Login | Cloudflare | Plausible | RSS | Reading Time | Links" (12 entries, OLD labels)
- Bottom row: "Dashboard | Site | Security | Automation | Monitoring | Tools" (6 entries, NEW labels)

**Root cause:** v3.8.0's `admin_menu` callback registered 12 WP submenu entries (from `sn_admin_pages()`) to "preserve legacy deep-link shortcuts in the WP left sidebar." In vanilla wp-admin this works as intended (sidebar entries are visually distinct from the in-page tab row). But the user runs WordPress/desktop-mode, which flips the WP left sidebar into a horizontal top nav — making the 12 legacy entries duplicate the 6 in-page tabs.

**Lesson missed:** memory entry `feedback_desktop_mode_blocks_browser_automation.md` already documents that desktop-mode does unexpected things with admin UI. v3.8.0 brainstorm didn't apply this lesson when deciding to keep 12 sidebar entries.

### Issue 2: Long scrolling per tab

**Symptom:** clicking the Site tab loads a single long page with 5 sub-sections stacked vertically (Identity + Social + OG + SEO Copy + Cloudflare). User feedback: *"I don't like the massive scrolls per tab now... There should be a way to fix it. Maybe sub-tabs?"*

**Root cause:** v3.8.0 inherited the internal-TOC pattern from the existing Identity tab (which had 4 sub-sections and was already long). But Identity was the EXCEPTION — most other tabs in the v3.7.x flat IA were short single-content. By forcing TOC pattern across all 5 multi-section tabs in v3.8.0, the average per-page length got WORSE for previously-short tabs.

**Why "sub-tabs" is the right pattern:** the user proposed sub-tabs explicitly. Each sub-tab renders only its own content, so vertical length is bounded by ONE section's size instead of summed across N sections. URL-driven means each sub-tab is bookmarkable.

### Issue 3: Plugin version cache stale

**Symptom:** dashboard widget shows "PLUGIN 3.7.6 • v3.8.0 available" though `git describe` on production confirms current checkout is v3.8.0 and the file's Version header reads `Version: 3.8.0`.

**Root cause:** WP's `get_plugin_data()` caches plugin metadata in the `plugins` option-like cache. The SN purge filter (theme's `inc/template-maintenance.php`) invalidates the THEMES cache (`wp_clean_themes_cache()`) but NOT the plugins cache. SSH-based plugin deploys update the file on disk but leave WP's cached metadata stale until something else triggers a refresh (visiting `wp-admin/plugins.php`, etc.).

**Symmetrical bug:** the same issue affects theme deploys for the `update_themes` transient if the deploy doesn't explicitly delete it. The fix should be symmetric across both.

## Approach chosen

**Three coordinated fixes, two atomic ships:**

| Fix | Where | Ships as |
|---|---|---|
| Sub-tabs (hybrid + TOC for Identity bundle) | Plugin | v3.8.1 |
| WP submenu reduction (12 → 6) | Plugin | v3.8.1 |
| Cache invalidation (plugin metadata) | Theme | v9.1.5 |

**Wave 1 ships theme v9.1.5 FIRST,** so that plugin v3.8.1's post-deploy verification can validate the cache fix (gate G12). Reverse order would fail G12 because the cache invalidation isn't live yet.

Alternatives considered + rejected:
- **Sub-tabs that also split Identity** (4 separate sub-tabs with 4 saves) — breaks the one-form-one-save UX
- **Accordion** (collapsible sections, no sub-tabs) — less discoverable; still scrolls when multiple expand
- **Hide 12 sidebar entries in desktop-mode via CSS** — couples plugin behavior to desktop-mode-specific selectors; hackier
- **Bundle the cache fix into the plugin** (e.g., self-invalidate on activation hook) — wrong layer; the theme owns cache orchestration via `sn_purge_all_caches`

## Section 1 — Sub-tab IA + naming + URL pattern

```
URL pattern: ?page=sn-theme-options&tab=<top>&sub=<sub-tab>
```

### Sub-tab structure

| Top tab | Sub-tabs (display order; first = default) | Notes |
|---|---|---|
| **Dashboard** | — (no sub-tabs; landing page) | unchanged from v3.8.0 |
| **Site** | **Identity & SEO** \| Cloudflare | "Identity & SEO" contains 4 internal TOC anchors (Identity / Social / Open Graph / SEO Copy) — preserves the one-form-one-save UX. Cloudflare is a single sub-tab with its own form. |
| **Security** | **Login** | Only 1 sub-tab at v3.8.1. Sub-tab nav HIDDEN when only 1 sub-tab present (renders as if no sub-tabs exist). Audit log addition in a future ship will reveal the nav. |
| **Automation** | **Webhooks** \| Cron | Two independent module-owned sub-tabs. |
| **Monitoring** | **Insights** \| Health \| Plausible \| RSS | Four independent module-owned sub-tabs. |
| **Tools** | **Reading Time** \| Links | Two independent sub-tabs. |

**Total sub-tabs at v3.8.1: 11** across 5 multi-section top tabs (Dashboard has 0).

### Naming rationale

- **"Identity & SEO"** (not just "Identity") because the sub-tab CONTAINS 4 internal sections, one of which is also called "Identity." The "& SEO" suffix distinguishes the GROUP from the inner section, and accurately describes that the bundle includes the SEO Copy section too.
- All other sub-tab labels match their existing section labels (no rename).

### URL backward compatibility

ALL v3.7.x AND v3.8.0 URLs continue to work via chained redirects. The redirect map (`sn_admin_legacy_redirect_map()`) extends to handle the v3.8.0 → v3.8.1 mapping:

| Legacy URL | Canonical v3.8.1 URL |
|---|---|
| `?tab=identity` (v3.7.x) | `?tab=site&sub=identity-and-seo#sn-sec-identity` (via chained redirect: v3.7.x → v3.8.0 → v3.8.1) |
| `?tab=site#sn-sec-identity` (v3.8.0) | `?tab=site&sub=identity-and-seo#sn-sec-identity` |
| `?tab=site#sn-sec-cloudflare` (v3.8.0) | `?tab=site&sub=cloudflare` |
| `?tab=security#sn-sec-login` (v3.8.0) | `?tab=security&sub=login` |
| `?tab=automation#sn-sec-webhooks` (v3.8.0) | `?tab=automation&sub=webhooks` |
| `?tab=automation#sn-sec-cron` (v3.8.0) | `?tab=automation&sub=cron` |
| `?tab=monitoring#sn-sec-insights` (v3.8.0) | `?tab=monitoring&sub=insights` |
| `?tab=monitoring#sn-sec-health` (v3.8.0) | `?tab=monitoring&sub=health` |
| `?tab=monitoring#sn-sec-plausible` (v3.8.0) | `?tab=monitoring&sub=plausible` |
| `?tab=monitoring#sn-sec-rss` (v3.8.0) | `?tab=monitoring&sub=rss` |
| `?tab=tools#sn-sec-reading-time` (v3.8.0) | `?tab=tools&sub=reading-time` |
| `?tab=tools#sn-sec-links` (v3.8.0) | `?tab=tools&sub=links` |

The legacy URL fragment (`#sn-sec-…`) is preserved through both redirects via raw `header('Location: …', true, 301)` (same technique as v3.8.0).

### Sub-tab default behavior

When user visits a top tab without an explicit `&sub=…`, the FIRST sub-tab in display order renders:
- `?tab=site` → `?tab=site&sub=identity-and-seo`
- `?tab=automation` → `?tab=automation&sub=webhooks`
- `?tab=monitoring` → `?tab=monitoring&sub=insights`
- `?tab=tools` → `?tab=tools&sub=reading-time`
- `?tab=security` → `?tab=security&sub=login` (only option)

The redirect to add the explicit `&sub=` is OPTIONAL — the dispatch can also just default-render the first sub-tab without changing the URL. Implementation choice: do the redirect (canonical URL principle: every page has one URL, not many).

### Sub-tab nav visual

```
Top tabs:   Dashboard │ Site │ Security │ Automation │ Monitoring │ Tools
                              ────────
Sub-tabs:   Identity & SEO  |  Cloudflare           ← only visible when count > 1
            ───────────────
Content:    [render of current sub-tab only]
```

Sub-tab nav is visually subordinate to top tabs (smaller text, different separator). New CSS class `.sn-sub-tabs` defined in `assets/admin.css`. Hidden via `display: none` (or simply not rendered server-side) when only 1 sub-tab exists for the active top tab.

## Section 2 — WP submenu reduction + plugin cache fix + visual review

### 2a. WP submenu reduction (12 → 6 entries)

**Change in `admin_menu` callback:** stop iterating `sn_admin_pages()` (12 legacy entries); iterate `sn_admin_top_tabs()` (6 new entries).

```php
// BEFORE (v3.8.0):
foreach ( sn_admin_pages() as $page ) {   // 12 entries
    $hooks[] = add_submenu_page( ... );
}

// AFTER (v3.8.1):
foreach ( sn_admin_top_tabs() as $page ) {  // 6 entries
    $hooks[] = add_submenu_page( ... );
}
```

`sn_admin_pages()` becomes dead code from the registration side but stays defined as a reference (its 12 entries remain the source for the legacy URL redirect map). Mark for deprecation-then-delete in v3.9.x (when patch cap rolls).

**Outcome:** WP sidebar in vanilla wp-admin shows 6 entries. Desktop-mode renders the same 6 entries as horizontal top nav — no duplication with in-page tabs.

**Legacy URL deep-jumps:** previously, users could click "Identity" in the WP sidebar and land directly on the Identity tab. After v3.8.1, the sidebar shows only "Site" — clicking it lands on Site → Identity & SEO sub-tab (the default sub-tab). One extra mental step ("Identity is under Site") but discoverable via the in-page sub-tab nav.

### 2b. Plugin cache fix (theme v9.1.5)

**Two lines added to `inc/template-maintenance.php`** in the `sn_purge_all_caches()` function's `object_cache` branch:

```php
// Before (lines 73-77):
if ( $args['object_cache'] ) {
    wp_cache_flush();
    delete_site_transient( 'update_themes' );
    wp_clean_themes_cache();
}

// After:
if ( $args['object_cache'] ) {
    wp_cache_flush();
    delete_site_transient( 'update_themes' );
    delete_site_transient( 'update_plugins' );   // NEW v9.1.5
    wp_clean_themes_cache();
    wp_clean_plugins_cache();                     // NEW v9.1.5
}
```

**Cross-cutting benefit:** the same fix also helps theme deploys (the `update_themes` transient case was already handled; the new code makes the plugin-side symmetric).

**Ships as theme v9.1.5.** Patch cap is 4/7 used in v9.1.x (v9.1.1 through v9.1.4); v9.1.5 makes it 5/7. Two patches remain before rollover to v9.2.0.

### 2c. Visual review (CSS spacing audit during implementation)

User reported "lots of issues with space" without specific call-outs. Approach:
1. After sub-tabs refactor lands locally, walk through each top tab + sub-tab and identify spacing inconsistencies (padding, margins, alignment)
2. Fix obvious ones inline (`assets/admin.css` tweaks) in same v3.8.1 commit
3. Anything requiring real design decisions (typography, color, layout pattern changes) gets surfaced to user with screenshot — NOT silently changed
4. If audit surfaces issues too big for a refinement, defer to v3.8.2

Bounded LOC estimate: ~30 LOC additional CSS for spacing tweaks. Could be less; could be slightly more.
