## Task 1 — Multi-event webhooks (post.updated / post.unpublished / post.deleted)
**Files:** `inc/webhooks.php` (logic), `inc/webhooks-admin.php` (per-webhook events checkboxes). **Test:** extend `tests/webhooks.php`.
**Change:**
1. **Event registry:** `sn_webhook_events()` → ordered assoc `['post.published'=>'Published (first publish)','post.updated'=>'Updated (re-saved while published)','post.unpublished'=>'Unpublished (publish → draft/pending/private)','post.deleted'=>'Deleted (trashed or permanently removed)']`. `sn_webhook_event_enabled($wh,$event)` → true for `post.published` when `$wh['events']` unset (back-compat), else `in_array($event,(array)($wh['events']??[]),true)`.
2. **Payload builder:** generalize to `sn_webhook_build_payload($event,$post_id,$delivery_id,$snapshot=array())`; keep `sn_webhook_build_post_published_payload` as a delegating shim. publish/updated resolve via `get_post()` (require `publish`); **unpublish/deleted snapshot title/slug/url/type/author at TRIGGER time** (the post may be gone by dispatch) and build from `$snapshot`. `event` JSON field + `X-SN-Event` header = `$event`.
3. **Enqueue/dispatch:** widen `sn_webhook_enqueue($webhook_id, $event, $post_id, $snapshot=array(), $attempt=1, $delivery_id=null)`; thread `$event`+`$snapshot` through the cron args; `add_action(SN_WEBHOOK_DISPATCH_HOOK,'sn_webhook_dispatch',10,6)`. In `sn_webhook_dispatch()` select builder by `$event`, set `X-SN-Event`, keep sign/retry/log byte-identical. **Defensive defaults** (`$event='post.published'`, `$snapshot=[]`) so in-flight OLD 4-arg events from before the deploy still dispatch (install-hooks-cannot-self-observe).
4. **Triggers:** branch `transition_post_status`: non-publish→publish & old≠publish → `post.published`; old=publish & new=publish → `post.updated`; old=publish & new∈{draft,pending,private} → `post.unpublished` (snapshot). `add_action('before_delete_post','sn_webhook_on_delete',10,2)` + trash via the `trash` branch → `post.deleted` (treat trashing-a-published-post as `post.deleted` only, NOT also unpublished — avoid double-fire). Apply the `sn_webhook_post_types` gate in EVERY branch. Skip revisions/auto-drafts.
5. **Admin UI:** `events[]` checkboxes per webhook (pre-checked from `$wh['events']` or `post.published` default); sanitize in `sn_webhook_create`/`sn_webhook_update`: `$entry['events']=array_values(array_intersect(array_keys(sn_webhook_events()),(array)($input['events']??[]))); if(empty($entry['events']))$entry['events']=['post.published'];`.
**Test (extend tests/webhooks.php):** registry returns 4 keys in order; event_enabled back-compat + explicit + rejects-unlisted; create/update sanitizer (`['post.updated','bogus']`→`['post.updated']`; empty→`['post.published']`); `build_payload('post.updated',...)` emits `event==='post.updated'`; snapshot path builds title/url for a non-publish post; **fan-out:** `events=>['post.updated']` → 0 enqueues on first publish, 1 on publish→publish; default(unset) → 1 on first publish, 0 on update (assert via the scheduled-events count + the `$event` arg). Update existing T8 for the widened arg order.
**Commit:** `feat(webhooks): opt-in post.updated/unpublished/deleted events over the existing pipeline`
**SETTINGS:** optional `events` key per `sn_webhooks` entry; default publish-only; migration-free.

## Task 3 — Privacy exporter + eraser (login-audit usernames)
**File:** NEW `inc/privacy-exporters.php` (require after `inc/audit-log.php`). **Test:** NEW `tests/privacy-exporters.php` (model on `tests/audit-retention-bounds.php`).

**Change:** shared matcher `sn_privacy_match_login_rows($blob,$user_login)` → `[$matched,$remaining]`.

- **Eraser:** `add_filter('wp_privacy_personal_data_erasers',…)` ⇒ `sn_privacy_erase_login_audit($email,$page=1)`: resolve user; filter out matched rows; `update_option(SN_AUDIT_OPTION,...)` if any removed; return `['items_removed'=>bool,'items_retained'=>false,'messages'=>[...],'done'=>true]`.
- Docblock the orphaned-deleted-user limitation (rows store user_login; a deleted WP user can't be resolved from email → those rows age out via the 90d prune only).
**Test:** seed 3 rows (2 'juan', 1 'someoneelse'); filters add the key; exporter(juan)→2 items; exporter(unknown)→empty+done; eraser(juan)→removed + 1 remaining; eraser(unknown)→no-op; matcher splits correctly.
**Commit:** `feat(privacy): personal-data exporter + eraser for login-audit usernames`
