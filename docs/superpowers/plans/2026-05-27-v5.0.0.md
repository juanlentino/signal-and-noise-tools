# Plugin v5.0.0 Implementation Plan — Paired Major (TENTATIVE — refine at BC)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **TENTATIVE STATUS:** This plan is written ahead of the v5.0.0 BC for visibility. Some sections — particularly Task 6 (drop pre-7.0 compat code) — depend on the LIVE state of the codebase after v4.6.0 ships + UATs. At v5.0.0 BC time (after v4.6.x gates stable), this plan must be refreshed against the actual code. Sections marked **[BC-REFINE]** explicitly defer detail to BC time.

**Goal:** Ship the breaking changes the v4.6.0 prep minor announced — HARD-raise WP 7.0 baseline, remove the legacy REST routes (4 from v2.5.0 + 6 from v4.6.0), flip JS clients to Ability-only, remove the orphan option, drop pre-7.0 compat code, promote `@deprecated` PHPdoc to `_deprecated_function()` runtime warnings.

**Architecture:** Mostly removals (the typical major shape — subtract code, add minimal new code). New code is concentrated in the `_deprecated_function()` runtime warnings (~10 calls) and the upgrade-path option-cleanup. Pre-7.0 compat code drop is audit-then-edit work that depends on what's in the codebase at v5.0.0 BC time.

**Tech Stack:** PHP 8.0+, WordPress 7.0+ (HARD requirement), Abilities API, no new JS, no new CSS.

**Reference spec:** [`docs/superpowers/specs/2026-05-27-v5-and-v10-paired-cycle-design.md`](https://github.com/juanlentino/signal-and-noise/blob/main/docs/superpowers/specs/2026-05-27-v5-and-v10-paired-cycle-design.md) — §5 v5.0.0 major scope.

**Sequencing prerequisite (HARD GATE):**
1. Plugin v4.6.0 shipped + UATed stable (all v4.6.x patches gated)
2. Theme v9.6.0 shipped + UATed stable (all v9.6.x patches gated)
3. v5.0.0 BC convened, this plan refreshed against live state

### Task 7: PROMOTE `@deprecated` PHPdoc → `_deprecated_function()` runtime warnings

**Files:** Functions removed in Tasks 2 + 3 (10 total) need REMOVAL — they're gone. But if the spec intent is to add a `_deprecated_function()` call as a HEADSTONE for any leftover callers... actually, since the functions are DELETED in Tasks 2 + 3, there's nothing to attach `_deprecated_function()` to.

**Clarification needed at BC time:** the spec §5 row "PROMOTE @deprecated PHPdoc → _deprecated_function() runtime warnings" might refer to OTHER non-Ability surface that's getting deprecated-but-not-removed in v5.0.0. The v4.6.0 plan only adds `@deprecated since 4.6.0` to the 10 REST handlers, which v5.0.0 REMOVES. So there's no leftover surface to runtime-warn.

**Action at BC time:** identify ANY non-Ability surface in the plugin that should be deprecated in v5.0.0 with REMOVAL scheduled for v6.0.0. Likely candidates:
- `sn_admin_pages()` (already `@deprecated 4.2.0` per scope audit §6 row P3 — could promote to runtime warning here).
- Pure-impl functions that are now only called from Ability execute_callbacks and have no other consumers (audit at BC).

**Estimated LOC:** ~80 (assumes 5–8 functions get `_deprecated_function()` calls added).
