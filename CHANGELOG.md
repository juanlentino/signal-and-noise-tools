# Changelog

All notable changes to Signal & Noise Tools are documented here.

This file holds two things only: **`## [Unreleased]`**, the working log that
accumulates across pull requests, and the **current release**. Everything older
lives in [docs/changelog/](docs/changelog/).

A pull request does not bump `Version` and does not tag — it closes an issue and
adds a bullet below. A release is a separate, deliberate act:
`tools/cut-release.sh`.

## [Unreleased]

### Added
- **Cadence warnings on the SN Queue card and on Connections › Scheduled (queue calendar phase 2, item 1).** The owner's rule: scheduled notes under 2 days apart are a cluster, notes over 7 days apart leave a gap. Days are counted in the site timezone, starting from the newest published note. The card lists each one in words, up to three, then "+N more in Scheduled". Examples: "Cluster: 2 notes Oct 20 and Oct 21", "Gap: no note Oct 25 to Nov 4 (12 days between notes)". Every line links to Scheduled, and a gap line keeps its Planned button. Connections › Scheduled has a new open Cadence box that says the same sentences under the rule, on both the native window and the classic page. When there is nothing to report it says "No clusters or gaps in the scheduled notes." Deliberate gaps come from the existing setting the Planned button writes (`sn_content_queue_planned_gaps`), never from code. The holiday pause (empty days Dec 20, 2026 to Jan 3, 2027, between the Dec 19 and Jan 4 notes) is already stored there, so it raises nothing. Any planned range that contains a gap now covers it. Changed: the card's single gap line (the first hole by the publishing-cadence flag's statistical threshold) is replaced by these lines. The `gap` field stays in the content-queue reading for other readers, and the card paints it only for an older payload. Today's live queue (notes every 2 to 4 days, then the holiday pause) shows no warning. Read-only: titles and dates only. Pinned by tests/abilities-content-queue.php, tests/desktop-status-resilience.cjs and the new tests/queue-cadence-twins.php.

## [2026.10.8] - 2026-10-12 — field vitals, the bot split, and pages that say when they changed

### Fixed
- **The fetch-as-markdown agent skill names the note's `.md` URL.** It said there is no `.md` suffix to append; with sn-rights-signals serving `/notes/<slug>.md` that is no longer true, so it now says a note's Markdown is also at its own URL, linked from the note page, and that other pages answer `.md` with a 404. The skill's digest in the agent-skills index changes with it. Merge after the Worker route deploys, or the skill promises a URL that 404s.
- **Returning readers get the current page, not a weeks-old copy (live-site audit, 2026-10-12, P1-1).** A page's Last-Modified was the post's own edit date, so after a deploy Cloudflare kept answering a returning browser's "has it changed?" with 304 and the browser kept its old copy (measured: /about/ and a provenance note rendering stylesheets from 22.0.0 and 20.6.0, /stats/ showing an older 30-day window). Last-Modified is now the later of the post's edit and the site's last purge (the plugin records the time when every deploy, Styles save or manual purge starts, before any cache is cleared and before the chain re-warms the home, notes and provenance pages, so a re-warmed page carries this purge's time and not the previous one), and the pages whose numbers are computed (/stats/ and the maturity pages, including the roadmap) send no Last-Modified at all, so they never 304 on stale numbers. Copies already cached carry the old date: one Cloudflare purge after this deploys clears them. Pinned by tests/seo-live-audit.php.
- **The RSS feed says it changed when a scheduled note goes live (P1-2).** The feed's lastBuildDate, Last-Modified and ETag came from WordPress's build date, which reads edit dates only, and a scheduled note keeps the date of its last edit (measured: a note edited Oct 1 and published Oct 11 left /feed/ dated Oct 6, so a reader polling since then got 304 and never saw it). The plugin now dates every feed by its newest publish or edit, never later than now (a note published early keeps its future scheduled date), through a get_feed_build_date filter in inc/seo-validators.php; comment feeds keep WordPress's date. Pinned by tests/seo-live-audit.php with that note's dates.
- **/notes/tags/ and every /tag/ page carry a social card and structured data (P2-5).** They had a canonical and a description but no Open Graph, Twitter card or JSON-LD. They now get og:title (the page's own title), og:description, og:url, og:type website, and a CollectionPage with a Home, Notes, page breadcrumb (the tag's name as written, "AI & music", not "AI &#038; music"), through the same gate as the other pages. A tag with no written description still gets none. Pinned by tests/seo-live-audit.php.
- **/stats/ Most read names the notes index "Notes", not "/notes/" (P2-7).** The posts page is the one page WordPress's URL lookup does not resolve. Pinned by tests/public-stats.php. The audit's 520 visits against 337 pageviews was a stale copy of the page from before Oct 4 (it still said "reader-days"); /stats/ already counts visits as sessions that saw a page (#1890), and today reads 381 views and 235 visits. Public figure changed: none.
- **The resume seed counts tracks, not releases (owner's call, 2026-10-12: the 110 figure counts tracks).** The seed that fills a fresh install's resume now reads "Tracks since 2022" on the stat and "roughly 110 tracks since 2022" in the first bullet, matching the live /resume, the /music bridge line and the Note "Before you opt in to an AI music platform" (corrected the same day). Changed: the stat label "Releases since 2022" becomes "Tracks since 2022"; the number stays 110. Only a fresh install reads the seed. Pinned by tests/resume-sync-engine.php (the seed counts tracks and never releases), with tests/os-leaf-content-resume.php and tests/resume-admin-form.php following the new wording.

### Changed
- **The S&N apps wear their own icons everywhere, the phone included (owner's call, 2026-10-12: "The apps icons should be part of the integration, not theme").** S&N Home (the faders), Signal & Noise (the pulse) and S&N Analytics (the level meter) now register their icons themselves, on the window, the dock and S&N Home's desktop icon, so they show with any desktop theme or none, and on the phone's home grid and tab bar, which had shown the stock shield, megaphone and chart because the phone ignores theme icon slots. The icons are the glyph alone on a transparent background (white strokes, one red mark each), so OpenStation's own tile, dock and phone glass shows behind them; a thin dark edge keeps them legible on the Legacy theme's light title bar. The Signal through noise theme no longer carries icons (it is color, type and wallpaper; its version goes to 1.1.0). Changed: the charcoal tile behind each icon is gone. Known: the dock's submenu head paints any drawn icon in one color, so there the red mark shows white. Pinned by tests/app-icons.php (each registration names its file, no stock dashicon; each SVG has a title, no script or external reference, no charcoal tile, exactly one red mark, fixed colors with a dark edge), the five app suites (the registered icon is the plugin asset URL, versioned with ?ver= so a redraw is not served stale) and tests/openstation-desktop-theme.php (no icons key, no icon files under the theme).
- **The /stats/ and maturity pages carry no em dashes (owner's call, 2026-10-12).** Every em dash in the copy the plugin paints on /stats/, the maturity hub, the ML and Proof of origin pages and the roadmap board (70 items) is now a colon, comma, semicolon or parentheses; the canonical-JSON line's spaced hyphens became parentheses. Wording is otherwise unchanged, except two roadmap items reworded for sense once the dashes were gone (Traffic rhythm flags, Coverage history). Pinned by tests/public-copy-no-em-dash.php (every string literal in those painters).
- **/stats/ no longer says there is "nothing to consent to" (owner's call).** The Privacy Policy says the site sets no cookies of its own while an embedded Spotify player may set its own, so the sentence now reads "No consent banner: the measurement sets no cookies on readers and uses no local storage." ("on readers": the plugin does set one cookie, on the owner's own signed-in devices, to leave them out of the counts.) Pinned by tests/public-copy-no-em-dash.php.

### Added
- **Field Core Web Vitals are a read (theme audit idea 4, 2026-10-12).** `sn-metrics` gains an `analytics_vitals` section (ability `signal-noise/get-analytics-vitals`): for LCP, INP and CLS over the chosen range, the 75th percentile and the good, needs improvement and poor shares against Google's thresholds, site-wide, per device (mobile, desktop, unknown) and for the top pages by views (`limit`, default 25, max 50). Each figure carries its sample count; a cell with no measurements reads null, never 0, and one under 30 measurements is labeled `small_sample`. `analytics_query` still refuses these metrics, now on purpose: its rollups are daily sums and a p75 is not one (the description says so). The Engagement view, in S&N Analytics and on the classic Analytics page alike, adds one table under the three field bands, "Core Web Vitals at p75, by device", with the same rows and the same note; it is read only when the bands have measurements, and it reads the devices alone, so a failed read of the top pages can no longer blank it. LCP and INP are read in 10 ms steps, rounded up so each measurement keeps its band (p75 reads under 10 ms high; CLS is read as stored), which keeps a month of whole-millisecond values well under the row cap. A top page whose address the read cannot ask about safely is left out of the list rather than shown as not measured, and a top-pages lookup that failed in the database makes the read fail rather than list no pages. Local door only: the remote verdict records it as a new payload that earns a twin once its shape settles, so the remote contract stays at 16. Pinned by tests/analytics-vitals.php (the SQL shape and its 10 ms steps, the path allowlist anchored at the very end, the devices-only read surviving a failed path read, a refused path dropped, a failed top-pages lookup, bands and thresholds, unknown is null, the small-sample label, a failed or capped read is no answer, both twins from one copy and one read) and tests/analytics-view-engagement.php (the table only when the bands have data).
- **The north star's calibration splits by the bot-signal score (theme audit idea 5).** `signal-noise/north-star` gains `calibration.by_score`: the same 28 days of core-page visitor-days, per device and at every scroll and dwell floor, in three cohorts side by side: presumed human (the beacon's signals scored under the threshold), likely automated (scored at it) and not scored (the visitor-day carried no signals, as every day before the beacon sent them). Nothing is subtracted, the three add up to the whole calibration, and the basis is inferred. When the signal rows cannot be read whole, the cohorts are null with a reason, never everyone not scored. Pinned by tests/north-star-score-split.php (not scored is never presumed human, bits merge across a visitor-day's rows, the sum pin at every scroll and dwell floor, the failed and capped reads).
