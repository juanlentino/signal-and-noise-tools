# Changelog

All notable changes to Signal & Noise Tools are documented here.

This file holds two things only: **`## [Unreleased]`**, the working log that
accumulates across pull requests, and the **current release**. Everything older
lives in [docs/changelog/](docs/changelog/).

A pull request does not bump `Version` and does not tag — it closes an issue and
adds a bullet below. A release is a separate, deliberate act:
`tools/cut-release.sh`.

## [2026.10.4] - 2026-10-12 — the 2026.10.3 audit fixed: nothing typed is lost, focus and contrast pass, forecasts that measure

### Changed
- **The forecaster uses two models, each where it measures better** (owner: "Apply the models where they are useful and precise"). A rolling-origin backtest on this site's real daily series (152 human days and 76 crawler days, 7 days ahead, 833 and 301 checks) scored Holt alone worse than "every day equals the last" on every series (skill -0.13 to -0.28; its own gate hid it on 79 to 96% of days), and the median of the last 14 days +0.18 to +0.30, level with Google's TimesFM 2.5 on the same folds. Averaging the two was worse than the median everywhere. Picking per series works: every forecast now backtests both and uses Holt only when its skill beats the median's by 0.1, which never scored below the median on the real series and takes the steady climbs and falls a median lags (Holt +0.56 where the median scored -1.5). Today every real series picks the median. The band is the 10th to 90th percentile of the chosen model's past misses, and how often it held is measured out of sample (it never grades itself); a band not yet measured says so and reads low confidence. The backtest and the pick are pinned on the real series.
  - **Figures that change:** a median forecast carries no up or down arrow (it states a level; the Theil-Sen trend tier still says which way), and a falling forecast leads the chips only when Holt carries it; a Holt pick keeps its arrow; the band is 80%, not the old approximate 95%, and confidence is judged against that 80% ("high" when it held within 5 points of it over at least 50 checks; on today's series human views reads medium at 72%); the views card prints the band's own ends ("5 to 39") at high confidence, never a ±%, because the band is not symmetric; each label names its model and how many checks its band held on; the gate scores more folds (history up to 90 days, training from 14); the forecast history is 90 days, not 30 (Insights) and 60 (the views card), so both read the same series the same way. The reader-anomalies watch restarts its settle clock once, since forecast signals change shape.
  - The public /maturity page's Predictive row says "backtested median and Holt forecasts, each used where it measures better", as do Insights' methods notes and the reader-anomalies MCP description.

### Fixed
- **Nothing you did is lost or misstated any more: the second batch from the 2026.10.3 audit.** Each of these lost data or told the owner something untrue.
  - **Typed text survives a repaint.** The window puts every field the reader is not in back to the stored value on each repaint, so text typed into Workflow's page fields vanished when a list's Edit opened, as did anything typed before a watch tick or a refused save. The host now keeps what was typed while the server still stores the value it was typed over, and lets it go when its form's save takes (an add form repaints blank and stays blank), when Cancel closes the editor it was in, or when the window shows another leaf. Drafts are kept per form, so an editor opening above an add form leaves the add form alone; picks in a select are kept; password fields never are.
  - **A refused save stays on the page.** A refusal (an expired security token, a page the window does not own) was only a 3.5-second toast; it is now also the window's error notice, and that notice is what tells the host to keep the typed values.
  - **Dismissing one scan candidate keeps the rest.** Pattern adoption, block migrations and corpus integrity each deleted the whole cached scan on a dismiss, so the page fell back to "no scan yet". Now only that candidate leaves the list; its count and the posts-affected count follow, and the cache keeps its expiry.
  - **The RSS tracker's Reset keeps the collector endpoint.** Reset deleted the whole settings option, including the endpoint set on Measurement › Analytics. Both confirms now say what Reset and Purge do.
  - **A rotated credential is not judged by its old verdict.** Saving a credential now clears the stored verdict for that row (and, for the site secret, for every row derived from it), so Credentials stops calling a new key bad (or good) on the old one's say.
  - **IndexNow says when a submission was refused.** A 4xx or a dead connection painted "Active" with the code buried; the status now names the refusal, and the last-submission line reads "2 hours ago: HTTP 200, 12 URLs" (or "no HTTP response").
  - **Zenodo no longer reports "0 published, 0 failed, of 0"** when no manual pass has run.
  - **A Now or Uses card left half filled says so.** The save used to answer "parses to zero sections"; it now says a card has a label with no items (or the reverse) and to fill or clear it.
