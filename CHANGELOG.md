# Changelog

All notable changes to Signal & Noise Tools are documented here.

This file holds two things only: **`## [Unreleased]`**, the working log that
accumulates across pull requests, and the **current release**. Everything older
lives in [docs/changelog/](docs/changelog/).

A pull request does not bump `Version` and does not tag — it closes an issue and
adds a bullet below. A release is a separate, deliberate act:
`tools/cut-release.sh`.

## [Unreleased]

### Changed
- **Each résumé PDF prints and links its own lane's address.** The contact line printed the bare host ("juanlentino.com") in both PDFs; the music PDF now prints and links `juanlentino.com/resume` and the operations PDF `juanlentino.com/resume/?lane=operations`, built from `home_url()` (a filled Website field still wins in the music PDF and the Spanish CV, now printed as it links, path included; the operations PDF always prints its own address). The operations Download, the format list and llms.txt link the operations PDF with `?v=<first 8 of its SHA-256>`, as the music Download does (`sn_resume_ops_pdf_link()`, from the file name the route serves, so a rename whose build failed never links a 404), and a phone withdrawal purges that address too. Measured at two Letter pages each: the seed fixture renders music 2 and operations 2; with the live header strings the operations contact line wraps to a second line, and the live operations PDF's second page has 487 pt free, so it stays at 2. `tests/resume-ops-pdf-build.php` (+8), `tests/resume-pdf-generate.php` (+5).

### Fixed
- **A CI flake in `tests/mcp-telemetry-read.php`** (62/63 on the 2026.11.8 cut, green on rerun). Four checks rebuilt a timestamp, to the second, with `$ago()` after the fixture had built it, so a second ticking between the two failed them. They now compare the fixture's own value. A forced 1-second pause reproduces CI's 62/63 on the old test and passes the new one.
- **A résumé PDF with a page the check could not read is no longer passed as clean.** The built-in reader counts the file's pages and reads each one's content stream; a page it could not read flags "only N of M pages could be read", a stream that would not inflate flags "N streams could not be inflated", and an Info dictionary it could not find flags "the metadata could not be read" (it was skipped, so a phone there went unchecked). Before, page one alone was over the 1,000-character floor and the rest went unseen. The flags moved to `inc/resume-pdf/check.php`. `tests/resume-pdf-text-check.php` (+3). The page count is at least Dompdf's own, so a page the reader does not find as a page is flagged as unread too. `tests/resume-pdf-text-check.php` (+1).
- **An indirect `/Length 99 0 R` is no longer read as a length of 9.** The pattern backtracked to the first digit; it now takes the whole number, so the reader falls back to the `endstream` marker as intended. `tests/resume-pdf-text-check.php` (+1).
- **Three numbers on three lines are no longer a phone number.** The phone pattern let a line break separate its groups, so a stats row ("250", "300", "2024") flagged; the groups must now share a line, and a no-break space counts as a space. `tests/resume-pdf-text-check.php` (+2).
- **An operations PDF withdrawn for a phone number is purged at the edge.** Withdrawal deleted the stored file and its facts but skipped the Cloudflare purge, so the edge could keep serving the last copy. `tests/resume-ops-pdf-build.php` (new, 17), which runs `sn_resume_ops_pdf_build()` and `sn_resume_ops_pdf_generate()` through Dompdf and the check: before it, disabling the phone withdrawal or the noindex check failed no suite. Removing the operations settings now purges the old address too. `tests/resume-ops-pdf-build.php` (+1).
- **The operations PDF's bytes are read back after they are stored.** The write's result was never checked, so a file that failed to store (a large value can) was reported as generated while the old one was served. Generate now compares the stored bytes with the rendered ones (not `update_option()`'s return, which is false for an unchanged value too) and records a failure; `sn_resume_ops_pdf_live()` also requires a stored PDF, not only its facts.
- **Removing the operations résumé's settings removes its PDF.** Generate left the old file and its facts in place, still linked. It now deletes both.
- **An operations résumé with no experience and no publications is not built.** The last good file stays, and the PDF box says why.
- **The PDF box says what happened to the operations PDF.** After a failed Generate it said "the last Generate failed" and also "set up; Generate builds it"; it now says whether the earlier file is still the one served. A file with a flag other than a phone says it stays published, since only a phone number withdraws it (the `sn_resume_ops_pdf_live()` docblock said any failed check did). A draft that holds the setup reads "set up in the draft" rather than "not set up yet", and the generated line reads "linked from the Operations lane on /resume". The box lines moved to `inc/resume-pdf/operations-box.php`; `sn_resume_ops_config()` names the published operations layout in one place. After a music PDF that failed (on Generate, Publish or Revert) it shows that failure above the old check, and marks an operations PDF built before it "Not rebuilt since".
- **A renderer that throws is reported, not a fatal.** `sn_resume_pdf_render()` had no try/catch, so an exception inside Dompdf ended the admin request with a white screen; it now returns an error ("The PDF renderer failed: …") that every caller already reports: Generate, the operations and Spanish PDFs and the draft preview. `tests/resume-pdf-generate.php` (new, 10), which runs Generate for real through a shared harness (`tests/lib/resume-pdf-harness.php`). Its message is now written to the PHP error log, and a failed music or Spanish CV build is stored with the PDF's facts (`error`, `error_at`) as the operations PDF's already was; the next good build clears it. The PDF box shows it, so the Generate flash no longer guesses at a cause ("Check that uploads is writable…") and points at the box; the draft preview, which stores nothing, gets its own flash. A first Generate that fails now leaves a stored option, so Publish retries the PDF. `tests/resume-pdf-generate.php` (+10).
- **Generate, Publish and Revert say when the operations PDF failed.** They reported success whenever the music PDF built, whatever happened to the operations one. Generate now answers "Music PDF generated … The operations PDF was not built; the PDF box says why", and Publish and Revert report a PDF that could not be rebuilt, the box saying which.
- **A save can no longer leave the public résumé empty.** The guard refused a document with no experience and no publications, but read the stored document, so one whose every entry was marked "Operations only" was saved and the music résumé (the page and its PDF) showed none. The guard now reads the music view; the refusal flash says rows marked "Operations only" do not count. `tests/resume-variants-edges.php` (new, 17). A stored résumé the tighter rule refuses falls back to the seed as before, now with a line in the PHP error log.
- **The operations settings are kept the way the form posts them.** Section names were matched case-sensitively, so "Summary" was dropped, and the block was kept only with a headline, a summary or sections, so one holding only a subhead, location, links, order or file name vanished on save. Names now match in any case, and any field set keeps the block. A block with only the "Earlier career" box or a file name now counts as set up, so the operations lane and PDF appear for it. The setup's first run is now decided by the headline, summary and sections: a block holding only the "Earlier career" box or a file name got none of them and its music skills rows were never marked "Music only"; it now gets both, keeping what the block held. `tests/resume-variants-edges.php` (+3, with a logged seed fallback).
- **The experience order matches an accented name in any case.** It lowercased with `strtolower()`, so "ÉCOLE" never matched "école"; it now uses `mb_strtolower()`.
- **A second setup run adds no row twice.** It re-added an operations affiliation or skills row the owner had renamed or deleted (a renamed Team Captain line came back beside the new one). It now adds them only to a list that has no operations row yet, so settings typed before the first run still get them. The setup's description, in both editors, now says a second run marks "Music only" again on what the operations résumé leaves out, since it does; and the not-found note is written only after the draft is saved. The "Earlier career: one line per role" label gains its colon. A refused setup save leaves the note alone: `tests/resume-ops-setup-refused.php` (new, 2).
- **The operations PDF's served headers are read, not grepped from the source.** `tests/resume-ops-pdf-route.php` ran each case under the CLI, which drops every `header()` call, so it could only search the source for the noindex line. It now runs them under `php-cgi` and reads the Content-Type, X-Robots-Tag, nosniff, Cache-Control and Content-Length the request really sends, and that a passed-through request carries none of them; without `php-cgi` it fails under CI and skips the header group locally. The native editor's round-trip fixture (`tests/os-leaf-content-resume.php`) gains an entry receipt, a bullet receipt and a credential URL, so a native save that dropped one now fails it.
- **CI now holds the résumé PDF reader to pdftotext.** The oracle in `tests/resume-pdf-text-check.php` skipped on every CI lane (17 passed there against 18 locally), because `ubuntu-latest` has no pdftotext. The tests job and the PHP matrix lanes now install `poppler-utils`, and the oracle fails under CI when pdftotext is missing (it still skips locally, saying the reader was not compared). The ATS read-back in `tests/resume-pdf.php` runs on CI for the first time too.

### Changed
- **The phone is in no version of the résumé, human or machine** (owner, 2026-11-02). No PDF prints it: the music PDF, the operations PDF, the Spanish CV and the draft preview share one template, which no longer has a phone in its contact line, and the include-phone argument of `sn_resume_pdf_html()` and `sn_resume_pdf_render()` is ignored (the slot stays so positional callers keep their meaning). The "Include the phone in the public PDF" switch and the private copy (with phone) are gone from both editors, with the `resume_pdf_private` action. The phone check is now a tripwire on every render: a phone pattern in the text or metadata, or the stored phone's digits (7+), refuses the file (`sn_resume_pdf_phone`): Generate writes nothing and stores the error for the PDF box, the draft preview downloads nothing, and the operations PDF withdraws the file served before it. Nothing exempts the music PDF any more, so the public-phone exemption and the "other than the public one" check line are gone. `pdf.phone` stays stored, never output, as the tripwire's input; `pdf.phone_public` may stay stored and nothing that builds a PDF or a page reads it. The pages already carried no phone (the sync engine never reads `pdf`; the identity JSON-LD has no `telephone`). A file published before this keeps what it was built with until the next Generate. `tests/resume-no-phone.php` (new, 9): with the phone stored and the old switch on, no PDF text layer (pdftotext when installed), no page body and no JSON-LD carries it; `tests/resume-pdf-generate.php` (+3).
