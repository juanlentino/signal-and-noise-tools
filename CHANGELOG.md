# Changelog

All notable changes to Signal & Noise Tools are documented here.

This file holds two things only: **`## [Unreleased]`**, the working log that
accumulates across pull requests, and the **current release**. Everything older
lives in [docs/changelog/](docs/changelog/).

A pull request does not bump `Version` and does not tag — it closes an issue and
adds a bullet below. A release is a separate, deliberate act:
`tools/cut-release.sh`.

## [Unreleased]

### Changed
- **The résumé's agent copies never carry a phone.** `/resume.md` and `/resume.md?lane=operations`, both JSON Resumes, `/cv.md`, `/cv/json-resume.json` and `/resume/contact.vcf` have no phone field at all now: the JSON Resume's `basics.phone`, the Markdown's `phone:` line and the vCard's `TEL` are gone, whatever **Include the phone in the public PDF** says or what phone is stored. The live copies carried none only because that switch was off. The PDFs keep their own phone handling.
- **The operations Markdown no longer links the vCard.** Its front matter's `formats` drops `vcard`; the contact card stays the music résumé's, and the music Markdown keeps the link.

### Fixed
- **A CI flake in `tests/mcp-telemetry-read.php`** (62/63 on the 2026.11.8 cut, green on rerun). Four checks rebuilt a timestamp, to the second, with `$ago()` after the fixture had built it, so a second ticking between the two failed them. They now compare the fixture's own value. A forced 1-second pause reproduces CI's 62/63 on the old test and passes the new one.
- **The JSON Resume split a skill at a comma inside parentheses.** "Content Provenance Standards (C2PA, TDMRep, RSL)" reached agents as three keywords, the last two "TDMRep" and "RSL)", on both lanes; the operations résumé's "cross-border market entry (U.S., Latin America)" as two. Skills now split on commas outside parentheses only; text that is not valid UTF-8 splits on every comma, as before, rather than losing its keywords. The Markdown joins the keywords back with commas, so it read right all along.
- **The operations JSON Resume put "(open to relocation)" in the region.** `basics.location` read city "Orlando", region "FL (open to relocation)". A trailing parenthetical now rides in `meta.x-locationNote`, the region reads "FL", and the Markdown front matter still says "Orlando, FL (open to relocation)".
- **The JSON Resume route could be indexed and named no canonical.** `/resume/json-resume.json` (and `?lane=operations`) now answers `X-Robots-Tag: noindex` and `Link: <https://juanlentino.com/resume/>; rel="canonical"`, the headers the Markdown and the vCard already sent, from one shared set. `tests/resume-format-headers.php` reads them as served, under php-cgi.
- **The JSON Resume alternate ignored the lane.** On `/resume/?lane=operations` the page's `<link rel="alternate" type="application/json">` named the music JSON Resume; it now names `?lane=operations`, as the Markdown alternate already did.
- **The format list did not name the operations Markdown, and its front matter did not name its lane.** `markdown_operations` joins the format list (front matter and agents manifest) while the operations PDF is live, the operations Markdown says `lane: "operations"`, and no optional Markdown section prints an empty heading any more (Experience, Education, Memberships & Credentials, Skills, Languages were unconditional).
- **The agents manifest claimed an authorship proof /resume does not have.** Its résumé entry said "The page carries a Bitcoin-anchored authorship proof" unconditionally; it now says so only when the page has an anchored version, as the Markdown and the JSON Resume already did.
- **The two résumés on /resume had no names a screen reader could find.** Each lane is now a region named "Music résumé" or "Operations & AI Strategy résumé", set at render time like `hidden`, so the stored page is unchanged.
- **The music lane's page document kept the phone fields.** Only the operations lane's were blanked; both are now. Nothing public changed: the page never printed them, and the music PDF and JSON Resume read the stored document.
- **A résumé save left agents reading the old copies.** `/resume.md`, `/resume/json-resume.json` (both lanes of each), `/resume/contact.vcf`, `/cv.md` and `/cv/json-resume.json` are cached at the edge untagged, so the tag purge never reached them. So is `/resume/?lane=operations&output_format=markdown`. A save of /resume or /cv now purges them by URL, on every save path, and so do a Publish or Revert before the first PDF (an email edit rewrites no page, so no page save fires) and every Generate PDF (the copies name the PDF's new `?v=` link).
- **The résumé editor said the PDF-only fields never show on /resume.** Since the two lanes, the Headline and Tagline head the Music lane. The PDF only hint (classic and dashboard), the Operations résumé hint ("the switch links both PDFs"), the docblocks and `docs/RESUME-PDF.md` now say what the page shows, and the docs catch up on drafts, Publish and Revert rebuilding the PDF, the receipts' https rule, the check's read flags and the test list. The page itself is unchanged.
- **The operations résumé keeps its address when shared.** On `/resume/?lane=operations` the canonical and `og:url` said `/resume/`, and a phone's share sheet copies the canonical while a link preview reads `og:url`, so the lane was dropped. Both now keep `?lane=operations` while an operations résumé exists (`inc/resume-lane-address.php`), and the hreflang trio is left out there, as the Spanish CV has no operations lane. An owner canonical override still wins; any other lane value is the music lane, so nothing a visitor types reaches the head. The theme's switch retargets both tags when the lane changes without a reload. `tests/resume-lane-address.php` (10).
- **The operations résumé's head and twins name the operations résumé.** On `/resume/?lane=operations` the `<title>`, `og:title` and `twitter:title` read "Juan Lentino · Résumé · Operations & AI Strategy", the meta, og and twitter descriptions are the first sentence of the operations summary as stored, and the ProfilePage's `url`, `@id` and `description` follow the lane (its Person and breadcrumb stay put). They hook two new view filters beside `sn_seo_view_url`, `sn_seo_view_title` and `sn_seo_view_description`, because the `sn_seo_singular_*` seams lose to the page's written description and add the site suffix. The operations Markdown and JSON Resume name `/resume/?lane=operations` as their `Link: rel="canonical"`, front matter `url` and `meta.canonical`, and both lanes' twins now list both lanes (`lanes:` in the front matter, `meta.x-lanes` in the JSON Resume: page, Markdown, JSON and PDF for each). The music head is unchanged, and the music twins change only by that map, pinned byte for byte. The AI plugin's `?output_format=markdown` alternate gets `lane=operations` there too (through core's `clean_url`; it has no filter of its own), so no Markdown alternate in the operations head names the music résumé. The lane is checked before any other work, and the stored résumé is read once per request. `tests/resume-lane-heads.php` (28).
