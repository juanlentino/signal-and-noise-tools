# Changelog

All notable changes to Signal & Noise Tools are documented here.

This file holds two things only: **`## [Unreleased]`**, the working log that
accumulates across pull requests, and the **current release**. Everything older
lives in [docs/changelog/](docs/changelog/).

A pull request does not bump `Version` and does not tag — it closes an issue and
adds a bullet below. A release is a separate, deliberate act:
`tools/cut-release.sh`.

## [Unreleased]

- **A post save purges the feeds and the llms files.** The companion theme PR holds the posts feeds and the machine files at the edge for five minutes with stale serving (they left with `no-cache` or WordPress's nocache headers; the machine files bypassed the cache at about 0.4 s a read, and the feed is fetched about 2,300 times a month), so a save has to clear them. `sn_cf_post_purge_urls()` adds the theme's own list of cached feed addresses (`sn_edge_cache_feed_paths()`: rss2, rss, rdf, atom and json under `/feed/` and `/notes/feed/`, plus `/?feed=json`) and `/llms.txt`, `/llms-full.txt`. The list is read from the theme, not copied, so every feed variant that gets the header is purged and a format the theme adds needs no edit here; comment, tag and other feeds stay on `no-cache` in the theme and are never held. `/.well-known/agents.json` and `/opensearch.xml` stay out because a save changes neither. 24 URLs at 39 notes, still one purge call (Cloudflare takes 30 a call; past that the existing chunking applies). A theme without the list adds nothing. Not added: `/tag/<slug>/` archives, which were never in the list and are held for the same day as before. Pinned in `tests/cloudflare-purge-coverage.php`.
- **The edge posture reads Always Online, as information.** Same settings answer, same token scope, and the stored value is the plain `on` or `off` the abilities already return under `posture.settings.values`. It is never judged: Always Online is on in the live zone and stays on by the owner's choice (2026-10-03), the working fallback until a worker-side last-good copy exists, so it is not a drift on the posture card and not a finding in the health scan. When it is on and the theme really sends `stale-while-revalidate` or `stale-if-error` to the edge (read from the `Cloudflare-CDN-Cache-Control` value the theme builds), the "also" line says so in plain words: "on, so Cloudflare ignores stale-while-revalidate and stale-if-error; the edge lifetime still applies". Pinned in `tests/cloudflare-posture.php`.
- **Generate PDF purges the PDF, not the site.** Pressing Generate ran the purge-everything ability so the edge would drop one file: every page, Varnish and Redis emptied, and the 20.7.0 purge ledger would have logged each Generate as a manual purge with a Redis flush. It now re-saves /resume as before, and that page save does the page's own purging (this plugin's per-URL Cloudflare purge for `/resume/` and its listings, Breeze's save handler for its stored copy), then sends the file's addresses through `sn_cf_purge_urls()`: the bare `…/resume/JuanLentino_Resume.pdf` and every `?v=` URL issued so far (kept in `sn_resume_pdf_issued`, newest 28, one purge call). All of them, because an old `?v=` link asked for after a later generation would cache the newer bytes under the old address for a year. Nothing happens when Cloudflare is not configured. Pinned in `tests/resume-pdf.php`.
- **MailPoet's page type leaves the sitemap.** Core listed `wp-sitemap-posts-mailpoet_page-1.xml` because MailPoet registers `mailpoet_page` as public; the `wp_sitemaps_post_types` filter drops it. Pinned in `tests/sitemap.php`.

### Changed
- **The plugin reads what three workers started sending on 2026-10-03 (owner, 2026-10-03).**
  - **An internal click is no longer a landing, and no longer "(direct)".** The analytics worker stores a click from one of the site's own pages with a blank referrer, the same as a visit with no referrer, so Entry pages counted every internal click as a landing and Sources counted it as "(direct)". Worker 1.23.0 stores the referrer kind in `double10` (0 none, 1 internal, 2 external). One rule, `inc/analytics-referrer-kind.php`, now feeds both rollups: the entry-pages rollup drops the internal clicks, and the referrer rollup stores them as `(internal)`, kept so sources still total what countries and devices total. Top sources and the five source categories leave `(internal)` out; `analytics_query` lists it as its own value. Applies to events from 2026-10-03 15:09 UTC (`SN_ANALYTICS_REFKIND_CUTOVER`, the worker's deploy at 15:09:39 rounded down to the minute); earlier events cannot be told apart and count as before, so "(direct)" is direct landings only on days after the cutover. Stored days change at the next nightly rollup or a Recompute.
  - **Hacker News on Android.** A referrer from the Materialistic app (`android-app://io.github.hidroh.materialistic/`) is stored as its bundle id and read as an unknown host. It now folds into Hacker News.
  - **The collector status carries `accepted`.** Worker 1.23.0's `/_sn/version` reports rows written beside `rejects`; `get-collector-status` passes `{scope, since, total}` through under the same caveat (one isolate, reset on deploy or eviction, never a site total). The ability's schema now declares both blocks; `rejects` had been in the payload since 10.62.0 without one.
  - **Login defense knows `account_throttle`.** Login guard 1.14.0's per-account throttle has its own pill and its own `account_throttled` count, and joins Checked like `throttle` and `lockout` (left out, the block rate would read higher the more it fired). The gauge now says a degraded list is a corrupt denylist that left an address family unchecked: since 1.14.0 a corrupt meta alone is logged as a pass.
  - **The crosstab shows what is inside the unnamed bucket.** `get-machine-readers-crosstab` gains `unnamed`: the top 20 `{ua_sample, hits}` from the edge's list of user agents that matched no taxonomy entry, read through the same 15-minute cache as the Machine Readers page. `null` when that list could not be read, `[]` when every read matched. Local only: the remote networks twin and the contract version are unchanged.
  - Remote MCP 1.12.5 lets `bridge.failures_today` exceed `anomaly.total_today`. Nothing in the plugin reads `failures_today` and the one reader of `total_today` prints it, so nothing changed.

### Fixed
- **Three readings stop overstating what they know.** The collector's `accepted` block with no numeric total is treated as malformed (absent), never shown as zero; an unnamed-agents read whose samples all sanitise away is `null` (not measured), not the `[]` that means every read matched; the remote agent-networks twin no longer fetches the unknown view for a field it drops. Codex on #1842.

### Added
- **An email when something spikes or breaks.** An hourly run reads only what the site already stores and mails the admin address, once per alert per day. A spike is a page with more than 15 human views today and more than 5 times its prior 7-day daily mean, or the whole site past 40 and 4 times its mean: the site gets about 50 human visits a week, so the floors decide and the ratios only matter on pages that already have traffic. A break is a REAL page with 3 or more stored edge 5xx in a day: the home page, a URL that resolves to a published post or page, or a known archive route (`/notes/`, `/provenance/`, filter `snt_alerts_archive_routes`). The stored 5xx rows are full of scanner probes (`/_security/_authenticate`, `/model/info`, `/Dockerfile`), and fifty errors on one of those mail nothing; the analytics excluded-path rule still drops admin, wp-json, xmlrpc and assets first. The edge rollup files a day after it ends, so a break mails the morning after. The email is plain text: what fired, the number, the baseline, where to look, and for a spike the day's top sources, with the line that referrer-less visits (apps, RSS readers, privacy browsers) show as direct. On by default (owner, 2026-10-03); the toggle is a second checkbox in the morning brief box on Connections, Cron, on the classic page and its native twin. Sent stamps live in an option kept 14 days, not a transient, and a send that fails stamps nothing so the next hour tries again. A stored read that fails is not a quiet day: the run judges nothing, mails nothing and records `read_failed` with the read's name, where a baseline read as zero would have mailed a false spike. The edge query keeps 50 path groups a day; a day that stored all 50 is named in the record, since a quieter real page may have been cut upstream. A day whose 5xx the edge rollup failed to read, or never read by the time it is two days old, is recorded as unread and ripens the watch: no rows is not no errors; the 5xx window is three UTC days so a day filed late is still seen. A spike mail whose sources read failed says so instead of "none stored". The `alerts_fired` watch is the agent-readable twin. Pinned in `tests/alerts.php`.
- **A note's first publish is pushed to the Internet Archive.** A `post` entering `publish` for the first time schedules one Save Page Now capture of its permalink five minutes later, with one retry at most. Updates, pages, private and password-protected notes are never pushed. First means first: any move into or out of publish stamps the note (`_sn_archive_push_seen`), with or without keys, so a note that predates the keys is not pushed when it is drafted and published again, and an event run twice asks nothing. The two keys are keyring rows read from wp-config (`SN_ARCHIVE_ACCESS_KEY`, `SN_ARCHIVE_SECRET_KEY`, from archive.org/account/s3.php); without both the module does nothing and reads "not configured". The result (requested at, HTTP status, job id, state) is post meta `_sn_archive_push`. A 200 that names a job is recorded as `requested`, never as captured: the archive crawls later and that outcome is not polled, so the record claims only what the answer proves; no content, title or excerpt is written, so nothing the provenance ledger signs moves. A failed push ripens the `archive_push_failed` watch for a week, and stays held (20 at most) until that same note is accepted, so a later push of another note cannot hide it, and removing the keys does not quiet it. A first publish whose event cannot be scheduled is held as a failure and left unstamped, so its next publish tries again. The request shape is the documented one and is pinned in `tests/archive-push.php`; the first publish after the keys are added is the live test.

## [20.7.1] - 2026-10-03 — Breeze's timed purge is off

### Fixed
- **Breeze's timed purge is off.** Its "Purge Cache After" field will not take 0: the form saved 1440, and 1 would have purged every minute. So the setting cannot turn it off, and the plugin unhooks Breeze's `breeze_purge_cache` handler and its rescheduler and clears the event, as 20.7.0 did for Breeze's update purge (owner, 2026-10-03). Pages purge on save and once per update; the nightly run only emptied a correct cache. A Breeze settings save can schedule it again, and the next request clears it. The purge ledger's `breeze_nightly` reads `off`. Pinned in `tests/purge-ledger.php`.
