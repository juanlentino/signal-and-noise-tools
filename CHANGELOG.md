# Changelog

All notable changes to Signal & Noise Tools are documented here.

This file holds two things only: **`## [Unreleased]`**, the working log that
accumulates across pull requests, and the **current release**. Everything older
lives in [docs/changelog/](docs/changelog/).

A pull request does not bump `Version` and does not tag — it closes an issue and
adds a bullet below. A release is a separate, deliberate act:
`tools/cut-release.sh`.

## [Unreleased]

### Fixed
- **What the 2026.10.3 audit found first** (owner: "a lot of things needing fixing ... figure it out"; every leaf swept live with real data and read by seven auditors):
  - Seven sentences pointed at a box that sits elsewhere or at a button that does not exist ("see the reference in the right column", "Run Test connection above", "the manual button below", "in the main column" four times, "press Refresh"); each names its target now, on both surfaces, and Webhooks' empty notice says to stop watching first when Watch live has put Add a webhook away. Provenance's empty Commits line says a new proof appears within 30 seconds, which is how often it polls.
  - Connections › Credentials' picker painted an empty box that read as "no credentials"; it says "Choose a credential", and any kit select whose value matches no option shows a placeholder.
  - Webhooks' "Add webhook" sat jammed against the last checkbox's label; the webhook forms stack, the button at the end.
  - Integrity › Reports printed "38 of 21 token pairs" from a cached count; the tile and the sentence count the printed pairs on both surfaces, and its run-date link opens a new tab instead of replacing the whole desktop with GitHub. One function counts them for both surfaces.
  - Six desktop-widget links (Open Dashboard and its siblings), Home's "this week" figure, and every link a builder paints without the kit used the admin accent, pure red here, 4.4:1 and failing AA for small text; they take the link pink. The widget guard that was meant to catch this matched nothing (its pattern could not cross a `;`); it now reads every card link's color and fails on all six old ones.
- **Every S&N control shows focus, and primary button labels read on their fill (2026.10.3 audit, batch 3).**
  - **Focus rings were invisible.** The shell's focus token is a whole box-shadow list, so `0 0 0 2px var( --os-ui-focus-ring )` was invalid and computed to none; beside `outline: none`, a focused native field or submit (Webhooks, Tags, S&N Analytics' date field and export buttons, the Explorer's crumbs) showed no ring. Each rule now uses the token as the value: the field ring for fields, the full ring for buttons.
  - **White on red was 3.9:1.** A primary label takes the accent ink, which OpenStation's accent picker keeps white until the accent is very light (its switch sits at luminance 0.35; black and white actually tie at 0.179), so on a red accent it was under AA. Inside S&N Home and S&N Analytics the ink is now black or white, chosen at that exact crossover from the fill itself: black on red (5.25:1), white on Rose and WordPress blue. It is checked against every OpenStation swatch, the WordPress admin schemes, and fills right at the threshold. The shell's own dialogs and other apps keep the picker's ink.
- **Security › Login URL tells the truth about the module.** It checked only the bypass and wps-hide-login, so a site running rename-wp-login read "Module active" while the module stood down, and every dormant state offered the custom slug's URL, which 404s while the module is off, with "Bookmark this URL". Both surfaces now read the module's state the way `inc/login-hide.php` decides it, give the login URL that works in each state, and, when `SN_LOGIN_SLUG` locks the slug, show the constant's slug (it showed the saved setting), offer no Save (it posted no slug and answered "Login slug cannot be empty") and say so once.
- **The write door stops claiming audit-log exports.** Its description still said "a couple are read-only login-audit exports carrying plaintext usernames", a year after those tools left the door, above a list without them. It now says some tools spend the AI budget and the Jev passes spend TypeSafe credit, on both surfaces.
- **Agent tools does not paint an unread sensor as zero calls.** When the browser-call sensor could not be read, the bridge table filled with 0s under a note saying they came from no data. Every count cell now says "not read", on both surfaces.

## [2026.10.3] - 2026-10-12 — MCP Clients redesigned, boxes share rows, folds are earned, Edit opens under its row, links read as links

### Changed
- **Links read as links in their sentence** (owner: "Fix the link style too"). Every S&N link was monospace 12px, so "Developer filter seams", "Open the PDF" and "Verification docket" painted as code, and door links took the admin accent, pure red on this site, which is 4.4:1 on the window and fails AA for text. A link now takes its sentence's font and size, underlined, in the app's link pink (about 9:1); a link whose text is an address (`/resume`, a permalink, the login URL, `repo#33`) keeps the code face. Door and go links take the same pink, and so do Home's "View all" and attention-row actions. An address link is underlined like a door link, and an anchor matches a door link's weight. The Provenance and MCP Clients overrides go, and "RSL licence" is "RSL license" on both surfaces.
- **The public /maturity page reads in American English** (owner: "fix the maturity page too"): "License file", "Behavioral deviation detection", and "as a license file" in the Reserved row. The row keys stay as they were.
- **Scheduled events on Connections › Cron is an earned fold.** It is a reference list (86 events here, 5,473px open). Closed, it says "86 events: none past due, every one handled", read from every event's own next run (more than 15 minutes behind is past due; the system cron runs on ticks), not from the plugin's health reading, which covers only its own jobs. It opens by itself when an event is past due or has no handler, and while a filter is typed; the filter and the count line sit inside it.
- **Edit opens under its row.** On Site › Redirects, Site › Broken links, Content › Résumé and Content › Workflow, clicking Edit (or Fix) used to open the editor below the whole table, and on Redirects it took the place of "Add a redirect", so it read as a different form (owner, on 2026.10.2: "it's weird to click in 'edit' and something else opens"). The table now splits at that row: the rows down to it, the open row marked and saying "Editing", the editor right under it, then the rest of the table under a repeated header. Focus moves into the editor, and Cancel returns it to that row's Edit. "Add a redirect" stays where it was while a rule is open. These lists also show every row they list instead of an inner scroll box of about ten (the app's 440px table cap no longer applies to them). On Broken links, Broken paths and Automated probes share one row (measured 578px and 644px tall); while a path is open they stack, because its editor makes that side far taller. Field names, actions, nonces, the long-path keys and the "+N more" counts are unchanged. Closing the editor (Cancel, Save or Delete) clears the row highlight: every table the list paints carries its selection, empty when no row is open, because the window reuses a table between paints and keeps a selection it is not told to drop. On Redirects and Broken links, Cancel sits beside Save (or Create) in the editor form's own action row, as on Résumé, instead of a row of its own. On Broken links the Automated probes list shows every row as well, so the pair stays balanced: measured live, 1,153px beside 910px, where a scrolled probes box stood at 644px (1.79x).
- **AI › MCP Clients is redesigned** (owner, on 2026.10.2: "The MCP clients page is also weird. You need to do better."). It said "three doors" over four cards, pointed at a "Door 1" and "Door 2" no card named and at "the Application Password below" from its last line, floated the remote switch away from the door it controls, and stamped the credential box "since v9.51.0". Now: one line that counts the four doors, the doors as four tiles, the write-door credential beside the remote door with its switch, then Connect a client: the Application Password, both door addresses, Claude Code at full width, and the Claude desktop app's steps beside the config they paste (no step says "above" or "below", which would lie when the pair stacks on a phone). The tiles carry state and what each door is; usage is said once, in the section that controls the door (it was on both, and the two rounded the same hour differently). The tile words take the foreground color: the stat default is the admin theme color, red here, which made four ready doors read as four alarms. A door that is not ready keeps its toned swatch. Measured live: 1,906px to about 1,265px. The classic leaf's sentences are corrected the same way; its forms, field names and actions are unchanged. The remote door's usage reads "Last used 2 hours ago", not a raw timestamp, and "1 call", not "1 calls".
- **Every S&N tile reads in the foreground color, not the admin theme's red.** The kit's default for a tile's value is the WordPress admin color, red on this site, so Health's "0 findings, all clear" and MCP Clients' "Bridge ready" read as alarms. Provenance, S&N Analytics and MCP Clients had each overridden it; the default now lives once in `assets/os-app.css`, and a tile that is not fine keeps its toned swatch.
- **Folds are earned, one at a time** (owner, 2026-10-12: "The collapsible options should be thought. Some places earn it, other don't."). One helper, `snt_kit_fold()`, paints the only fold S&N Home allows, and a place earns it when it is reference or setup read once in a while (never status, a warning or a control in regular use), when the closed fold still states the answer (the summary is required; without one the content paints open), and when it opens itself while something inside needs the reader. Every fold is listed with its reason in `tests/sn-dashboard-no-folds.php`; an unlisted one fails the sweep. The first: MCP Clients' **Connect a client**, setup done once per client, closed under "Claude Code, the Claude desktop app, or any client through @automattic/mcp-wordpress-remote, with both door addresses", and open by itself while you have no Application Password. Inside it, each client is now a sub-heading a screen reader can move between, not a bold line; "Claude Code connects straight over HTTP, with no config file" replaces a sentence that mentioned a proxy before any proxy appeared; the write-door notices no longer say "below" (in the no-password state no form follows), and the classic credential box loses its "since v9.51.0" badge too.
- **Agent tools names the doors the way MCP Clients does.** "Door 1", "Door 1b" and "Door 2" are now the read door, the write door and the core MCP adapter, the names on the MCP Clients tiles, on both surfaces. No sentence says the write door is "below" or the read door "above" any more (they now share a row), and the "since v9.x" stamps are gone.
- **Boxes that fit side by side share a row** (owner: "some of the settings became a scroll page"). Measured live with the grid refit a visible window runs: Measurement › Analytics' left column ran 3,094px against 2,059px, so exclusion and tuning move to a row of their own under both columns; Agent tools pairs the read door with the write door; Health pairs "Could not run" with "Also scanned"; Reports pairs the placement-dependent and arithmetic tiers. Every pair is within 1.5x height.

### Fixed
- **A fold you open stays open.** The window repaints a leaf by mirroring the painted attributes, so a fold the reader opened snapped shut on the next filter keystroke, watch tick or save. The host now remembers each toggle of an earned fold and puts it back on the paint's own event, before the frame. Your choice holds while the page says the same thing; when its answer changes (an event turns past due), the fold follows the page again.
- **Deploy Status's Remote MCP row is its version again.** 2026.10.2 painted "2.2.0 · contract 16", which wrapped in the narrow column and said nothing when the contract matched. A match now lives in the check's title ("contract 16 matches this plugin"); only a mismatch says the contract, as one amber line under Workers naming both sides ("Remote MCP contract 15; this plugin expects 16.").
- **SN Provenance names the top identified crawler family.** It read "Top crawler family: other-bot, 49%", the bucket for bots the taxonomy cannot name. other-bot and unclassified-machine are skipped (live: search, 15% of reader reads); with only buckets reading, the row is left out.
- **Integrity › Reports no longer says "38 of 21 token pairs would fall below 4.5:1".** The 21 pairs are the served palette; the 38 summed the failures of every palette the theme ships. The count now follows the same palette as the pairs it is printed against, on both surfaces; each palette's own count stays in the report.
