# Changelog

All notable changes to Signal & Noise Tools are documented here.

This file holds two things only: **`## [Unreleased]`**, the working log that
accumulates across pull requests, and the **current release**. Everything older
lives in [docs/changelog/](docs/changelog/).

A pull request does not bump `Version` and does not tag — it closes an issue and
adds a bullet below. A release is a separate, deliberate act:
`tools/cut-release.sh`.

## [Unreleased]

### Changed
- **One résumé editor: no music PDF, no setup box, "Résumé settings" and "Contact" (owner, 2026-11-12).** With résumé settings (`variants.operations`, new `sn_resume_pdf_is_one()`), Generate no longer builds the music PDF: it removes `uploads/resume/JuanLentino_Resume_Music.pdf` (and the old `JuanLentino_Resume.pdf`) whether or not Cloudflare is configured, deletes the `sn_resume_pdf` option, builds the résumé PDF and the Spanish CV, purges both files' addresses with every ?v= ever issued plus the agent copies, and returns the résumé PDF's facts or its error. A failure is recorded on the résumé PDF's facts, including one before its build ran (no uploads directory); the `resume_pdf_ops_failed` flash stays but can no longer fire. Without settings the music PDF is built as before. Publish rebuilds the PDFs when the résumé PDF is live or its last build failed (one withdrawn for a phone is not live, and Publish must still rebuild it once the phone is out), with no music facts stored. Removed: the "Operations résumé setup" box on both editors (classic `sn_admin_render_resume_operations_setup`, native `resume_operations_setup`), its admin-post action `resume_operations_setup` (`sn_handle_resume_operations_setup`; the action map is 93), the `resume_ops_setup` and `resume_ops_setup_partial` flashes, the "not found by the last setup" note (`sn_resume_ops_setup_missing` is no longer read), the hint telling the owner never to re-run it, the music "Show What I've Built in the music PDF" switch (`sn_admin_render_resume_music_built_toggle`, `resume_music_built_toggle`), the Resume PDF box's music paragraph ("This is the music PDF…", "Open the PDF") and the box's music lines and "stopped at the music PDF" note, and from the "PDF only" section the Headline, Tagline, Professional summary, Location, Website, Core competencies and Technical toolkit fields. Renamed (labels only; option keys, `variants.operations`, field names and `sn_resume_ops_*` functions unchanged): "Operations résumé" is "Résumé settings", "PDF only" is "Contact" (Email and Phone), and the box calls the file "Résumé PDF", "linked from /resume's Download". No data is lost: a draft save now carries over from the draft, else the live document, every `pdf` key and `variants.music` the post lacks (`sn_resume_draft_carry_over()`). `sn_resume_pdf_retire_old()` is now `sn_resume_pdf_retire_file()`. `sn_resume_operations_setup()` stays as the tests' fixture builder (`inc/resume-pdf/generate.php`, `inc/resume-pdf/operations-box.php`, `inc/resume-draft.php`, `inc/admin-post-actions/resume-draft.php`, `inc/admin-post-handler.php`, `inc/admin-flash-messages.php`, `inc/admin-forms/resume-page.php`, `inc/admin-forms/resume-variants.php`, `apps/sn-dashboard/parts/leaves/content-resume*.php`, `docs/RESUME-PDF.md`). Tests: `tests/resume-ops-pdf-build.php` (47; the new groups fail on main), `tests/resume-draft.php` (the carry-over, red on main), `tests/os-leaf-content-resume.php` (both editors' new names, the removed box and fields, a negative control proving the carry-over keeps Contact's round trip lossless, and both Resume PDF boxes without the music paragraph when one, red with the check removed), `resume-pdf-generate` (Publish after a withdrawn résumé PDF rebuilds it, red before the widened condition), `resume-admin-form`, `resume-no-phone`, `resume-variants`, `resume-variants-edges`, `admin-post-actions`. `tests/resume-ops-setup-refused.php` is deleted: it tested only the removed handler.

## [2026.11.34] - 2026-11-12 — The résumé PDF is JuanLentino_Resume.pdf; old addresses redirect

### Changed
- **The résumé PDF is JuanLentino_Resume.pdf again (owner, 2026-11-12).** The one résumé's PDF defaults to `/resume/JuanLentino_Resume.pdf`, both on a blank "PDF file name" and in the Operations setup. The stored name decides, so the live file changes when the owner sets that field and presses Generate. Its two old addresses redirect there with a 301 and the ?v= of the current file: `/resume/JuanLentino_Resume_Operations.pdf`, and `/wp-content/uploads/resume/JuanLentino_Resume.pdf`, where the music PDF used to be. No address is redirected while it is still the stored name, or when no PDF is live. The music PDF, linked from nothing public, is now written as `JuanLentino_Resume_Music.pdf`. Generate removes the old uploads file and purges its address and every ?v= ever issued, since a static file is served before WordPress can redirect it (`inc/resume-pdf/generate.php`, `inc/resume-pdf/operations.php`, `inc/resume-variants.php`, `inc/resume-operations-setup.php`, `docs/RESUME-PDF.md`). Tests: `tests/resume-ops-pdf-build.php` (38; the new group fails with either change removed), plus the file names pinned in `resume-one`, `resume-head`, `resume-pdf` and `resume-no-phone`.
