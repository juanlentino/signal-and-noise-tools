# Changelog

All notable changes to Signal & Noise Tools are documented here.

This file holds two things only: **`## [Unreleased]`**, the working log that
accumulates across pull requests, and the **current release**. Everything older
lives in [docs/changelog/](docs/changelog/).

A pull request does not bump `Version` and does not tag — it closes an issue and
adds a bullet below. A release is a separate, deliberate act:
`tools/cut-release.sh`.

## [2026.10.22] - 2026-10-16 — Live snapshots kept 24 hours, publish windows per note, three roadmap items

### Added
- **Analytics › Overview: the last 24 hours of the live panel, kept.** Each completed 5-minute slot is stored for 24 hours (`sn_live_slot_detail`, not autoloaded; stored once, deleted past 24 hours on every write and every read): human readers, readers by traffic class, the top five pages and the top five sources, as the live panel would have shown them. Under the Right now block, classic and native, a grid of the last day (an hour per row, a slot per cell) links each slot; following one paints its class split, pages and sources (no script; `sn_slot` is new native window state). `signal-noise/live-now` gains an optional `hours_back` (1 to 24) that adds `slots`; with no argument its answer is byte for byte what it was. Three grouped Analytics Engine reads run only when the hour holds a slot the store does not have. Aggregates only: no visitor id, IP, user agent, cookie or request text. No floor, as live has none (owner, 2026-10-16). `live` stays local-only.
- **Publish windows: each note's first hour, split by lane.** `_sn_published_at` is stamped once, at a note's first move to publish (scheduled or manual, the moment it really went live), kept on updates and republishes, and reset only when the post's date moves past it. Its window, `[published_at, published_at + length)` with the length a new setting (Measurement › Analytics › Setup › Publish windows and its classic twin, default 60 minutes), is read on demand with the SN Traffic Lanes beacon derivation on that note's path alone: window and after, lane by lane, window + after equal to the total page views (hits; visits can count a visitor-day straddling the end in both). A failed, truncated or uncapped read says "not read" with its reason, never a short count. The note dossier's Numbers gains a "First hour" readout (the human readers after the window first, the window by lane, how much was owner or automation, its top sources, "window open, N min left" while open); `signal-noise/posts-signals` gains an optional `publish_window` (a note id); both defaults otherwise unchanged. A closed window is cached in `sn_publish_window_cache` (not autoloaded, 90 days, 200 entries at most). No backfill: older notes say "Published before publish windows existed." The remote door and `sn_remote_analytics_query` are unchanged (contract bump deferred).
- **Measurement › Search Console: Unanswered searches.** The queries Google showed the site for at least 5 times in the synced 28-day window that earned no click, most shown first, each with its impressions, average position and the page Google showed; a query shown on the home page or an index is marked "No note answers this". Capped at 25 with "+N more; the list is capped, not complete." Arithmetic only, no model reads it. The daily sync now also reads the query x page rows (500, stored compact beside the window; a failure there keeps the window), and a new read-only ability, `signal-noise/search-unanswered`, serves the list on the read door (a sibling, not a key on search-performance, whose remote twin's contract stays as it is). Painted on the native leaf and its classic twin, with honest empty states for no synced data and an empty window.
- **AI › Agent tools: the refusals, counted.** Every write a door declined, set against the rule that declined it: one table of door, rule, 7 days and 30 days, busiest first, on both twins and as `refusals` inside sn-site-facts' `tool_telemetry`. A rule that never fired is not listed. Most counts come from the call log (refused, rejected, invalid and conflicting calls to write tools, sn-apply's gates among them). The two kinds decided before the log are now counted on their own: the write door's credential, kill switch and capability checks, and write abilities denied outside MCP (WordPress 7.1+). They live in one non-autoloaded option, a door, a rule and a count per day for 90 days, never a payload; a signed-out request is not counted. Observe only: no allow or deny decision changed.
- **Analytics › Search: index coverage history is kept, not overwritten.** Each completed weekly URL Inspection run now also appends one summary reading (inspected, indexed, not indexed, crawled but not indexed, unknown, errors, and the median days since Google last crawled) to `snt_gsc_coverage_history`, a non-autoloaded option capped at 104 readings (two years). The Index coverage panel and its native twin state what moved since the previous run and list the last eight readings; under two readings they say "History starts with the next weekly run." The `signal-noise/search-coverage` ability gains a `history` key; every existing key is unchanged.

### Changed
