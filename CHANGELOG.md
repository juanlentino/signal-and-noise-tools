# Changelog

All notable changes to Signal & Noise Tools are documented here.

This file holds two things only: **`## [Unreleased]`**, the working log that
accumulates across pull requests, and the **current release**. Everything older
lives in [docs/changelog/](docs/changelog/).

A pull request does not bump `Version` and does not tag — it closes an issue and
adds a bullet below. A release is a separate, deliberate act:
`tools/cut-release.sh`.

## [Unreleased]

- **The IndexNow key has a probe.** Verify all read the keyring's `indexnow_key` row as "no probe", which is never a pass. It now fetches `/<key>.txt` at its public URL, through the edge the way a search engine does, and passes only when the body is the key (a trailing newline aside); a 4xx is refused (the file is served only while IndexNow is on), a 5xx or a transport failure is an error. Same request shape as the other probes (6 s, no redirects, TLS verified). Neither the key nor the body enters a verdict. New `tests/keyring-probe-indexnow.php` (9 checks, 7 red before).
- **The daily Cloudflare monitor reads Worker health.** Beside the zone and firewall reads, one GraphQL read of `workersInvocationsAdaptive` over the last day (both bounds explicit, a minute under a day) stores, per Worker: requests, errors and their share, subrequests, CPU p50 and p99 in milliseconds (from the status with the most requests, since quantiles do not add) and requests by status. `cloudflare-status` (and `sn-status{cloudflare}`) carries it as `workers`; the Edge, 7 days card gains a Workers, last day table. A token without Account › Account Analytics › Read reads `needs_permission` with that scope named, never zero; a missing account ID says so and makes no request. Shown, not judged: no Worker's configured `cpu_ms` is known to the plugin, so nothing is flagged. Local only; the remote contract is unchanged. New `tests/cloudflare-monitor-workers.php` (16 checks, red before).
- **Fixed: a spike alert is about a real page, and says how much of it looks automated.** On 2026-10-18 `alerts_fired` went ripe on a spike for `/zz-sweep-missing-7f3a/`, a 404 the owner's own automated sweep had walked. A path now spikes only when it is a real page (the home page, a published post or page, a known archive route), the same test a break already passes; its views still count toward the site-wide total, which is unchanged. Each path spike's mail gains one line: how many of that path's presumed-human visitor-days that UTC day the beacon bot-signal score marks likely automated, as inferred, shown only and never subtracted, or "not measured" when no visitor-day carried signals, or "could not be read" when the read failed. That read is one Analytics Engine query per spiking path, made only when a spike fires. New `tests/alerts-spike-real.php` (14 checks, 6 red before).
- **/verify speaks the site's language, has a skip link, and its tabs are a tablist, not a nav.** The standalone page said `lang="en"` where every theme page says `en-US`; it now prints the site's own language attributes. It gains the theme's skip link (first in the body, to the main region, styled like the theme's `.sn-skip-link` in the page's own tokens, off screen until focused), and the tab bar is no longer a navigation landmark: its wrapper is a `div` with the same class, and the tablist carries the "Verification sections" name. Renders at 375 and 1440, light and dark, are byte-identical to the live page until Tab focuses the skip link. New `tests/provenance-verify-a11y.php` (7 checks, 7 red before).
- **Fixed: the collector reads healthy while the first-party token is off.** Analytics worker #55 added `first_party_token_set` to `/_sn/version`, and `get-collector-status` (and `sn-status {collector}`) counted it as a required binding, so with the optional `SN_FIRST_PARTY_TOKEN` unset the collector read `healthy: false` with "False bindings: first_party_token_set: each is a silent-data-loss mode." The header is off until the owner sets the secret, and off loses no data, so the flag is now skipped like the optional owner flags: it never fails `config_bindings` and never joins its count. A real required binding still fails. `tests/abilities-collector-status.php` gains 4 checks (3 red before).
- **The Search Console sitemaps report is read with the weekly coverage run.** One `sites.sitemaps.list` call (the `webmasters.readonly` scope already held) at the end of each URL Inspection run stores, per sitemap, when Google last read it, whether a submission is pending, the URLs listed and its errors and warnings; Google's deprecated `indexed` count is not kept, and a failed read keeps the last good record with the error beside it. It shows in plain words in the Index coverage panel of S&N Analytics › Search (classic and native) and as `sitemaps` in `search-coverage` (local only, no remote twin, no contract change). `tests/search-console-sitemaps.php`, 18 checks (red before).
- **New watch `index_gap`: a published note or page not indexed after 14 days.** Read from the stored coverage map, never a live inspection. 14 days is one weekly run past the day-10 single inspection. The note lists each path with Google's state verbatim, the days since publish, Bing's answer and a direct URL Inspection link, and says to click Request indexing there (the API cannot request it). Tag archives and pages excluded by noindex on purpose never count; it clears when the weekly run reads the page indexed. Live 2026-10-19 the map holds 8 such notes and pages (`/about` and `/notes/recognition-was-always-downstream` among them); each one published 14 or more days ago ripens it. `tests/search-console-index-watch.php`, 19 checks (red before).
- **Bing's view of the URLs Google has not indexed.** At the end of the weekly coverage run, one Bing `GetUrlInfo` per not-indexed URL (noindex pages skipped, at most 25 a run, an answer under six days old not re-asked) says whether Bing crawled it, only found it, or does not know it, so a Google-only gap reads apart from one on both engines. It is a crawl date, not an index verdict, and the words say so; a refused call reads "Bing not read", never "Bing lacks it". The Index coverage table gains a Bing column, each path links to Google's URL Inspection, and `search-coverage`'s `not_indexed_paths` rows carry `url` and `bing`. `GetUrlSubmissionQuota` is not read: it governs submissions, and nothing here submits. `tests/bing-url-info.php`, 17 checks (red before).
- **Traffic lanes read the analytics worker's first-party code.** A beacon carrying the `x-sn-first-party` header with the worker's secret is recorded as owner identity 6 (analytics worker #55); the lanes now file it as own infrastructure / first party, the same lane the machine side already uses, instead of an unknown owner code.
- **A day the deploy history no longer reaches reads unknown, not 0 installs.** The history keeps the newest 20 installs, so a full one holds nothing before its oldest row, and that row's own day may have lost rows to the cap. `snt_desktop_edge_installs_on()`, shared by `edge-errors-summary`'s `installs_by_day` and the SN Systems card, now answers `null` (unknown) for any day up to the oldest row of a full history, and `explained` follows to `null`. Live 2026-10-19: 1 + 13 + 6 rows from 10-17 on filled it, and 10-16 (about 12 releases, and every `/wp-admin/edit.php` 500 of the week) read "0 installs, not explained" as a fact, while 10-17 read 1 against about 13 releases. `tests/edge-errors-installs-by-day.php` gains 5 checks (3 red before).
- **Fixed: the desktop widgets no longer reach the site all at once.** Returning to the OpenStation desktop, or bringing it back into focus, re-armed every stale widget at 0 ms in the same instant, and a moved pulse stamp woke all its subscribers in one call, so a small PHP pool answered 503 on `desktop/pulse`, `desktop/machine-readers` and the deploy and anchor runs (the week's edge errors). Every poller's wait now gets 0 to 5 seconds of jitter from `sntPollCadence.jitter`, the pulse wakes each subscriber after its own, and SN Queue doubles its wait after a failed read (capped at 15 minutes) as the other cards already did. The 503s on `desktop-mode/v1/session` and `/openstation/sw.js` come from OpenStation itself, not from these cards.
- **Fixed: scanner probes no longer count as the site failing.** A direct request to a core library file (a `.php` under `/wp-includes/` or `/wp-admin/includes/`) fatals because WordPress never loads it that way; 26 of the week's 177 stored 5xx were these (`/wp-admin/includes/schema.php`, `/wp-includes/customize/class-wp-customize-cropped-image-control.php`). The 5xx reading now counts them apart as `probes` (total and paths), left out of `total`, `paths` and each day's total, so the Systems card, the install verdict and `edge-errors-summary` read real failures. The `/wp-admin/*.php` screens such as `customize.php` stay in the total: they are routed pages a real failure could hit. Who-asked counts still include probes, and a day that was not read still says so. Remote contract 21; the worker's own bump is a separate PR.
- **Removed: the Free Managed Ruleset row from Cloudflare edge posture.** On the Free plan Cloudflare runs that ruleset itself: it never appears in the zone's own managed entrypoint and the dashboard offers no deploy, so the read could only say "not deployed" (a false finding in Health) and could never catch a real change. The managed-entrypoint request, its row and the `managed` key in `sn-status`'s Cloudflare posture are gone; a record stored before this still carrying `managed` raises nothing. The rate-limit rule and leaked-credentials detection reads stay on the same Zone WAF Read scope.
- **Fixed: a link the probe could not reach is no longer reported broken.** Health › Broken internal links flagged a live `/servicios` as "HTTP 0" and kept the finding for 24 hours, because one request that got no answer (timeout or refused) was cached as a broken link. A request with no answer is now skipped as unverifiable (reason `no_answer`) and never cached, so the next scan asks again. A real 404 still flags.
- **The 24-hour grid sits beside the live block.** The grid is about 290px wide, so it no longer takes a row of its own: Right now is two columns that wrap, the last hour, its surge line and the live lists on the left, the grid with its chosen slot on the right. On a panel narrower than about 800px the grid drops under the live block as before. No scroller at any width.

## [2026.10.50] - 2026-10-19 — the 24-hour grid fits one glance; the JSON résumé carries its highlights


- **The JSON Resume carries the stats strip.** `meta.x-highlights` lists the page's highlights (`{n, label}`, blank ones dropped), so `/resume/json-resume.json` and `/cv/json-resume.json` hold every fact the page shows. JSON Resume's `meta` allows extra keys, and the `x-` prefix matches `x-provenance`. No stats, no key.
- **The last 24 hours under Right now is a compact heat grid that never scrolls.** It was a 24-row table of red numbers, most of them 0, that scrolled. Now each hour is a column (now at the right) and each 5-minute slot a small square, colored by its human readers with no number inside: zero is a quiet gray, and up to three steps, scaled to the window's busiest slot, start at the accent and deepen toward the text color, so each non-empty step keeps at least the accent's contrast in both themes. A slot that was never recorded is dotted, not a zero. The grid is about 140px tall and shrinks to fit the panel down to 320px wide. An hour axis every 6 hours marks now; a legend names the real steps; a line under it names the busiest slot and how many slots had readers. Each slot is still the link that opens its pages, sources and traffic classes, now named for screen readers as its time range and count ("18:15 to 18:20, 3 human readers"), with the same text shown as a hint on hover and focus. The classic page and the native Overview share the one painter.
