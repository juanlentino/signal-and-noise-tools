## [Unreleased]

### Added
- **An app checking a coded link it was just sent is no longer a suspect visit.** When a coded link is sent in a LinkedIn message, LinkedIn's verified preview bot fetches it and, within a minute, a browser on Microsoft's network opens it for a few seconds (2026-11-17, /r/angela: verified fetches 15:46:54 to 15:47:01 UTC, the browser at 15:47:48 from AS8075). The browser alone proves nothing, since the same network carries this site's own smoke tests, so it is recognized only through the verified fetch: a suspect-class session on the same /r/ code, one page view, starting within 60 seconds after it, joined by code and time only. The sessions read takes it out of the suspect list and counts it in `link_scans` (class suspect only; null otherwise or when the shares could not be read). The share itself is already in Links › Shares; class totals elsewhere still count the visit. Remote contract 35 to 36 (additive). Code: `inc/share-echoes-scan.php`. Test: `tests/share-echoes-scan.php` (red with a wider window or without the after-the-fetch guard).

### Fixed
- **"Direct to contact, nothing sent" now flags a visit that spent a moment on another page first.** A session counts when its second page is a contact page and its entry view was short. ## [2026.11.47] - 2026-11-17 — Sessions flag paired and direct-to-contact visits; sampled days are recorded

### Added
- **Two observe-only session flags: agent pairing and direct to contact.** Both join by time (and page) only, never by visitor code, place or network, and subtract nothing.
  - `paired`: a human session whose source is (direct) and that overlaps in time with, or starts or ends within 60 seconds of, a bot- or suspect-class page view. The read is one row per second of bot- and suspect-class page views. The Sessions tab adds "near an automated hit" beside the source, and the live readers list marks a paired reader the same way.
  - `contact_direct`: a human session whose source is (direct), whose entry page is a contact page (`/contact` or under it) or whose second page is one after an entry view under 10 seconds, and in which no contact form was submitted. The contact form sends no beacon event, so a submission is an AllTerrain Forms entry (inbox, read, spam or archived; not a partial save) created between the session's start and 60 seconds after its end. The Sessions tab adds "direct to contact, nothing sent".
  - The sessions ability returns both on each session (null for other classes, or when its read failed) and `flags_by_day` (sessions, direct, paired and contact_direct per site day over the whole window; ask from six days ago for the last 7 days). A flag that was not read is null on every day, and the tab's header says so. When a wide window's hits read caps, the page reads its own span, so only the per-day count goes null.
  - Code: `inc/analytics-pairing.php`, `inc/analytics-contact-direct.php`. Tests: `tests/analytics-pairing.php` (Niigata and Yerevan, the 60-second edge, a 61-second miss), `tests/analytics-contact-direct.php` (Niigata, Yerevan, Vilnius, a referred session, a session with a submission), `tests/analytics-sessions-paired.php`.
- **Returning to an open tab.** A visitor-day that sends engagement rows now but has no page view since its New York midnight (a tab opened before the visitor code rotated) is counted apart in the admin live answer as `open_tab`, taken out of `now`, the human class and the Overview's Reading now, and its line in Readers now reads "returning to an open tab" with the page it is on. Before this they counted in `now` and listed as a reader with no pages. The public answer is unchanged. The hour bars, stored slots, surge and Being read now still count them. Code: `inc/analytics-live-open-tab.php`. Test: `tests/analytics-live-open-tab.php`.

### Changed
- **Sampled page views say so.** The session read selects Analytics Engine's sample interval, and each session gains `pageviews_stored` and `pageviews_est` (`pageviews` stays the stored rows). The Sessions tab gains a Page views column that reads "about N, from M stored" when a visitor-day was sampled, and the sampled-today note uses the same wording. Remote contract 33 to 34 (additive); the Worker's `CONTRACT_VERSION` and its fixture copy follow separately.
- **The live-now description says what `today` is.** Since analytics worker 2.2.0, `today` is the exact D1 count when `today_exact` is true, else Analytics Engine's weighted sum. `today_exact` and `open_tab` join its output schema.
- **A record of which days Analytics Engine sampled.** The nightly rollup now also reads the last 90 site days and keeps, per day and event type, the rows Analytics Engine stored and the events they stand for, for every class and for the counted-human class alone (`inc/analytics-sampled-days.php`, option `sn_analytics_sampled_days`). A day is only added or overwritten from a complete fresh read, never deleted, and per day and event the reading with more stored rows wins, so a thinner re-read never replaces a fuller one and the evidence outlives Analytics Engine's retention. A run that writes nothing records why (`last_run`). The `analytics-dual-write` ability returns it as `sampled_days` with `onset`, the earliest day a human row was sampled; `sn_analytics_day_estimated()` answers per day, Integrity › Lanes labels such a beacon day "estimated (sampled)", the 30-day dashboard trend says how many of its days are estimated, and the daily series in `get-analytics-series` and the REST `/analytics/series` carry `estimated` per day (per week bucket when any of its days is). No number changes. Test: `tests/analytics-sampled-days.php`.
- **The contact form's blocked attempts, counted per day.** A late hook on Forms' spam verdict adds one per refused submission to that site day's count for the guard that caught it (honeypot, time trap, rate limit, rule, challenge, Akismet, other), kept 90 days, counts only. Integrity › Reports shows the daily table in both twins, scan or no scan, and `forms-spam-scan` returns it as `blocked_daily` (`inc/forms-blocked-tally.php`). Test: `tests/forms-blocked-tally.php`.
- **The analytics-integrity check names what it recorded.** A flagged check's fix hint now leads with the recorded UTC time, day, path, class, views and pageview_visits, so `get-health-scan` and its remote twin show the scope without wp-cli. The record and its writer are unchanged. Test: `tests/health-analytics-integrity.php`.
- **Every Analytics Engine read takes the visitor-day from the first 16 characters of the index.** The analytics worker can then give each event type its own index, so Analytics Engine stops sampling a burst of one visitor's events as one; figures are unchanged, because every index written today is exactly those 16 characters. One constant, `SN_AE_VID` in `inc/analytics-vid.php`, holds the expression; each reader requires it. `count(DISTINCT substring(index1, 1, 16))` was checked on the live dataset on 2026-11-17 and matched `count(DISTINCT index1)`, so the dialect guard now allows exactly that expression and still rejects every other one. Tests: `tests/analytics-vid-prefix.php` (no SQL string in `inc/` names `index1` outside the helper), `tests/analytics-sql-dialect.php`.
