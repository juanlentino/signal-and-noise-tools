# Changelog

All notable changes to Signal & Noise Tools are documented here.

This file holds two things only: **`## [Unreleased]`**, the working log that
accumulates across pull requests, and the **current release**. Everything older
lives in [docs/changelog/](docs/changelog/).

A pull request does not bump `Version` and does not tag — it closes an issue and
adds a bullet below. A release is a separate, deliberate act:
`tools/cut-release.sh`.

## [Unreleased]

### Fixed
- **The factory pilot closes, by class, the bypasses an audit reproduced (third round of fixes) (maintainer tooling, nothing ships).** `job ready` now runs the same evidence check as `advance <id> ready`, so a commit pushed after the review is refused. SURFACES is an allowlist that fails closed (exactly one line, a value on it, only `public`, `admin`, `security`, `data` or `none` alone), and every move to build, from any stage, needs an accepting intake that passes it, so escalating from intake no longer skips intake. Intake that names `security` or `data` needs a second `SECURITY: PASS <sha>` line in the review; `job ready` needs `gh pr checks` all green; `ready -> merged` asks GitHub; rework from ready puts the pull request back to draft and removes `factory:ready`. `job new` refuses a closed issue and one already labeled `factory:needs-human` or `factory:ready`, and never leaves a folder without `job.json`. `FACTORY_DRY=1` refuses the real jobs folder. `job.json` is saved atomically, `status` skips an unreadable one, `worktree` restores a deleted folder on its branch and refuses a path that is not a git worktree of that branch, and `spec` can escalate or be abandoned. The gate runs the base branch's `tests/run.sh`, fails a change that edits it or deletes or renames a test, counts only an added or modified test, wants its bullet inside `## [Unreleased]`, lints PHP files from a NUL-separated list, and finds an em dash on any added line. New `job refresh <id>` rewrites `issue.md` with the owner's comments as quoted data. `job` is now a small package (`tools/factory/jobkit/`), and `SKILL.md` and `README.md` say what the code enforces and name its limits: any owner comment after a stop counts as the go-ahead, and job state is local to one checkout. A further review round closes nine more, also by class: the gate names its base as `refs/remotes/origin/<base>`, lints with no stdin and any-case `.php`, forces every diff to text and fails a change to `.gitattributes`, and wants one `## [Unreleased]` heading with a bullet the diff adds inside it; a job made by a dry run is marked and never mixes with a live one, and `FACTORY_ROOT` is read only in a dry run; `job ready` compares the commit with GitHub's head for the pull request, checks the worktree's origin, and announces once; SURFACES refuses a list continued on the next line; a job's worktree and branch come from its id, never from `job.json`, and a `job.json` of the wrong shape is a one-line refusal. A last round makes the round limit real: the gate runs only at stage `gate` and refuses to run again after a FAIL, so a failed gate always costs a round; it also fails an em dash written as an HTML entity, ignores `git replace`, and `FACTORY_DRY` must be exactly `1`. Test: `tests/factory-job.php` (42 to 186 assertions, with parts in `tests/lib/factory-*.php`; each fix was removed in turn and its assertion went red).

## [2026.11.56] - 2026-11-22 — The ingest canary has its own path; rest sampled is claimed only when both counts describe the same moment

### Fixed
- **"Listed in Sessions (rest sampled)" appears only when the stored-row figure and the exact count describe the same moment.** SN Traffic compared the worker's exact count for today (at most 45 minutes old) with stored rows that could come from the same-day last-good option, which has no age limit: 12 rows stored at 9 am against an exact 20 at 2 pm printed "rest sampled: 12" on a day with no sampling. The last-good now records when it was read (`at`), and the new `sn_analytics_today_stored_beside()` returns the stored rows only when they were read no earlier than the realtime cache's 5-minute retention before the exact read. SN Traffic's `today_listed` and live-now's `today_stored` (beside an exact `today`) use it; otherwise the row is absent and `today_stored` is null. `today` is unchanged, and with no exact count `today_stored` is what it was. A last-good written before this change has no read time and is not compared.
- **The feed-opens daylight-saving test can fail.** Its instant (16:00 UTC on Nov 8, six days back) read Nov 2 under UTC arithmetic, under 86,400-second steps in New York time and under calendar days alike. It is now 11:30 pm in New York on Nov 1, 2026, the day of the fall-back, six days back: calendar days answer Oct 26, and both wrong formulas answer Oct 27. Each was swapped in by hand and failed the line. No code change.
- **The ingest canary is its own path, so it leaves the own-tools figure and nothing else can stand in for it.** The hourly canary was a page view of `/` under a SignalNoise- user agent (identity 7). The owner's own-tools figure sums identity 6 and 7 page views, so the canary added about 24 a day to it while its file header said it changed no count; and the ingest check took any identity 7 page view in the last day for the canary, so another SignalNoise- tool would have hidden a dead one. The canary now sends `/_sn/canary` (`SN_INGEST_CANARY_PATH`, a path the site does not serve), the check's read matches that path, and the lanes' owner read leaves it out; the Quality line, the lanes rule text, `get-analytics-summary`'s description and the file headers say so. No lane rule version changes: no stored row changes lane. For the first 24 hours after the first send on the new path (stored as `since` in `sn_ingest_canary_last`) the check also accepts `/`, because the newest old rows are still inside its window; after that only the canary path counts. Canary rows already stored on `/` stay in the own-tools figure for their days. No worker change; how the worker stores this path was not verified from this repository.
- **Two small corrections.** `sn_cron_hooks()` lists the hourly ingest canary with the recurring hooks, not under "Single events" (the cron dashboard's owned-hooks registry already lists it). A bullet that sat above `## [Unreleased]` in this file since 2026-11-12 ("Preview PDF previews the résumé PDF", #2435) shipped in 2026.11.35 and is now in that release's section in `docs/changelog/v13.md`; a test refuses a bullet above the heading.
