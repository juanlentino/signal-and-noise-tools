## [Unreleased]

### Fixed
- **The factory pilot closes, by class, the bypasses an audit reproduced (third round of fixes) (maintainer tooling, nothing ships).** `job ready` now runs the same evidence check as `advance <id> ready`, so a commit pushed after the review is refused. SURFACES is an allowlist that fails closed (exactly one line, a value on it, only `public`, `admin`, `security`, `data` or `none` alone), and every move to build, from any stage, needs an accepting intake that passes it, so escalating from intake no longer skips intake. Intake that names `security` or `data` needs a second `SECURITY: PASS <sha>` line in the review; `job ready` needs `gh pr checks` all green; `ready -> merged` asks GitHub; rework from ready puts the pull request back to draft and removes `factory:ready`. `job new` refuses a closed issue and one already labeled `factory:needs-human` or `factory:ready`, and never leaves a folder without `job.json`. `FACTORY_DRY=1` refuses the real jobs folder. `job.json` is saved atomically, `status` skips an unreadable one, `worktree` restores a deleted folder on its branch and refuses a path that is not a git worktree of that branch, and `spec` can escalate or be abandoned. The gate runs the base branch's `tests/run.sh`, fails a change that edits it or deletes or renames a test, counts only an added or modified test, wants its bullet inside `## [Unreleased]`, lints PHP files from a NUL-separated list, and finds an em dash on any added line. New `job refresh <id>` rewrites `issue.md` with the owner's comments as quoted data. `job` is now a small package (`tools/factory/jobkit/`), and `SKILL.md` and `README.md` say what the code enforces and name its limits: any owner comment after a stop counts as the go-ahead, and job state is local to one checkout. A further review round closes nine more, also by class: the gate names its base as `refs/remotes/origin/<base>`, lints with no stdin and any-case `.php`, forces every diff to text and fails a change to `.gitattributes`, and wants one `## [Unreleased]` heading with a bullet the diff adds inside it; a job made by a dry run is marked and never mixes with a live one, and `FACTORY_ROOT` is read only in a dry run; `job ready` compares the commit with GitHub's head for the pull request, checks the worktree's origin, and announces once; SURFACES refuses a list continued on the next line; a job's worktree and branch come from its id, never from `job.json`, and a `job.json` of the wrong shape is a one-line refusal. Test: `tests/factory-job.php` (42 to 164 assertions, with parts in `tests/lib/factory-*.php`; each fix was removed in turn and its assertion went red).

## [2026.11.55] - 2026-11-22 — The vitals read names the elements behind not-good CLS readings

### Added
- **The Core Web Vitals read names which page elements account for the not-good CLS readings.** `signal-noise/get-analytics-vitals` (sn-metrics' `analytics_vitals`) gains `cls_sources`: for CLS readings over the good threshold (0.1) that carried a shift source, rows `{path, source, readings, needs_improvement, poor, worst}` grouped by path and source, most readings first, at most 50 (readings are sample-weighted, the two bands are counts, worst is a score). `cls_sources_unattributed` counts the not-good readings that carried no source, so an empty list is not read as "nothing shifted". The source is the selector analytics worker 2.4.0 stores in blob17 of a `vc` row (page markup only: tag, id, class names), read only where `blob1 = 'vc'`; the list stays empty until that worker and a theme release carrying the field are live. A failed sources read nulls both keys, says why in `cls_sources_failure` and `sn_analytics_vitals_failure()`, and leaves the rest of the payload standing (kept 5 minutes, not 15). Local door only; no screen changes (`inc/analytics-vitals-sources.php`, new). Tests: `tests/analytics-vitals-sources.php` (new; red before the change, and with the `vc` filter, the cap, the score scaling or the failed-leg check removed) and `tests/analytics-vitals-sources-on-core.php` (new: the real payloads, the failed leg included, pass core's output validation).

### Security
- **The cron orphan cleanup workflow refuses a `hooks` value that is not hook names.** ssh joins its arguments and the remote shell parses them again, so a value with a space lost every name after it and one with `;` or `$()` would have run on the server (only someone who can dispatch the workflow could send one). The runner now accepts letters, digits, underscores and commas only, the remote side checks each name again and passes it to PHP through the environment, and a hook whose handler check could not run is kept, not deleted (`.github/workflows/cron-orphan-cleanup.yml`).
