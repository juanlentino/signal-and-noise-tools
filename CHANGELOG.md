# Changelog

All notable changes to Signal & Noise Tools are documented here.

This file holds two things only: **`## [Unreleased]`**, the working log that
accumulates across pull requests, and the **current release**. Everything older
lives in [docs/changelog/](docs/changelog/).

A pull request does not bump `Version` and does not tag — it closes an issue and
adds a bullet below. A release is a separate, deliberate act:
`tools/cut-release.sh`.

## [Unreleased]

- **`/login` no longer hands out the hidden login URL.** WordPress core redirects `/login` to `wp_login_url()`, and the login mask rewrites that to the custom slug, so `GET /login` answered `302 /sn-login` on the live site: anyone who typed `/login` was given the secret door, defeating the point of masking it (the owner found it on 2026-10-17). `inc/login-hide.php` now unhooks core's `wp_redirect_admin_locations` while the mask is active, so `/login`, `/admin` and `/dashboard` 404 like `/wp-login.php` and `/wp-admin/`. The emergency bypass and the wps-hide-login stand-down still return first, leaving core's redirect in place when the mask is off. New `tests/login-admin-locations.php` (red before: 2 of 3 failed).

### Fixed
- **The app error log holds days again, not about 4 hours.** Object Cache Pro prefetches a request's cache keys before plugins load, so the WordPress AI client's cached model objects (group `wp_ai_client`) came back as incomplete classes, and OCP logged "The cache key `ai_client_...` is incompatible with prefetching" on every request. On 2026-10-17 that notice was about 980 of the error log's last 1000 lines, so a fatal from earlier the same day was already gone when the edge-errors investigation looked. The plugin now registers `wp_ai_client` as non-prefetchable through OCP's own `wp_cache_add_non_prefetchable_groups()` at load (new `inc/object-cache-groups.php`); without OCP it does nothing. No wp-config change: OCP filters each request's stored prefetch list by these groups at shutdown, so lists stored earlier heal as each URL is visited again (flushing the object cache clears them at once). The one `transient`-group notice (a MailPoet key) is left alone. Pinned by the new tests/object-cache-groups.php.
### Added
- **edge-errors-summary says, per day, how many installs there were and whether they explain the 5xx.** A new `installs_by_day` list (oldest first) gives each day's plugin and theme installs from the deploy history and `explained`: true when every 5xx that day is a 503 on the owner's dashboard paths, at most 3 per install, the same rule and the same functions the SN Systems card uses. `installs` is null without a deploy history (unknown, never 0), and `explained` is null for a day not read yet or with no 5xx. `sn-status{edge_errors}` carries it too, since it reads the same ability. Why: the 2026-10-12 to 10-18 investigation had to rebuild install times from git tags to see that 10-15 (58 errors against 7 installs) was over budget. Local door only, like get-deploy-status's `runtime`: the remote twin keeps the shared schema and callback, so the remote contract and the worker do not move. Pinned by the new tests/edge-errors-installs-by-day.php and a strip pin in tests/abilities-remote-set.php.

## [2026.10.35] - 2026-10-17 — provenance chains keep their backslashes, a change-class backfill, and cleanup


- **Cleanup: provenance requests drop the v1 signature header, and smaller tidy-ups.** Requests to the provenance Worker no longer send the body-only `X-SN-Signature`; Worker 1.26.1 refuses v1 (`accept_v1: false` on `/_sn/version`), so the v2 `X-SN-Sig` envelope is the only one, and a test now fails if any provenance file sends the v1 header (the owner's own outbound webhooks keep it). The rest changes no behavior: the MCP bridge returns the shared `sn_rest_no_route_error()` instead of its own copy of core's literal; `inc/maturity-legacy-redirects.php` is now `inc/legacy-page-redirects.php` with `sn_legacy_page_redirect_*` functions and a new `sn_legacy_page_redirects` filter (the old `sn_maturity_legacy_redirects` still applies, as a deprecated alias); one script, `tools/fetch-wp-test-core.sh`, fetches the WordPress core files the standalone sweep needs, and both CI sweep jobs call it; stale comments and two `@since Unreleased` tags are corrected; the README states the webmention receiver's limits (10 per IP per hour, 20 per source host per day, 2,000 unverified, each a named 429) and `docs/REST-HARDENING.md` describes the token-gated routes' `rest_no_route` answer and its `no-store` header.
- **sn-apply can label provenance versions minted before the change class existed.** A new publish-only `change.type: "change_class_backfill"` (target `{scope: "provenance_labels"}`) takes `window_dates` (UTC days, matched against each chain entry's `committed_at`) and `labels: [{post_id, change_class}]`, plans the single version each listed post minted in the window, and refuses the whole call (422) when a post has none or several, naming every candidate. The dry run reports each row with its current and proposed label, a day-level audit match (the rw audit log does not record which version a write minted), and the would-be `change_classes` totals; the apply requires the plan fingerprint (409 when stale) and writes through `sn_prov_set_change_class()`, all or nothing, leaving every payload and hash untouched; `sn_prov_set_change_class()` now hands core a slashed chain, because `update_post_meta()` unslashes and a relabel would otherwise strip every backslash from the signed payloads it rewrites. This ships as code only: no version is labeled until the owner runs the backfill.
- **Every provenance chain write keeps its backslashes.** `update_post_meta()` unslashes its value, and the chain writers (append, replace head, the Worker confirmation update, the chain backfill repair) handed it the chain raw, so a backslash anywhere in a signed payload was stripped on save and the stored payload stopped matching its `content_hash`; the integrity sweep and the webhook re-dispatch recompute from that stored payload. No live note was affected (the integrity sweeps are clean), but any note whose signed content held a backslash would have been. Every write now goes through one helper, `sn_prov_put_chain()`, which slashes the chain; `tests/provenance-chain-slash.php` round-trips each writer through core-like unslashing and fails if any `inc/` file writes the chain meta another way.
