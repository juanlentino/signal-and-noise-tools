# Changelog

All notable changes to Signal & Noise Tools are documented here.

This file holds two things only: **`## [Unreleased]`**, the working log that
accumulates across pull requests, and the **current release**. Everything older
lives in [docs/changelog/](docs/changelog/).

A pull request does not bump `Version` and does not tag — it closes an issue and
adds a bullet below. A release is a separate, deliberate act:
`tools/cut-release.sh`.

## [Unreleased]

### Fixed
- **The S&N Health home widget is gone, with the Spend section it was the only caller of.** `inc/site-health-widget.php` registered no hook; its register function was a no-op since 11.30.0 (the box folded into the Signal & Noise widget) and nothing in `inc/`, `apps/` or the bootstrap has called its three render functions since, so the module kept a promise nobody could read: a state-coloured glance, an Uptime append, a Spend append, all unreachable. 17.4.0 re-homed the spend readers on AI › Models & Budget, which left `sn_spend_watch_health_section()` in `inc/spend-watch.php` with no caller either. Pinned: the module file's absence in `tests/dash-widget.php` (in place of the source-text negative pin that read the dead file), the absent section builder and a spend module that no longer names the widget in `tests/spend-watch.php`, no `.sn-hw-*` rule and the token counts that shrank with it in `tests/analytics-tokens.php`; the advisory-tier list pin and the four null-scan accessor pins, whose only home was the deleted suite, moved to `tests/health-link-opportunities.php`; the readers' unconfigured-is-null contract, which only the deleted section block exercised, is pinned directly in `tests/spend-watch.php`. Each new pin shown red against the unfixed tree.
- **Enter on the Apply modal's Cancel (or its close x) cancels; it used to apply.** The document keydown handler in `assets/health-suggest-actions.js` read every Enter outside a textarea as Apply: `preventDefault()` ate the focused button's own click and `accept()` ran, so a keyboard user who Tabbed to Cancel and pressed Enter committed the write (ai-alt-apply, ai-drift-apply, ai-orphan-apply, ai-link-apply, pattern-adoption-apply, block-migrations-apply). Now the handler reads the Enter target through the shadow root (`e.composedPath()[ 0 ]`; the document only sees the `<os-button>` or `<os-modal>` host in the kit) and, when it is a button, lets that button run its own click: Cancel and the close x cancel, Apply applies once, Enter anywhere else still applies. Driven with real key events in headless Chromium against the classic box and the kit `<os-modal>`: both cancel controls committed on the unfixed script, both cancel on the fixed one. Pinned: the button test, the shadow-root read, the return before `preventDefault`; three red against the unfixed script.

## [17.4.0] - 2026-09-20 — readings find their homes

The flag is already in REST (`register_post_meta` with `show_in_rest`), so nothing new is registered: one nested entry, `meta._sn_evergreen`, appended to `SNT_OS_POSTS_FIELDS` (core's `_fields` accepts `meta.<key>` and ships that key alone, never the other meta keys on the post), and one descriptor beside Provenance and Edge that reads the flag off the row's `meta` and paints a green dot and the word "Evergreen" when it is true, an empty cell otherwise (absent is not zero, the two siblings' idiom; the classic dash is not carried over). Read-only, as the classic column is; the write stays in the post's Signal & Noise box. The filter has no mode argument, so the column is in the Pages window too; there it paints the flag where a page carries it (the checkbox is on both types), a reading the classic Pages list never had. Pinned: the `_fields` string ending in `meta._sn_evergreen`, the descriptor keyed to that path and reading `row.meta`, not flagged returning an empty node, the classic column's word as the label, every field PHP ships having a column the script renders; red against the unfixed code, each half separately.
